# 破産者マップは消えたのか
## 3ドメインが「18秒以内」に同じ管理基盤へ移動した記録

2026年6月11日現在、破産者マップは少なくとも表面上は閲覧できない状態です。

しかし、公開情報を確認すると、単にサイトが消えて終わったとは言い切れない動きが残っています。

`hasanmap.org`、`hasanmap.top`、新たに追加された`hasanmap.cc`の3ドメインが、Cloudflareのネームサーバーから同じNjalla系ネームサーバーへ変更されました。

しかも、レジストラ側などのRDAP記録に残る変更時刻は、2026年6月8日18時05分58秒から18時06分16秒（日本時間）までの、わずか18秒以内に集中しています。

この記事では、被害者の氏名や住所、地図データには一切触れません。対象サイトへの閲覧誘導も目的としていません。扱うのはDNS、RDAP、証明書透明性ログなど、第三者が確認できるインフラの公開情報だけです。

また、公開情報だけで実在個人を運営者と断定することはできません。本稿では、確認できた事実と推定を明確に分けます。

---

# 先に結論

**事実:** 2026年6月11日現在、`hasanmap.org`、`hasanmap.top`、`hasanmap.cc`の3ドメインからサイトへ到達できません。

**事実:** 3ドメインのネームサーバーは、同じNjalla系の3台へ統一されています。

**推定:** 復活が完了した証拠はありませんが、同一管理主体がドメイン管理を一括して移転・再整理した可能性は非常に高いと考えられます。

---

# 何が起きたのか

## 1. 新しいミラーとして`hasanmap.cc`が追加された

2026年6月8日の確認時点で、`hasanmap.org`上のミラー案内ページには、次の3ドメインが「公式ミラーサイト」として掲載されていました。

- `hasanmap.org`
- `hasanmap.top`（停止中の表示）
- `hasanmap.cc`

`hasanmap.cc`は2026年6月7日16時17分20秒（日本時間）に登録されています。

登録直後にはCloudflareを使用し、`hasanmap.org`と同じ内容を配信していました。

当時、本文を取得せずHTTPのHEAD情報だけで比較したところ、`/data/last.json`のファイルサイズ、ETag、更新時刻が`.org`と`.cc`で一致していました。詳細取得APIのCORS設定にも`.org`向けの設定が残っていました。

このため、`.cc`は単なる類似ドメインではなく、本体側が用意したミラーだったと判断できます。

## 2. 3ドメインが同じネームサーバーへ変更された

現在の3ドメインには、次のネームサーバーが設定されています。

```text
1-ceci.njalla.do
2-nest.pipe.ma
3-pas.njalla.in
```

変更前は、3ドメインともCloudflareの次のネームサーバーを使用していました。

```text
aurora.ns.cloudflare.com
javon.ns.cloudflare.com
```

注目すべきなのは変更時刻です。

| ドメイン | 公開RDAPで確認できる変更時刻（JST） | 状態 |
|---|---:|---|
| `hasanmap.top` | 2026年6月8日18:05:58 | `server hold` |
| `hasanmap.cc` | 2026年6月8日18:06:06 | active |
| `hasanmap.org` | 2026年6月8日18:06:16 | 後に`pending transfer` |

3件の操作は18秒以内に集中しています。

同じ名称を持つ3ドメインが、同じ3台のネームサーバーへ、ほぼ同時に変更されています。偶然や第三者による個別操作より、同じ管理画面または同じ管理主体による一括操作と考える方が自然です。

これは運営者の実名を示す証拠ではありませんが、3ドメインが同じ管理下にあることを示す強いインフラ相関です。

## 3. `hasanmap.org`は移管処理中

2026年6月11日確認時点で、`hasanmap.org`のレジストリRDAPには`pending transfer`が表示されています。

これは、別のレジストラへの移管要求が提出され、処理が完了していない状態を示します。

ただし、公開RDAPだけでは移管先のレジストラや、移管を申請した人物を確定できません。

確認できるのは、「単にDNSを止めただけではなく、ドメイン登録管理の移動も進められている」という事実までです。

## 4. 現在は公開用DNSレコードが外されている

2026年6月11日現在の状態は次のとおりです。

| ドメイン | 現在の公開状態 |
|---|---|
| `hasanmap.top` | `server hold`。DNSで名前解決されない |
| `hasanmap.org` | NSは存在するがA/AAAAレコードなし。`www`はNXDOMAIN |
| `hasanmap.cc` | NSは存在するがA/AAAAレコードなし。`www`はNXDOMAIN |

`.org`と`.cc`には、ネームサーバーとSOAは残っています。しかし、Webサイトへ接続するためのA、AAAA、CNAMEなどは確認できません。

したがって、現時点では復活していません。

一方で、ドメイン自体を手放したわけでもありません。管理先をそろえたうえで公開用レコードを外している状態です。

# 「復活準備」と言えるのか

ここは、事実と推定を分ける必要があります。

## 確認できる事実

- 新しい`.cc`ドメインが取得され、公式ミラーとして掲載された
- `.org`と`.cc`で同じコンテンツ配信セットが使われていた
- 3ドメインのネームサーバーが同じ構成へ短時間で変更された
- `.org`はレジストラ移管処理中
- 現在は公開用DNSレコードが外されている

## 推定できること

**中確度:** Cloudflareから別のDNS・登録管理基盤へ移し、ドメインを一括管理し直している。

**中確度:** レジストラ移管や設定変更が終わるまで、意図的にWeb公開を停止している。

**低確度:** 通報や停止措置を受けにくくする目的で、事業者構成を変更している。

## まだ分からないこと

- 本当に再公開する予定があるのか
- 次のホスティング事業者
- オリジンサーバーのIP
- 管理者の実名
- 移管先レジストラ
- 新たな決済・削除申請手段

管理基盤を移したことと、サイトを復活させることは同義ではありません。ドメインを維持するだけ、または撤退処理の一環である可能性も残ります。

# 運営者の特定はどこまで進んだのか

## 確定していること

- `.org/.top/.cc`は同じ管理主体が操作している可能性が極めて高い
- 2026年6月8日にCloudflare系NSからNjalla系NSへ一括変更された
- `.org`についてレジストラ移管処理が進行している

## 特定できていないこと

- 実在個人の氏名
- オリジンサーバーの生IP
- 実際の居住地や活動拠点

登録情報に表示される国や都市は、プライバシー代行や登録サービス側の情報である可能性があります。そのため、運営者の居住地を示す証拠として扱うことはできません。

技術構成から年齢、職業、人物像を断定することもできません。

# `anti-hasanmap.org`との関係

`anti-hasanmap.org`は、今回確認されたNjalla系への移動に加わっていません。

同ドメインはSquarespace Domains、Google系ネームサーバー、Google Sitesという別構成です。登録日、証明書、DNS、ホスティングも本体3ドメインと異なります。

したがって、現時点の公開情報では本体との同一運営を示す証拠はありません。

広告導線や活動時期について検証する余地はありますが、「タイミングが近い」「関連広告が表示された」という理由だけで同一運営と断定することはできません。

# 被害者・士業・公的機関が保全を検討できる情報

公開OSINTだけで非公開の登録者情報や操作IPを取得することはできません。

一方、正式な法的手続きや公的照会に備え、次の事業者へ関連記録の保全を求めることは検討できます。

## Cloudflare

対象:


保全対象の候補:

- ゾーン作成日時
- DNS設定変更履歴
- アカウントログイン履歴
- APIトークンによる操作履歴
- 6月8日前後のゾーン削除・ネームサーバー変更記録

## Tucows / OpenSRS


- Auth Codeの発行・利用記録
- `.org`の移管要求日時と手続き記録
- `.top`の`server hold`に関する記録

## Immaterialism Limited / Njalla側

対象:


- DNS設定の操作記録

第三者が非公開情報の開示を受けられるわけではありません。まずはログ保全を求め、被害者本人、代理人、弁護士、公的機関による正式照会へつなげることが現実的です。

大量通報や個人による突撃は避けるべきです。対象、識別子、確認日時、根拠URLを整理した保全依頼の方が有効です。

# この調査でしないこと

- 対象サーバーへのポートスキャン
- 脆弱性診断や侵入
- APIへのPOST
- 被害者データの取得
- 氏名や住所の転載
- 鍵アカウントや削除投稿の内容の推測
- 根拠のない個人・企業への犯人認定

必要なのは閲覧数や犯人探しの熱狂ではなく、被害を増やさず、公開情報を正確に残し、正式な手続きへつなげることです。

# まとめ

破産者マップは、2026年6月11日現在、3ドメインとも閲覧できません。

しかし、その直前には新しい`.cc`ミラーが用意され、その後3ドメインすべてが18秒以内に同じNjalla系管理基盤へ移されました。さらに`.org`ではレジストラ移管が進行しています。

これは「復活した」という証拠ではありません。

一方で、「何もせず消えた」という動きとも異なります。

現時点で最も正確な表現は、次のとおりです。

> サイトは停止している。しかし、3ドメインの管理は短時間で一括再編され、移管処理も進んでいる。再公開の準備か、ドメイン保全・撤退処理かは、まだ確定できない。

今後の注目点は、`.org`の`pending transfer`が解消した後のレジストラ、3ドメインへのA/AAAA/CNAME再設定、新しい証明書、新ミラーの追加です。

興味本位で対象サイトを探したり、個人情報を拡散したりする必要はありません。

追うべきなのは、被害者ではなく、インフラの公開記録です。
