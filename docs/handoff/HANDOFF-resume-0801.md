### 計器1: アイコングリッドの動き（v0.1.1208）

ユーザー報告「増えていく動きならいいけど、そうじゃない」。状態速報にこう出る:

```
アイコングリッド 作り直しN回(スライドX/増加Y) / 累計N枚 / 平均Nms — <判定>
```

- **「スライド支配的」と出たら** → 推論が確定。`STORY_GROWTH_MAX_CELLS`(360)到達後は
  窓をスライドさせず固定する方向で直す。積み上がり演出そのものは設計として正しいので壊さない。
- **「積み上がりのみ」と出たら** → 私の読み違い。別の原因を探す。

真因の推論（未実測）: `popup-entry.js` の `syncStoryGrowth` が
`STORY_GROWTH_STATE.sourceOffset = Math.max(0, srcLen - target)` を計算しており、
上限超えではコメント1件ごとに offset が進む。`rebuildStoryGrowth` は `innerHTML=''` で
全消し再構築するため、毎回360枚が総入替になる。

★ユーザーの設計意図は「ぷよぷよのように積み上がる」。上限を境に実装が別物にすり替わっている
のが問題であって、演出自体は正しい。

### 計器2: 会場モードの立ち上がり（v0.1.1207）

ユーザー報告「立ち上がりが遅い、もしくは出ないときがある」。**会場を開いた状態**で速報を取ると出る:

```
会場立ち上がり 開いたN回 / 鏡◯ms / 集計◯ms / 初描画◯ms / 初席◯ms / <フラグ>
```

- 鏡が大きい → 鏡の catch-up（`chrome.storage.local.get`・最大3秒待ち）が遅い
- 集計が大きい → `aggregateParticipants()` のチャンク差分読みが遅い
- **初描画は速いのに初席が「—」** → 描けているが人が居ない = **匿名主体なら仕様**

★「出ない」報告には仕様が混ざっている。実際 lv351078551 では
`userId付き率1.6%`（123件中1件）で会場0人になったが、これは正常。
計器は「描画したが0人」と「人が見えた」を別に記録するので、そこで判別できる。

★会場を開いていないと `venueSeatsDiag: null` になり、この行は出ない。

## 反省（次のセッションが同じ轍を踏まないために）

### 1. 自分で規律を破って性能を壊した（v0.1.1201 → 1204）

v0.1.1201 の席なしホバー補完で、**paint のたびに5段すべてを
`querySelectorAll('.nl-story-userlane-cell')` で走査**していた。会場213人規模では描画のたびに
これが走り、拡張全体（マーケ分析・診断）が重くなった。

コメントには自分で「hot path 非汚染」と書いていたが、実際は真逆。
このプロジェクトには「paint のたびの DOM 走査は禁止」という明示的な規律がある。

**切り分けで分かった重要な事実**: マーケ分析のHTML生成は速い（実配信規模2,800件で
集計12ms + 生成54ms）。「(3/3) HTML生成で止まる」ように見えたのは、その表示の後に
画面更新の機会が無いまま**ブラウザ全体が会場側の処理で詰まっていた**ため。
巻き添えを食っていただけで、マーケ分析自体は無実だった。

### 2. 配線の存在だけを見るテストは効かない

v0.1.1201 で書いた wiring テストは文字列スキャンだったため、`if (false)` を前置する変異を
検知できず20件緑のまま通った。reality-checker から受けた指摘と同型の穴を自分で作っていた。
呼び出しが**無条件に実行される文**であることまで断言する形に直した。

### 3. 推測で対象を決めない

「キャラと枠を消して」で、ユーザーが残したい部分を消しかけた（実行前に止められた）。
以前の要望との連想で対象を推測したのが誤り。**画面の指定は推測せず確認する。**

## この環境で効いた手順（そのまま使える）

```bash
npm run verify:cc          # 出荷ゲート一本（test/lint/typecheck/build/tracked-imports/
                           #   tree-map/site-health/feature-map/verify:bump）
npm run copy:ext           # C:\nicolive-ext へ配布（この後ユーザーが 🔄 → F5）
```

- 新規 lib を足したら `npm run tree-map` と `npm run feature-map` の再生成も同じコミットに含める
- push すると pre-push フックがビルドを走らせるので、**push 直後は必ず dist の buildId が
  1つずれる**。追いかけると終わらないので打ち切ってよい
- `git add -A` は使わない。以前から未追跡だった無関係ファイルを巻き込む（今回1回踏んだ）
- 計器を足したら**必ず printer まで通す**。`venueSeatsDiag` も `statusFastDiagLite` も
  フィールドを個別に列挙する造りなので、そこに足さないと値は貯まるのに永久に読めない
