## ★このセッションで確定した事実(コードで裏取り済み)

### 1. 前の引き継ぎの「最優先タスク」は【誤った原因】への対策だった

前引き継ぎは「幅が足りないから埋め込みが `display:none` で消える。だから
『📐 このタブが狭いため表示できません』と案内を出せ」と書いていた。**これは誤り。**

真相: `content-entry.js:7606` の
`if (!_inlineHostEverShown) hidePageFrameOverlay('autoshow_off')`
= **「こん太アイコンを押すまで出さない」という設計どおりの初期状態**。
幅不足のときは消さずに `below` へ降格するだけ(`inlinePanelDiagPlacementHints` は
文言を持つだけで、消す判断には関与していない)。

→ 実装していたら「押していないだけの人に嘘の理由」を表示していた。**この案は破棄。**

### 2. 「二択」ではなかった(ユーザーの提起が正しかった)

面は6つ(埋め込み/サイドパネル/会場/ライブビュー/コメビュ/状態)、
**埋め込みだけで配置4通り**(`beside`/`below`/`floating`/`dock_bottom`・`storageKeys.js:436-442`)。
ただし**ポップアップのUIに出ているのは「横付き / 下」の2つだけ**=残り2つは到達不能。

| 配置 | 実際の挙動(コード確認) |
|---|---|
| `beside` | 動画の幅を奪う(1100px必要) |
| `below` | 下に押し込む |
| `floating` | **動画の上に浮く**(position:fixed / 420px幅 / z-index 2147483646) |

★`dock_bottom` は動画が画面の7割以内なら食い込み0(`source:'player-rect'`)。

 ただし**UIに露出していない**ので、出すなら配線が要る(未着手)。

### 3. 会場が映像を覆っていたのは「バグではなく3つの会議結論の積み重ね」

- ① 2026-06-14「映像セーフエリア」: 中央に映像を残す。減らすなら**表示人数**を減らす
- ② 同日「満席感」: 人数↑→会場↑(48→56→64→**72vh**)
- ③ 2026-06-22「全員500人の顔」: 同時表示上限(~150)を撤廃し overflow-y へ

③が①の逃げ道を塞ぎ、②が高さを押し上げた。2,769人で **72vh**=映像が実質ゼロ。
**単体では3つとも正しい判断で、誰も間違えていない。**

→ 会議(4体・3対1)で**②を降ろす**と裁定。①=機能的ハード制約 / ③=核心価値 /
 ②=満席感を**面積で買おうとした実装判断に過ぎない**。
→ **v0.1.1322 で 48vh 固定**(`resolveVenueMaxHeightVh`)。旧実装を同じハーネスで
 再生して4件が赤になることを確認済み(偽陽性の緑ではない)。
