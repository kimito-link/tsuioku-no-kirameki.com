## 1. ★Botの見立ては成立しない（実コードで確認）

### 事実1: サイドパネルに幕(cloak)は【無い】
`extension/sidepanel.html` の `cloak` 3件は **すべてコメント**。実コードに幕は無い。
```
:8   v0.1.1279 で幕(cloak)を足した版から黒が始まり…（経緯の記述）
:152 ■ これは【幕(cloak)ではない】——混同すると12版の失敗を繰り返す
:153 [[cloakNotForSidePanel]] が禁じたのは【中身を隠す幕】
```
★v0.1.1423 で **導入時(795c41b3・25行)の姿へ戻した**と明記。

### 事実2: 地の色は iframe より【先】に塗られている
`sidepanel.html:193` の body 構造（実物）:
```html
<div id="nl-underlay"></div>
<iframe title="ニコ生ログ" src="popup.html?inline=1&dock=sidepanel"></iframe>
```
`#nl-underlay`(`:169-183`): `position:absolute; inset:0; background-color:#fffaf2; z-index:0`

⟹ ★iframe が透明でも**背後にクリーム色がある**。Chrome の暗い地は出ない。
　　`:118-122` に実測記録あり —「透明にした状態で親の色を読むと rgb(255,250,242) が返った」

### 事実3: html にも地の色が二段構えで宣言済み
`sidepanel.html:1` と `popup.html:1` は**同値**（実物確認）:
```
style="color-scheme: light; background-color: #fffaf2;
       background-image: linear-gradient(160deg, #fffaf2, #eef8ff)"
```
★検査 `pageColorSchemeGate` / `colorSchemeMetaPresent` / `sidepanelBlackScreen` が機械照合。

⟹ ★**「色を宣言する方向」は既に全部やってある。** ここを触るのは13版目になる。

## 1. ★同じ症状が過去に特定されている（popup.html:406 実物）

v0.1.1433 の記述が**ユーザーと同じ言葉**を使っている:

## 2. ★対策は入っているが、body に穴が残っている

| 要素 | パース時点で塗られるか |
|---|---|

| ★`popup.html` の **body** | ★**inline style が無い**（`<body>` タグは素） |

> `<style>` 内の `html{background}` も間に合わない。
> ★インライン style 属性なら HTML パース時点で効く。

★html はこの理由で inline 化された。★**body は inline 化されていない。**

## 4. ★残った可能性（実測で絞り込んだ結果）

| 可能性 | 根拠 |
|---|---|
| ★**Playwright の Chromium では再現しない環境差** | 444+193 フレーム測って一度も黒が出ない。実機は「毎回」出る＝**環境差が症状を決めている** |

　これは Playwright では出せない（`chrome.sidePanel.open()` はユーザー操作が要る）。

★今回足した `judgeSidepanelBandStripes` は帯ごとの塗りを判定できるので、
　実機で拾えれば「どの帯が塗られていないか」を機械で言える。

## ★次に測るもの（ここに絞られた）

★**本物の Chrome サイドパネル（`chrome.sidePanel`）として開いた文書**。
Playwright は `sidepanel.html` を**普通のタブ**として開いており、
サイドパネル固有の描画経路（別プロセスの合成・パネル背景・GPU ラスタ）を通っていない。

★実機で拾うべき値（`judgeSidepanelBandStripes` が判定できる形）:
1. 縦に5点、`elementFromPoint` → 祖先チェーン → 塗り手が居るか
2. ★**居座る**ので、開いてから数秒後でも測れる（フレーム単位の急ぎは不要）
3. `devicePixelRatio` / GPU ラスタ設定（縞＝**タイル境界**の可能性が残る）

★★**仮説を1つ追加（未検証）**: 縞が**規則的な横帯**なら、GPU のラスタタイル境界かもしれない。
　その場合コードではなく**合成レイヤの問題**で、`will-change` / `contain` / 巨大要素が引き金になる。
　★このリポは `content-visibility` で2回・`contain:size` で1回踏んでいる領域。
　★ただし**これも推測**。実機で縞の間隔（等間隔か・何pxか）を見れば切り分く。

## ★ユーザーに1つだけ聞くとしたら

　等間隔 → 合成/ラスタ側。不規則 → 描画（中身）側。★ここで探す場所が半分に減る。
