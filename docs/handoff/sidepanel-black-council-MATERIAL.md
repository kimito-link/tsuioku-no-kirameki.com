## 3. ★重要な留保(会議はここを踏まえること)

### 3-1. ★【裏取り完了】「14.5秒」は範囲であって断定値ではない(計器は正しい)

観測点は離散(sidepanel-entry.js:519):

```
0, 60, 120, 200, 300, 450, 600, 800, 1100, 1500, 2000, 2500, 3500,
5000, 8000, 12000, 18000, 25000, 30000
```

`t=14574ms` は「**12000 の次のサンプルまで 0 だった**」の意味で、
実際に面積を得たのが 12.1秒でも 14.5秒でも同じ行になる。

★ただし **計器は既に正しく「範囲」で出している**([sidepanelSelfDiag.js:49](../../src/lib/sidepanelSelfDiag.js)
`summarizeZeroAreaWindow` を確認):
`窓0x0の継続=t=98〜14574ms(14778msまでに面積確定・16点)` の
「**14778msまでに**」がその範囲表現。断定していない。**計器の欠陥ではない。**

★**結論**: 「14.5秒黒かった」は**上限であって断定値ではない**が、
**下限でも12秒を超える**(12000のサンプルで0だった)ので、
いずれにせよ**人が耐えられない長さ**である点は動かない。
([[measure-the-region-you-claim-2026-08-10]])

### 3-2. ★【裏取り完了・真因確定】幕が15秒残るのは「保険が打ち消されている」から

当初「保険が動いていない可能性(未確認)」と書いたが、**コードを読んで確定した**。
推測ではない。

**確定した事実(すべて実コードで確認):**

1. 保険は **400ms** で走る。出荷ビルドにも入っている
   (`extension/dist/cloak-failsafe.js` の中身を確認):
   ```js
   setTimeout(()=>{document.documentElement.removeAttribute("data-nl-popup-primary-cloak")},400)
   ```
   `popup.html:10376` で `dist/popup.js` より前に読み込まれる。**保険は正しく動く。**

2. ところが [popup-entry.js:4043](../../src/extension/popup-entry.js)
   `ensurePopupPrimaryCloakedBeforeFirstReveal()` が **cloak を再付与する**:
   ```js
   function ensurePopupPrimaryCloakedBeforeFirstReveal() {
     if (popupPrimaryRevealDone) return;              // ★ガードはJS内フラグだけ
     document.documentElement.setAttribute('data-nl-popup-primary-cloak', '1');
   }
   ```

3. ★**保険は属性を外すが `popupPrimaryRevealDone` を立てない**。
   よってガードが効かず、次に呼ばれた時点で**付け直される**。

4. 呼び元は **`refresh()` の中**([popup-entry.js:15298](../../src/extension/popup-entry.js))。
   `refresh()` は起動後に何度も走る。

**＝時系列(これが15秒の正体):**
```
  0ms      cloak は popup.html に静的に付いている
  400ms    保険が外す              → 一瞬見える
  その後   refresh() が付け直す      → また黒い
  …        refresh が遅い(今回 7,883ms・lives(stale) 3,301ms)ため
  14985ms  revealPopupPrimaryOnce に到達せず、まだ黒い
```

★**「保険を早くする」方向(v1352/1353/1354 の3版)が効かなかった理由**がこれで説明できる。
保険を何msにしても、**その後で付け直される**なら意味がない。
＝[[gate-may-be-the-only-recovery-path-2026-08-04]] の逆で、
**復帰経路を別の経路が打ち消していた**。

### 3-2b. ★【裏取り完了】シェードが14.5秒覆っていたのも説明がつく

v1373 で上限を 2.5秒にしたのに 14,574ms 覆っていた理由も**コードで確定した**。

**解除の呼び元は2つだけ**([popup-entry.js](../../src/extension/popup-entry.js)):

| 行 | いつ呼ばれるか | 実効の待ち時間 |
|---|---|---|
| 22069 | **`setTimeout(..., 5000)` の中** | ★**5秒待ってから**上限2.5秒を開始＝最短 **7.5秒** |
| 19641 | `refresh()` の finally(初回のみ) | refresh の所要に引きずられる(今回 **7,883ms**) |

`dismissInlineShadeWhenDataReady(cap)` 自体は正しく `setTimeout(..., cap)` で
強制解除する([18748行](../../src/extension/popup-entry.js))。**上限は効いている。**
★問題は **上限の起点が「呼ばれた時刻」**であること。
＝[[timer-delay-is-not-timer-origin-2026-08-12]] を**また踏んでいる**
(私が今日メモリに書いた当の教訓)。

**5秒 + 2.5秒 = 7.5秒**、これに refresh の遅延が乗ると 14.5秒に届く。実測と整合する。

### 3-3. storage 飽和との相関(因果は未証明)

- 更新所要 **7,883ms** / 保存 **3,489件** / lives(stale) 3,301ms

- ★「storage を軽くすれば窓0x0も短くなる」は**相関のみで因果は未証明**

### 3-4. 「あとから黒くなった(15秒後のvisibleで2回)」

起動直後の一瞬ではなく、**後から**黒くなっている。
これは窓の滑り出し(起動時のみ)では説明できない可能性がある(未確認)。
