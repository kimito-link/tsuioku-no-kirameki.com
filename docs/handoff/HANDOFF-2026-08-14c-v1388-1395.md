## 2. ★会場にギフトが出ない（根治・v1394）

### 真因
①POP の tick は `document.hidden` で**無条件 early return**していた。
会場を開く→①が隠れる→`renderStoryUserLane` が走らない→
その中の `publishLaneMirror` も走らない→**鏡が更新されない**→
会場は656秒前（ギフトを投げる前）の鏡を描き続ける。

★**「描かない」は正しい**。間違いは**描画と publish を同じ early return に載せていた**こと。
publish は【別の画面のためのデータ供給】で、自分の可視性とは無関係。

### 直し方
`src/lib/hiddenPublishPolicy.js`（純関数・test付き）で分離:

| 状態 | paint | publish |
|---|---|---|
| 見えている | ✅ | ✅ |
| 隠れ + 会場open | ❌ | **✅ ← 根治点** |
| 隠れ + 会場closed | ❌ | ❌（誰も読まない=省電力） |

### ★私の誤診2回（次の人は繰り返さない）
- `venueLaneBuckets.js:196` の `gift:[]` が犯人 → **誤り**（フォールバック経路で、実機は降格していない）
- 折りたたみで DOM が外れて `noEls` → **誤り**（速報の `lanePublishSkip` は見送り0回）

**どちらも速報の数字を読めば否定できた。** 仮説を実装する前に既存の計器を読む。

## 5. この日に確立した掟

- **「見えていないから止める」を書くときは、その処理の受益者が自分だけか確認する**（v1394）
- **進行中(取得中)を出すなら「いつからか＋いつまで許すか」をセットで持つ**（永久ペンディングは見えない失敗）
- **防御が効いた回数を分子に入れない**（防御が効くほど数字が悪化する誤誘導になる・v1391）
- **起動直後のスナップショットで断定しない**（「まだ分からない」と「壊れている」を混ぜない・v1391）
- **`Number(null) === 0`**。null を素通しすると「不明」が「0」に化けて判定が永久に出ない（2回踏んだ）
- **registry 登録・純関数・test が緑でも、呼び出し側が入力を渡していなければ画面には出ない**（v1395）
- **popup-entry.js は max-lines 上限にちょうど張り付いている**。足すなら lib 側に置き、副作用 import 1行にする。既存の複数行 import を1行に畳んで枠を作る（挙動不変）
