### v0.1.1211 — 速報に「popup起動から何秒後の値か」を明記

**私自身の誤読を止めるための版。**

速報の「約22秒前にpopupで取得」は【速報生成時刻からの経過】であって
【popup起動からの経過】ではない。実際には起動362ms後のスナップショットだったのに
「22秒経っても鏡が空＝取りこぼし」と誤読した。

答えは `loadShadeProbe.shadeAgeMs` として既にJSONにあったのに、人間が読む行に無かった。

- 3秒未満なら「ゼロでも正常です」と明示（鏡のflushはpublishの400ms後・幕は800ms最低表示）
- **実装中に `Number(null)===0` の罠を踏み、「値が取れなかった」を「起動0.0秒」と
  偽る不具合を作った**。テストが検出

### v0.1.1212 — 会場の幾何差が本物か測定対象ズレかを判別

実測で `幾何≠ link:128×40px(①110×38px)` が出たが、調査の結果
**①popup.html と venueBar.js の当該CSSはバイト単位で同一**だった。

真因は計器の構造。両側とも各段の**先頭タイル1枚**しか測っておらず、
meta は max-width までの収縮ボックスなので「名前が長い人ほどタイルが広い」。
①と会場で先頭の人が違えば、CSSが完全一致でも差が出る。

- 両側の計測に `tileKey`（測った当のタイルの userKey）を追加
- 3分類: `css_mismatch`(同一人物=本物) / `measured_different_people`(別人) /
  `unknown_target`(判定不能・どちらにも決めつけない)

★**これを入れずにCSSを触っていたら、正しいものを壊していた。**
  実際その直前まで「移植漏れの再発だ」と判断しかけていた。

### v0.1.1213 — 読み上げで「読まれずに消えた件数」を計測

実配信(4時間8分・記録1万件)で読み上げが破綻。ところが計器の帳尻が合わなかった:
1分に約52件届いて「読めた約6件＋間引き12件＝18件」しか説明できず、**約34件が行方不明**。

真因は `voicePlayer.js` の `if (!wav ...) { ...; continue; }`。
voicevoxClient は synthesis を8000msでタイムアウトさせ catch で null を返すが、
受け側が spokenTotal も drop も増やさずに捨てていた。

- `synthNullTotal` / `synthNullNearTimeout` を追加（時間切れかどうかを別枠で数える）
- ★あわせて `buildVoiceDiagLine` の早期returnを修正。合成が全滅すると spokenTotal が
  0のままなので、**読み上げが最も壊れているときほど診断行が丸ごと消える**構造だった

**実測結果（2026-08-01 16:26 の速報）**: `合成失敗1件(時間切れ0/その他1)`。
→ **時間切れではない失敗経路が実在する**ことを確認。大規模配信での再測が必要。

### 参考: v0.1.1215 のすり替え計器の取り方（v0.1.1217 で入替0になるはず）

**取り方に条件がある。** 3回試して3回とも読めなかったので手順を明記する。

| 条件 | 理由 |
|---|---|
| **watch ページ内**のポップアップであること | 別窓だと `viewKind:"popup"` かつ `lidMiss` で描画が起動しない |
| アイコングリッドが**実際に画面に見えている**こと | 描画されないと計器が動かない |
| popup を開いたまま**数十秒以上**置くこと | 起動0.3秒の値では全部ゼロ（v0.1.1211の警告行が出る） |

```
グリッド中身更新 N回 / 書換Nマス — 中身の入替Nマス=既存アイコンが別人にすり替わっています(最大Nマス/回)
```

- **入替が多い** → 推論が確定。上限到達後は窓を固定する方向で直す
- **入替0（積み上がり）** → まだ別の原因がある

★`viewKind` が `embed_watch` になっている速報でないと読めない。
  `popup` になっていたら取り直し。

## この環境で効いた手順

```bash
npm run verify:cc          # 出荷ゲート一本
npm run copy:ext           # C:\nicolive-ext へ配布
```

- **新規 lib を足したら** `npm run tree-map` と `npm run feature-map` の
  **両方**を再生成して同じコミットに含める（片方だけだと feature-map で赤）
- **新規ファイルは `git add` してから** `verify:cc` を回す
  （`check:tracked-imports` が「未追跡ファイルへの import」で赤になる。
  これは過去に Vercel 全滅を起こしたコミット漏れを検知するゲート）
- **型定義（`@typedef`）にもフィールドを足す** — typecheck が検知する
- push 後は pre-push フックのビルドで dist の buildId が1つずれる。追わなくてよい
- `git add -A` は使わない

### ユーザーへの反映3手順（push しただけでは届かない）

1. `git pull`（こちらで実行する。ユーザーに頼まない）
2. 拡張をリロード（🔄）← **ユーザー操作が必須**
3. watch タブを F5 ← **ユーザー操作が必須**

`copy:ext` まで済ませておけば 2 と 3 だけで反映される。
