# 会議のお題 — 「顔を近づけないと読めない」を解く（2026-08-14）

> 司令塔が実コードを測ってから書いた**地図**。会議はこの数字を前提に発散すること。
> ★ユーザー確定の方向: **最初から大きく + ユーザーが調整可能**。ここは議論しない。
> ★決めてほしいのは「**どこを**大きくするか」＝枠の設計。

---

## 1. ユーザーの実際の言葉（最優先の一次情報）

> 「どの画面サイズでみても めっちゃおおきいほうがいいとおもう　会場モードも通常POPモードも」
> 「将来のスマホ化もそうだけど **みんな画面に顔をちかづけてみないとみれない**らしい」
> 「特に **スマホしか対応していない配信** など、わざわざ顔をちかづけるという手間があってつらいらしい」
> 「ぜんたいじゃなくて **BSPみたいに大きくする枠をつければいい** とおもう」

★最後の一言が効いている。**全体を一律に拡大するのは却下**された。
　理由（司令塔の解釈・会議で検証してほしい）:
　全体 zoom は情報量を減らす。この拡張の価値は「たくさん見える」ことなので、
　全部大きくすると**別の価値を壊す**。

★「みんな」＝配信者本人だけでなく**視聴者/コラボ相手**も見ている可能性。
　誰が読む画面なのかを会議で確定させたい（設計が変わる）。

## 3. 会議で決めてほしいこと

### Q1. 「大きく見せる枠」はどれか（複数可・優先順位つき）

- (a) **PICK UP 帯を本当に大きくする**（既存・場所を取らない・会場にも同じ帯がある）
- (b) **最新コメントの大型パネルを新設**（情報量は多いが既存表示を圧迫する）
- (c) **別ウィンドウの大画面ビュー**（本体レイアウト無傷・別窓を開く手間）
- (d) 会議が思いつく別案（**これを期待している**）

★判断基準を先に決めてほしい:「離れて何を読みたいのか」。
　コメント本文か / 誰が来たか(名前) / 金額(ギフト) / 人数 — **全部は大きくできない**。

### Q2. 自動調整の作法

「最初から大きく + ユーザーが調整可能」は確定。詰めるのは:
- 既定値をいくつにするか（何px相当で「顔を近づけずに読める」のか）
- ±ボタンか / 画面幅に自動追従(clamp)か / 両方か
- 設定はどこに置くか（毎回探させない）
- ★**どの画面に効くか**（POP / 会場 / コメビュ / 別窓 で共有するのか個別なのか）

### Q3. やってはいけないこと（会議で反証があれば歓迎）

- `transform: scale()` は**当たり判定とスクロール量がズレる**ので使わない
- レーンの `perRow/段数/幅` を直接いじらない（ちらつき対策 diff-skip に波及・過去7版空振り）
- font-size を161箇所個別に上げる（レイアウト総崩れ）
