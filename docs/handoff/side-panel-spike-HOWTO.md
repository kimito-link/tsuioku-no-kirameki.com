> ブランチ: `spike/side-panel-preview` / 2026-08-06
> ★これは「見てから決める」ためのプレビュー。master は無傷(v0.1.1272 のまま)。

## なぜ Side Panel か

点滅の根治候補。**ニコ生のページの【外】**にパネルを出すので、ページ側から触れない。

```
今のパネル   : ニコ生のページの中に間借りしている
              → ページが再レンダーすれば消える/潰される/作り直される
              → だから25版かけても止まらなかった

Side Panel   : ブラウザ自身のUI領域(ページの外)
              → ニコ生のDOMではないので、ページは触れない
              → 消しようがない
```

Shadow DOM 案は「ページの中で身を隠す」策で、器を消される弱点が残る。
Side Panel はそもそもページの外なので、その弱点自体が無い。
しかも**土台は既に入っていた**(sidePanel権限・side_panel宣言・sidepanel.html)。
足りなかったのは「開く処理」だけ。

### ★実装上の注意(実測して判明した罠)

`chrome.sidePanel.open()` は**ユーザー操作の文脈でしか呼べない**。
実際に `may only be called in response to a user gesture` を踏んだ。

```
❌ クリック → await で設定を読む → open()   … 文脈が切れて拒否される
✅ クリック → open() を同期で呼ぶ → 後で設定を整える
```

そのため設定は**メモリキャッシュを同期で読む**形にし、SW起動時とstorage変更時に
温め直している。これが無いとSW再起動後の最初の1クリックだけ効かない
(ユーザーには「たまに効かない」に見える=最悪の症状)。

## 試し方

### 1. 反映
```bash
git checkout spike/side-panel-preview
git pull
```
そのあと **拡張リロード → watch タブ F5**。

### 2. サイドパネルに切り替える

設定UIはまだ作っていないので、切り替えは手動。
拡張の「サービスワーカー」のコンソールで次を実行する
(chrome://extensions → この拡張の「Service Worker」をクリック → Console タブ)。

```js
chrome.storage.local.set({ nls_toolbar_action_policy: 'side_panel' })
```

そのあと**ツールバーのこん太アイコンをクリック**するとサイドパネルが開く。

### 3. 元に戻す

```js
chrome.storage.local.set({ nls_toolbar_action_policy: 'prefer_focus_inline' })
```

**コード変更は不要**。設定を戻すだけで完全に従来動作へ戻る。

## 見え方の違い(ここが判断のポイント)

| | 今のパネル | Side Panel |
|---|---|---|
| 場所 | 動画の横(ページの中に埋め込み) | ブラウザ右側の専用領域 |
| 点滅 | **する**(ページに消される) | **原理的にしない** |
| 幅 | ページのレイアウトに従う | ユーザーがドラッグで調整できる |
| 配信を切り替えたとき | 追従する | タブ固有(setOptionsのtabId)で追従する |
| 全画面の動画と併用 | 干渉する | しない |

★**good/bad ではなく好みの問題**。実際に見て決めてほしい。

## この spike で変更したファイル
