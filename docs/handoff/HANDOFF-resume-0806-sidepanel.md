### Side Panel 実装の要点(触るとき注意)

- `extension/background.js` のクリックリスナー
  - **`open()` はユーザー操作の文脈でしか呼べない**。`await` を挟むと拒否される
    (`may only be called in response to a user gesture` を実際に踏んだ)
    → リスナー先頭で**同期的に**呼び、設定はメモリキャッシュを同期で読む
  - 判定は「**明示的に埋め込みを選んでいない限り開く**」に倒してある
    (キャッシュ未読込・読み取り失敗もサイドパネル側へ。逆にすると「たまに点滅」になる)
  - タブ固有(`setOptions({tabId})`)。過去に「全タブ共有で別配信を掴む」問題で撤退した記録あり
- 埋め込みに戻す道は残してある: storage の `nls_toolbar_action_policy` に `'prefer_focus_inline'`

## 作業の型(このリポの規律)

- 出荷ゲート: **`npm run verify:cc` 一本**(全10ステップ)
- **変異テストで赤を確認するまでが1セット**
- version bump: `package.json` / `extension/manifest.json` /
  `tsuioku-no-kirameki/index.html`(4箇所) / `src/lib/changelog.js`
- 新規lib追加時は `npm run tree-map` `npm run feature-map` `npm run site-health` を再生成
- 反映3手順: **pull → 拡張リロード → watch タブ F5**
  ★master に入れてあるので、ユーザーは `git pull` だけでよい
  (ブランチ名を毎回打たせるのは負担、と指摘を受けた)

### ★実機確認は chrome-devtools MCP でできる

```
mcp__chrome-devtools__install_extension  … extension/ フォルダを読み込める
mcp__chrome-devtools__reload_extension   … 変更後の再読み込み
mcp__chrome-devtools__trigger_extension_action … アイコンクリック相当
mcp__chrome-devtools__evaluate_script    … ページ/SW で計測できる
```
**「入れました、次で分かります」を繰り返さない。出す前に実ブラウザで測る。**
点滅の判定は rAF で毎フレーム観測して消失回数を数えるのが確実
(例: 20秒/1198コマ observed → vanishCount 0)。

## 踏んだ地雷(繰り返さない)

1. **`grep` でビルド成果物の日本語は見つからない**(バンドラが `\uXXXX` にする)。
   `node -e` でデコードして確認する
2. **`popup-entry.js` は max-lines ラチェットがある**(現在22275)。
   バグ修正で超えたらラチェットを実測+50へ更新してよい(理由をコメントに残す)
3. **`python` の一括置換は CRLF/LF で失敗する**。`newline=''` で読み書きする
4. **テストがゲートの存在を固定していることがある**。ゲート撤去時は
   テストの「向き」を反転させる(消したことを固定する)
5. MCP の `trigger_extension_action` は本物のクリックと扱いが違うことがある。
   サイドパネルが開かないときは**ユーザーの実クリックで確認**してもらう
