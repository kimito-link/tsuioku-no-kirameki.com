# VOICEVOX読み上げを「どのPCでも動く」ようにする — 設計

- 起案: 2026-08-04（司令塔 Claude Code）
- 会議: `council/voicevox-any-pc-answers.json`（6体・design ルーティング・2巡）
- 発端: メインPCでは動くが、別のノートPCで動かなかった（ユーザー報告）
- 状態: **設計のみ／実装未着手**

---

## 0. 結論（先に書く）

**まず「なぜ動かないか」を名指しできるようにする。ポート設定UIはその後。**

理由は2つ。

1. ポート設定UIを先に作っても、**未起動・ファイアウォール遮断には効かない**。
   効かない相手のほうが多いと見られるのに、ユーザーには「設定したのに直らない」と映る。
2. 現状の助言文は「拡張側では直せません」で止まっており、
   **受け取った人が次に何をすればいいか分からない**。ここが実際の詰まりどころ。

## 1. 実装の現状（コードを読んで確認・推測なし）

接続先は**3箇所で固定**されている。1つ変えても動かない。

| 場所 | 内容 |
|---|---|
| `src/lib/voicevoxClient.js:2` | `VOICEVOX_BASE_URL = 'http://127.0.0.1:50021'` |
| `extension/manifest.json` | `host_permissions` に `http://127.0.0.1:50021/*` のみ |
| `extension/background.js:3451` | SSRF防止の許可リストで 50021 のみ通す |

タイムアウト既定値（`voicevoxClient.js`）:
- 接続確認 3000ms / audio_query 3000ms / synthesis 8000ms

失敗分類の計器は**既にある**（`src/lib/voiceSynthFailureReason.js`）。
分類: `unreachable` / `timeout` / `query_http` / `synth_http` / `query_body` / `synth_body` / `unknown`

現状 `unreachable` の助言文:
> VOICEVOX に接続できていません。起動しているか・ポート(既定50021)が合っているか
> 確認してください(拡張側では直せません)。

**設計当初からの宿題**: `memory/reference_voicevox_unique_voice_reading.md:46` に
「COEIROINK / AivisSpeech 対応（VOICEVOX互換API・ポート違いだけ）」が将来課題として記載済み。
今回の件はこの宿題が表面化したもの。

## 2. 会議の結論と、司令塔による訂正

### 会議が合意した点（採用する）

- ポート設定UIを先に作るのは**誤り**。FW遮断・未起動には効かない。
- `optional_host_permissions` による動的権限要求は**CWS審査でポートスキャン的挙動と見なされるリスク**がある。
  公開直後（v0.1.1244）の今、審査リスクの高い変更を初手に置くべきでない。
- 「ポート番号を調べて入力してください」は非エンジニア配信者には壁が高すぎる。
- まず**失敗理由の実態を可視化**してから吸収範囲を決める（「測ってから直す」規律に合致）。

### 会議の誤り（採用しない）

会議の最有力案は「**VOICEVOXプロセス検出・ポート占有チェック・ファイアウォール例外提示**を行う
診断モジュール」だったが、**Chrome拡張(MV3)にこれらの能力は無い**。
JSサンドボックスからプロセス列挙もFW設定読み取りもできない。
（会議自身も途中で「拡張単体では不可能」と気づいていたが、最終案に反映されないまま合意された）

ネイティブメッセージングホストを別途配布すれば可能だが、
**インストーラを配る話**になり、本プロダクトの配布形態（CWSからの拡張1本）を変えてしまう。
今回の規模に対して過大。**不採用**。

### 司令塔による実測（会議後に追加・ここが設計の要）

会議は「未起動とFW遮断は拡張から区別できない」として諦めたが、**実測すると区別できる**。

```
未起動のポートへ fetch:
  経過 21ms / TypeError: fetch failed / cause: ECONNREFUSED
```

- **未起動** → OSが即座に拒否 = **数十ミリ秒で失敗**
- **FW/セキュリティソフト遮断** → パケットが黙って捨てられる = **タイムアウトまで待つ（3秒）**

ブラウザの `Failed to fetch` は理由を隠すが、**所要時間は隠せない**。
この1つの測定値で、打つ手が正反対の2つを分けられる。

> 既存メモリ [[instrument-must-name-the-cause-2026-08-01]] の
> 「同じ症状に複数原因があると開発者が誤判定する」がそのまま当てはまる。
> 今回は**ユーザーが**誤判定する版。

## 3. 原因の見立て（優先度順）

| # | 原因 | 見分け方 | 打つ手 |
|---|---|---|---|
| 1 | VOICEVOXが未起動／未インストール | 失敗が**即座**(<300ms) | 起動を促す。インストール導線 |
| 2 | 別エンジンを使用（COEIROINK/AivisSpeech/SHAREVOX） | 50021が即失敗、他ポートに応答 | ポート設定（後述フェーズ2） |
| 3 | ポートずれ（多重起動・他アプリと衝突） | 同上 | 同上 |
| 4 | FW/セキュリティソフトがlocalhost遮断 | 失敗が**タイムアウト**(3秒フル) | 例外設定の案内（拡張では直せない） |
| 5 | 非力なノートPCで合成が8秒超 | `timeout`だが接続は成功 | 文字数制限・軽量設定 |
| 6 | 拡張のリロード漏れ・版ずれ | 既存の版数計器 | 反映3手順 |

**#1が最も多いと見ている**（VOICEVOXは常時起動するものではなく、この開発機でも今は落ちている）。
ただし**これは見立てであって実測ではない**。フェーズ1で確かめる。

## 4. 実装フェーズ

### フェーズ1: 原因を名指しできるようにする（審査リスクほぼゼロ・最優先）

`unreachable` を**所要時間で3つに割る**。

| 新分類 | 条件 | ユーザーに出す文言 |
|---|---|---|
| `not_running` | 失敗が即座(<300ms) | 「VOICEVOXが起動していません。VOICEVOXを起動してからもう一度お試しください」 |
| `blocked` | タイムアウトまで到達 | 「セキュリティソフトがPC内部の通信を止めている可能性があります。VOICEVOXを許可リストに追加してください」 |
| `unreachable` | 上記で判定不能 | 従来文言（**「判定不能」を残す**＝断定しない） |

変更するファイル:
- `src/lib/voiceSynthFailureReason.js` — 分類とラベルと助言文
- `src/lib/voicevoxClient.js` — 失敗時に**経過msを添えて**投げる（現状は理由だけ）

**注意**: 分類を足したら `statusFastDiagLite` へのpassthroughを必ず通すこと。
通さないと状態速報のコピペに永久に出ない（既知の地雷 [[fastdiag-lite-is-the-printer-subset]]）。

### フェーズ2: セットアップ確認UI（接続テスト）

読み上げ設定の近くに「接続テスト」ボタン1つ。押すと上記分類を実行し、
**原因と次の一手を1文で**出す。ポート入力欄は**この段階では置かない**。

### フェーズ3: ポート設定（フェーズ1の実測で必要と分かった場合のみ）

実測で「別エンジン/ポートずれ」が実際に多いと分かったときだけ着手する。
manifest を `http://127.0.0.1:*/` に広げると審査で理由説明を求められるため、
**候補ポートの固定リスト**（50021/50031/50032/10101 等）に絞るほうが通しやすい。
自動スキャンはしない（起動が遅くなる・審査でポートスキャンと見なされる）。

## 5. やらないこと（明示）

- ネイティブメッセージングホストの配布（配布形態を変えるため過大）
- 起動時の自動ポートスキャン（審査リスク・起動遅延）
- 外部への送信（ローカル保存のみの方針を崩さない）
- ポート入力UIを最初に出すこと（効かない相手のほうが多い）

## 6. 別件: 同じノートPCで「ページが応答しません」（2026-08-04 追報）

ユーザーから追加報告。**タブを2つしか開いていないのに**、
ニコ生タブと「追憶のきらめき コメビュ」の**両方**を名指しして
Chrome の「ページが応答しません」ダイアログが出た。

### 読み取れる事実（写真より・推測と区別すること）

- 固まったのは2ページとも（Chromeが両方を列挙している）
- 背後のコメビュは**描画済み**（アイコン列・段の説明・コメントが見えている）
  → 起動できずに固まったのではなく、**動いた後に詰まった**
- 右上に「**読み上げ：ON**」の表示あり
- タブは2つだけ = 多重起動や大量タブが原因ではない

### 切り分けの要点

「ページが応答しません」は**JSがメインスレッドを数秒占有し続けた**ときに出る。
ネットワークの遅さでは出ない。つまり**計算で詰まっている**。

VOICEVOXの件と**同一原因とは限らないが、無関係とも言い切れない**。
読み上げONの状態でエンジンに繋がらない場合の挙動（リトライ・キュー滞留）は
未確認。ここは**測ってから判断する**。

### この件で次にやること（VOICEVOXのフェーズ1より先でもよい）

1. ノートPCで再現したときに**状態速報をコピー**してもらう
   （どの処理が詰まっているかの当たりが付く）
2. 併せて、そのPCで**読み上げをOFFにしても再現するか**を1回だけ試してもらう
   → OFFで再現しなければ読み上げ経路、再現すれば別経路と分かる。
     質問1つで経路が半分に絞れる、最も安い切り分け。
3. 上記2つが揃うまで**コードは触らない**（推測で直さない規律）

> 過去に同型の事故がある: v0.1.1201 で「マーケ分析がHTML生成で止まる」ように見えたが
> 生成は速く、会場側の処理でブラウザ全体が詰まっていた巻き添えだった。
> **見えている場所と原因の場所は違うことがある。**
