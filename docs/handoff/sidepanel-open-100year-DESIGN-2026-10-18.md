# サイドパネルを開く瞬間の「黒い幕」— 100年持つ設計(下書き 2026-10-18)

> 状態: 設計のみ・未実装。実機の効果は未確認。測定は不確定(下の「分かっていること/いないこと」)。
> 触る場所: extension/background.js(`action.onClicked` と事前用意 `prearmSidePanelForTab`)・src/extension/sidepanel-entry.js(lv の自力発見)・extension/manifest.json(`side_panel.default_path`)。

## 分かっていること(コードと過去の実機で確認済み)
- 押した瞬間に Chrome が出す標準の読み込み表示(ダークでは黒地に灰色の横縞)は、パネルの path を open() の【あと】または【同時】に差し替えると居座る(background.js:3561-3570・v0.1.1434 の実機確認)。
- 押下時、いまのコードは lv が取れるたびに `setOptions({path:'sidepanel.html?lv=…'})` を【毎回】投げてから open() している(background.js:3580-3586)。事前用意(`prearmSidePanelForTab`)が済んでいれば同じ path なので無害のはずだが、済んでいないと path が変わり、読み込み直しが起きうる。
- 事前用意は `tabs.onUpdated`(読み込み完了/URL変化)でしか動かない(background.js:1110-1114)。次のときは動かない: 拡張を更新した直後に既に開いていたタブ・別タブから切り替えただけのタブ・SW が眠って起きた直後(推測)。→ そのタブでの最初の1回目の押下が、まさに「差し替えと open の競合」になる。
- パネル側は、?lv= が空なら自力で watch タブを探す仕組みを既に持つ(sidepanel-entry.js:155 付近・v0.1.1435)。

## 分かっていないこと(測れていない・断言しない)
- 実機の「押した瞬間の黒」が、上の競合で起きているのか、Chrome が最初のフレームを出すまでの素の時間なのか。画素録画は2回やったが、範囲に他のタブが映り込み、結論が出なかった(2026-10-18)。

## 設計の原則(原因が上のどれでも壊れにくい形)
1. **押下の経路は open() だけ**。押した瞬間に path を触らない(await も挟まない)。競合を起こす操作を、そもそも押下の経路から無くす。
2. **path は固定にする**。`side_panel.default_path` と起動時の `setOptions({path:'sidepanel.html', enabled:true})` を1回だけ。タブごとの path 状態を持たない=「事前用意が済んだか」という状態が消え、SW の再起動・拡張更新・タブ切替で壊れる経路が無くなる。
3. **lv はパネルが自分で決める**(`tabs.query({active:true, currentWindow:true})` で、いま見ているタブの /watch/lv…)。曖昧(watch が複数でどれも非アクティブ等)なら何も決めず、従来どおりの案内を出す。
4. **押す前に済ませることは「べき等・状態なし」だけ**。起動時・更新時・タブ切替時に、同じ関数を何度呼んでも結果が同じになる形にする(メモ不要)。
5. **測定は「手順」として残し、常時の計器を足さない**(MEMORY: 計器を足して満足しない)。実機の画素録画は、パネルの上端の細い帯だけを撮り、合図のあとに押す手順を docs に固定する。
6. **効いたかは実機の画素で判定**。コードの解析で「効くはず」と言わない。

## 変更案(小さい順・各1版)
- A(最小): 押下時の `setOptions` を、「そのタブに事前用意済みと分かるときは呼ばない」に変える。分かる手段=SW メモリの Set(眠ったら空=従来どおり呼ぶ)。危険は小さい・効果は限定的。
- B(原則2・3を実装): 固定 path + パネルの自力 lv 発見へ一本化。押下は open() のみ。事前用意と per-tab path を撤去。影響: 複数 watch タブの曖昧さの扱い・初回の iframe 読み込みが lv 発見の分だけ遅れるか(要・実測)。
- C: `tabs.onActivated` と `runtime.onInstalled/onStartup` で既存の watch タブを一括で事前用意(Aと組む場合の穴埋め)。

おすすめ: 先に画素録画(細い帯・合図あり)で、黒が「押した直後の最初の数フレーム」か「読み込み直し後の数百ms」かを分けてから、A か B を選ぶ。測れない場合は B(状態を持たない側へ倒す)。
