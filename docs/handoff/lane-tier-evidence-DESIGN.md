## 3. ★「観測済みの匿名が1000人来たら」への答え（必答論点）

**上段は埋まってよい。ただし3層で C1 を構造的に保証する。**

1. **門**: 根拠ゼロの匿名は E4→たぬ姉。**りんく段に到達する経路が存在しない**。
   C1（`tanuPolicy.js:10-12`）が守る利益は「**非匿名が埋もれない**」ことであって
   「匿名が上段に居ない」ことではない（原文どおり）。
2. **順**: 段内で**数値IDを匿名より必ず先頭**に。`storyUserLaneSort.js` の
   uidランク比較（`:31-35`）を thumbScore比較（`:27-29`）**より前**に出す。
   ＝匿名が何千人来ても非匿名は構造的に段の先頭。
3. **密**: 25人目以降をアイコンのみにする段内LOD（たぬ姉段で実績・実測1,615px→598px）。
   りんく段への適用は**実測してから決める**（v1の計器の結果次第）。

★**枠の上限（匿名はN人まで）は採らない**。Nを正当化する実測が無く、
「人数を減らす解」はユーザーが2026-08-12に禁止。上限分岐は fail-open の再発源。

1. ユーザーの指示の順序そのもの（「仕様見直し会議をしてから計器をつくって」）

3. v1単独で「正確なデータをださないといみがない」を解く（100%/7.3%の歪みが消える）
4. lib/domain内で完結＝**退化リスク実質ゼロ**
5. v1の計器とv2の法が**同じ関数**を使う＝v1の実測が「v2で何人昇格するか」の予告になる

## 5. 桁レンジは【直さない】（ただし「仕様」と呼ぶのをやめる）

`identity.js:34` の `\d{5,14}` は変更しない。根拠:
1. 新しい法では E1/E2 が **IDの形を見ない**ため、4桁の実在ユーザーも
   サムネか名前が取れれば**りんく段に入る**＝誤判定の実害の大半が法の側で消える

   ＝実測ゼロで払うリスクではない

「5〜14桁の根拠はニコ生の仕様ではなく既存挙動との互換維持。

## 7. 捨てた案と理由

| 案 | 却下理由 |
|---|---|
| **gpt-oss-20b案**（匿名は観測済みでも下段） | ★`tanuPolicy` の**現行実装と論理的に同一**。匿名522は今日と同じく埋まったまま＝**ユーザーの不満を1つも解かない**。**変更ゼロの案に版を1つ使うことになる** |
| りんく段の匿名枠上限（N人まで） | Nを正当化する実測が無い。「人数を減らす解」はユーザーが禁止済み。上限分岐は別名fail-openの再発源 |
| 桁レンジの即時修正 | 実害の大半は法の側で消える。残害は未実測。3画面全域に波及する変更を実測ゼロで同梱しない |
| 法Aのdemoteを残して法Bだけ直す | 真因は「2つの法の並立」。v2で正本を1本に確定する |
| 「確認済み匿名」専用段の新設 | 3画面のCSS・鏡契約・diff-skip鍵すべてに波及する最大工事。過剰設計 |
