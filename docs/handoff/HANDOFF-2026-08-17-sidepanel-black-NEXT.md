## 2. ★真因（確定済み・触ってよい場所/だめな場所）

### 構造が原因

v0.1.1275 でパネルを Side Panel へ移行したとき、
**`sidepanel.html` が `popup.html` を iframe で包む**構造になった。
直後から 1279→1283→1285→1289→1294→1298→1299 と**7版**「黒い」を直し続けている。

真因は **iframe の `about:blank` の隙間**
（[[about-blank-gap-is-the-black-2026-08-12]]）。
iframe の src が読み込まれる前の `about:blank` 文書には親の CSS が届かず、
`color-scheme: normal` ＝ OS がダークなら暗色になる。
★**要素の background は要素の地、中の文書のキャンバスはその上に合成**されるので、
外側から塗っても救えない。

### ★★触ってはいけない（7版ぶんの空振り記録）

- **幕(cloak)・シェードの「消し方」を増やす方向** … 7版やって症状は消えなかった
- **白0.2秒** … Chromium issue 40190899。**直せない。追わない**
  （[[sidepanel-white-flash-is-unfixable-2026-08-10]]）
- 窓0x0 / 幕の残留 / シェードの残留は**全て下流**。第一現象ではない
  （[[stalled-event-loop-masquerades-as-paint-bug-2026-08-12]]）

### ★本筋（未着手）

**iframe をやめて `sidepanel.html` に直接描く。**
影響が大きいので別タスクとして温存してきたが、
**ユーザーの体感が消えていない以上、ここに着手するのが正しい。**

## ★★2026-08-19 追記 — ここで【決着】した（この節が最新）

> **上の「本筋に着手するのが正しい」は、2026-08-19 の実測と会議で覆った。読む順はこの節が先。**

### 何が起きたか（実測・実ブラウザ）

主因は **`changelog.js` が 1,042KB＝popupバンドルの43%** だったこと。
same-origin iframe は親と同一メインスレッドなので、iframe内のJSパースが親を止めていた。

| | 前 | 後 |
|---|---|---|
| popup バンドル | 2,404KB | **1,392KB** |
| 親スレッドの最大停止 | **1,373ms** | **106ms（92%減）** |
| 残る「一瞬の黒」 | — | **平均32ms（1〜3フレーム）** |

### ★結論：32ms は【受け入れる】。iframe 廃止には着手しない

会議（nvidia/nemotron-3-ultra-550b 他4体）で割れたため、司令塔が実コードで裏取りした結果：

1. ★**popup.html を埋めているのは4箇所**（会議は2箇所という前提で設計していた＝前提が誤り）
   `sidepanel-entry.js` / `live-view-entry.js:66` / `content-entry.js:3886` / `status-entry.js:2685`
   → iframe廃止は**4面すべての作り直し**。うち `content-entry.js` は**配信ページに注入される側**＝
   壊すと全ユーザーの視聴中に出る。
2. 32ms は**知覚的現在（約100ms）より短い**。ユーザーの言葉も「一瞬はでますね」であり
   「直せ」ではない。
3. `srcdoc` は **CSP では止まらない**（`frame-src 'self'` は srcdoc を妨げない＝会議の却下理由は誤り）が、
   ★**1.4MBのJSを読む間の停止は同じ**なので黒は消えない。**却下理由が違うだけで却下は正しい。**

### ★判定は【コードに置いた】。文書だけにしない

同じ結論は上の「直せない。追わない」で**既に文書化されていたのに、84版積まれた**
（`git log --all --grep=黒` は92件）。**文書は読まれないことがある。**

→ **正本は [`src/lib/aboutBlankGapVerdict.js`](../../src/lib/aboutBlankGapVerdict.js)**（純関数）。
　 `aboutBlankGapVerdict.test.js` が機械照合する。

```js
judgeAboutBlankGap({ residualMs: 32, approach: 'curtain' })
// → { action: 'reject', reason: '「curtain」は…84版で空振り済み…' }
```

- **色/幕/透明/隠して戻す** の4手口 … `reject`（着手前に止まる）
- **32ms** … `accept`
- ★**96msを超えたら `investigate`** … 仕様では説明がつかない＝**主因の再発**を疑う
  （まず `changelogBundleBudget.test.js` を見る）。**見逃す装置にはしていない。**
- **iframe廃止など構造を変える案は `reject` しない** … 思考停止の装置にしないため

## ★★2026-10-05 追記 — 「残り32msは仕様由来」は誤りだった。v0.1.1561 で黒の窓をゼロにした

> 読む順はこの節が最新。上の 2026-08-19 の「32ms は受け入れる」を覆す。

### ユーザーの言葉(一次情報)
> 「押した瞬間またくろくなってますがそれはなおらない？」→「ではでないようにして」

### 実測(devtools Chrome・OSダーク・sidepanel.html?lv=lv342383970・5回)

| 回 | load(親ms) | 中身の first-paint(親ms) | 見せた時刻 | 黒の窓 |
|---|---|---|---|---|
| 旧(1x cold) | 739 | 1,104 | 764(load) | **約340ms** |
| 旧(1x warm) | 127 | 181 | 128(load) | 53ms(3フレーム) |
| 旧+paint待ち(grace 600) | 192 | 840 | 793(grace) | 47ms |
| 旧+paint待ち(grace 1200) | 165 | 1,393 | 1,366(grace) | 27ms |
| **覆い方式(v0.1.1561)** | 615 | **611** | 805(paint) | **0** |

★決定的な事実: **`opacity:0` の iframe は Chrome が描画を後回しにする。** 中の文書の
first-paint は、見せた(opacity:1 にした)**後**に初めて起きる(見せた 27〜50ms 後＝2〜3フレーム)。
その 2〜3 フレームが「iframe は見えているのに中身が無い＝直前の about:blank の暗いフレーム」。
2026-08-19 に「仕様由来の 32ms(about:blank のキャンバス)」と受け入れたものの正体はこれ。
**隠し方そのものが描画を止めていた**ので、load を待っても paint を待っても、opacity:0 のままでは原理的に消えない。

### 直し方(v0.1.1561・外科的・iframe 構造は変えない)
- `sidepanel.html`: iframe は **隠さない**(opacity 1 のまま)。上に親側の覆い `#nl-ifr-cover`(クリーム色・z-index 2)を置き、
  `iframe.nl-ifr-loading + #nl-ifr-cover` で読み込み中だけ現す。CSS アニメ 1.5s で必ず消える(JS が死んでも)。
- `sidepanel-entry.js`: 見せる合図を **load → 中の文書の first-paint**(同一オリジンなので `cw.performance` の paint entry /
  PerformanceObserver / 毎フレームの直接確認)に変更。load から 600ms の猶予と 1.5s の最終保険は残す。
- 自己診断 `reveal: { reason, loadAt, paintAt, revealAt }` を状態速報の storage に載せた。**黒の窓 = revealAt < paintAt**。
  paint で見せていれば常に revealAt ≥ paintAt。
- 判定モジュール `aboutBlankGapVerdict.js` の関数は変えていない(「色/幕/透明/隠して戻す」が空振りだった記録は事実)。
  ただし「残り 32ms は仕様由来」という前提は本節で訂正した。

### 残っていること(正直に)
- 実機(ユーザーの Chrome・OSダーク・storage 20〜37MB)での確認はこれから。devtools Chrome では 0。
- 白 0.2 秒(Chromium issue 40190899・パネルの入れ物自体)は別物で、これは直せない。
- 覆いが外れるまでの間はクリーム色が見える(実測 load 後 190〜300ms)。黒ではない。
