## ★★★ v0.1.1221 でホバー未表示の真因が判明した（最重要）

**1216〜1220 の修正は全部正しかった。その後段で捨てられていた。**

`enrichUserLaneAggregatesWithProfileAndDisplay`
（[src/lib/userLaneCandidatesFromStorage.js](../../src/lib/userLaneCandidatesFromStorage.js)）が
戻り値を**5キーだけ個別に列挙して**作り直しており、
`recentTexts` / `commentCount` / `giftCount` / `_laneSortAt` を黙って捨てていた。
この戻り値は `STORY_SOURCE_STATE.laneAggregates`（表示の正本）を上書きするため、
欠けたまま会場・レーンの全下流へ流れる。

**症状は3つに見えたが原因は1つ**:

| 消えたキー | 症状 |
|---|---|
| `recentTexts` | ホバーカードの直近発言が空（4回直したのに出なかった） |
| `commentCount` | `venueSeats.js` の `preCount` が 1 に落ち **VIP常連が誰も光らない**（v0.1.734 の退行） |
| `_laneSortAt` | 会場の席順・レーンの並び順の根拠が 0 になる |

**実機でだけ壊れた理由**（ここが教訓）:
`enrich` は「nickname か avatarObserved が**変わった人だけ**」新オブジェクトを作る。
実配信では名前が整う人が多いので壊れるが、**手書き集約を渡す単体テストは
元から余分なキーを持たない**ので永久に緑だった。

対処は spread（`{...agg, 変えるキーだけ上書き}`）。producer にフィールドが増えても無改修で済む。
回帰テスト2件を追加し、**旧実装に戻すと赤になることを確認済み**（欠けたキー名も出る）。

- グリッドの役割は「固定された名簿からの逆引き」。「今来た人に気づく」のは
  応援レーン（直近アクティブ順）とランキングが担う
- DOM が360で完全に頭打ち。1万件・4時間超でも一定

★**批判役の反対意見「新規を知る手段はグリッドだけ」は事実誤認**だった。
  `storyUserLaneGuideHtml.js:82` が「直近アクティブ順」と明示。
  **会議の結論をそのまま採らず、必ず実コードで裏取りすること。**

## このセッションで踏んだ穴（次が同じことをしないために）

### 1. 「値は貯まるのに中継で落ちる」を5回踏んだ

| 落ちた場所 | 版 |
|---|---|
| `touchRoster` が text を保存していない | 1216 |
| `venueSeats` の中継漏れ | 1218（テストで検出） |
| `Object.freeze` の列挙漏れ | 1219（実装中に検出） |
| 鏡（laneMirror）に載せていない | 1220 |
| **`enrich` が5キーだけ書き写す** ← 真因 | 1221 |

**教訓**: 会場のデータ経路は多段で、途中に**オブジェクトを作り直す関数**が複数ある。
そのうち「フィールドを個別に列挙して書き写す」造りは、**列挙し忘れを黙って捨てる**。

- **見つけたら spread に直す**（`{...src, 変えるキーだけ上書き}`）。
  producer にフィールドが増えても中継は無改修で済む形にする
- 新フィールドを足したら**中継関数を全部 grep する**。1箇所直して満足しない
- テストは**本番 producer の出力をそのまま次段に渡す**。手書き fixture は
  「余分なキーが無い」ので落ちを永久に検出できない（5回外した直接の原因）
- 効く断言: `Object.keys(before).filter(k => !(k in after))` が空であること

### 2. 画面の指定を推測で広げた（3回）

「りんく・こん太・たぬ姉が消えてる」の対象を、
(1)レーンの段の人 → (2)段の説明のキャラ → (3)映像に重なるキャラ
と二度取り違え、スクリーンショットで初めて確定した。
さらに「段の説明のキャラ」は**消してはいけなかった**（v0.1.1220 で復活）。

**教訓**: 画面の話は現物を見るまで確定させない。

### 3. 速報の読み違い

「サムネが取れない」を私の変更のせいかと疑ったが、計器が答えを出していた:
```
顔404=13(t:13,e:0)  ← 全部タイムアウト。エラー0件
```
別配信では `failedTimeout:0 / failedError:3 / succeededTotal:7`（7割成功）。
**ネットワーク/CDN 側の問題**で、拡張は正常だった。

## この環境で効いた手順

```bash
npm run verify:cc          # 出荷ゲート一本
npm run copy:ext           # C:\nicolive-ext へ配布
```

- **新規 lib を足したら** `tree-map` と `feature-map` の**両方**を再生成
- **LP を触ったら** `site-health` も再生成（`verify:cc` が赤になる）
- **新規ファイルは `git add` してから** `verify:cc`（`tracked-imports` が赤になる）
- **型定義（`@typedef`）にもフィールドを足す** — typecheck が全箇所を指摘してくれる
- **JSDoc の直前に定数を挿入しない** — 引数の型注釈が分断されて typecheck が赤になる（踏んだ）
- push 後は pre-push フックのビルドで dist の buildId が1つずれる。追わなくてよい
- `git add -A` は使わない

### ユーザーへの反映3手順

1. `git pull`（こちらで実行する）
2. 拡張をリロード（🔄）← **ユーザー操作が必須**
3. watch タブを F5 ← **ユーザー操作が必須**

`copy:ext` まで済ませておけば 2 と 3 だけで反映される。
