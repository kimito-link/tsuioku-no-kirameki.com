## 各版の内容

### v0.1.1216 — ホバーカードに本文を出す（1回目・実機では出ず）

`venueLiveRoster.touchRoster` が `text` の有無だけ見て保存していなかった。

### v0.1.1217 — アイコンの「ちらちら」を根治 ★実機で確認済み

**唯一、実機で効果を確認できた修正。**

真因: `sourceOffset = 全件数 - 360`。上限を超えると**コメント1件ごとに窓が1つ進み、
i番目のマスに毎回別人が入る**。クリックで発言を読む機能はあるのに、
狙った人を掴む前に位置が変わっていた。

対処: 窓を先頭固定（常に0）。最初の360件を「名簿」として凍結。

会議（4体）で上限後の新規の扱いを決定。3体が本案を支持:
- グリッドの役割は「固定された名簿からの逆引き」。「今来た人に気づく」のは
  応援レーン（直近アクティブ順）とランキングが担う
- DOM が360で完全に頭打ち。1万件・4時間超でも一定

★**批判役の反対意見「新規を知る手段はグリッドだけ」は事実誤認**だった。
  `storyUserLaneGuideHtml.js:82` が「直近アクティブ順」と明示。
  **会議の結論をそのまま採らず、必ず実コードで裏取りすること。**

ラベルも「グリッドははじめの360件で固定・そのあとのN件は下の応援レーンに出ます」へ。

### v0.1.1218 — ホバーに直近5件（2回目・実機では出ず）

`recentTextRing.js` を追加。roster に直近N件を持たせた。
★storage を読まないのが核心（クリックパネルは「常時readを増やさない」と明記）。

### v0.1.1219 — 候補集計にも本文（3回目・実機では出ず）

`userLaneCandidatesFromStorage` に `recentTexts` を追加。
★**返す直前に `Object.freeze` でフィールドを個別に列挙し直す造り**で、
  そこに足し忘れると値が黙って消える（実装中に踏んだ）。

### v0.1.1220 — 鏡経路 + キャラ復活（4回目・未確認）

**真因はここ。** 会場は鏡（`laneMirror`）が使えるとき**鏡を優先**する
（`venueBar.js composeVenueBaseRows`）。1218 は roster を、1219 は候補集計を
直したが、どちらも鏡に負けて実機では空のままだった。

鏡セルに `recentTexts` を載せて全経路を繋いだ:
```
①POPのbuckets → buildLaneMirrorSnapshot → venueRowsFromLaneMirror
→ collectVenueParticipants → buildVenueHoverCardModel
```
鏡は容量を優先して**3件**に絞る（純Web公開のサイズを守る）。

あわせて段の説明のキャラアイコンを復活（v0.1.1199/1203 の `display:none` を撤回）。

## この環境で効いた手順

```bash
npm run verify:cc          # 出荷ゲート一本
npm run copy:ext           # C:\nicolive-ext へ配布
```

- **新規 lib を足したら** `tree-map` と `feature-map` の**両方**を再生成
- **LP を触ったら** `site-health` も再生成（`verify:cc` が赤になる）
- **新規ファイルは `git add` してから** `verify:cc`（`tracked-imports` が赤になる）
- **型定義（`@typedef`）にもフィールドを足す** — typecheck が全箇所を指摘してくれる
- **JSDoc の直前に定数を挿入しない** — 引数の型注釈が分断されて typecheck が赤になる（踏んだ）
- push 後は pre-push フックのビルドで dist の buildId が1つずれる。追わなくてよい
- `git add -A` は使わない

### ユーザーへの反映3手順

1. `git pull`（こちらで実行する）
2. 拡張をリロード（🔄）← **ユーザー操作が必須**
3. watch タブを F5 ← **ユーザー操作が必須**
