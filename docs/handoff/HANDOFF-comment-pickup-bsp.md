## なぜ「読み上げから漏れたコメント」が筋が良いか

2026-08-01 の実測で、読み上げは**構造的に全部読めない**ことが確定している:

```
需要31.8/分 vs 供給21.1/分 / 間引き59件 / voiced率67.4% / 判定=playback
```

1件あたり実再生2.5〜3.0秒かかるため、**1分に20件程度が物理的な上限**。
残りは捨てるしかない（捨てないと遅延が積み上がる＝設計上の意図的な選択）。

**この「捨てた59件」こそが埋もれているコメントそのもの。**
視覚で拾えば、読み上げの物理的限界を音以外で補える。
二重に出ない（読んだものは出さない）ので棲み分けも自然。

★実装するなら `voicePlayer` の drop 経路（`_notifyDropped` / `dropCountGateTotal`）から
拾えるはず。ただし**未検証**。
