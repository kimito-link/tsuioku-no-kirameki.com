## 1. 直した症状(真因つき・すべてコードか実測で確定)

### ① レーンのタイルが 24→3 に減る = v1370
**真因**: `shouldSkipLightSupplyOverwrite` が `!rosterLid || cur !== rosterLid` で
**名簿IDが空**を**配信切替**と同一視して守りを外していた。起動直後は名簿がまだ
配信IDを持たないので必ずこの窓を通る(名簿19人に対し供給3件が素通り)。

★これは**同じ型の4件目**。「守るものが無いから通す」が別名で再発し続けていた:
DOM 0枚 → `prev<=0` → `roster-empty` → **`live-switch`**。
→ [[fail-open-recurs-under-new-names-2026-08-12]] / `src/lib/failOpenGuardCensus.test.js`
で**分岐を数で固定**した(名簿ガード5・縮小ガード4)。無自覚に増やせない。

### ② 状態速報が真っ白のまま開かない = v1371
**真因**: init 冒頭の `refreshWebPublishOptInCache`/`refreshUploadConfigCache` が
生の `await chrome.storage.local.get` を**timeout 無し**で待っていた。
storage が詰まると init がそこで止まり、既にあった初回描画にも一生到達しない。
★**このページの他の read は全て有界化済みで、ここだけが非対称に無防備**だった。

★私は最初「初回描画が無い」と誤診断した。実際は v0.1.797 から存在していた。
**症状(白紙)から機能の不在を推定すると外す**。

### ③ パネルの黒 = シェードが12.7秒居座る = v1373
**真因**: 2配信同時記録で storage が飽和 → シェードが待つ「データ」が来ない。
シェードの上限(JS 10秒 / CSS保険 15秒)が**そのまま体感の黒時間を決めていた**。
★ユーザーの別スクショで**同じパネルが正常に描けている**ことが決め手。
「描けない」のではなく**描けるまで待たされている**＝上限を短くするのが正しい直し方。
→ `INLINE_SHADE_DATA_FALLBACK_MS` 10s→**2.5s** / CSS保険 15s→**5s**。

★**storage 飽和(48.8秒)もこれで連鎖が切れて 99ms になった**。飽和は原因でなく結果だった。

### ④ 12.7秒中身が出ていないのに ✅正常 = v1373
合算値(`summarizeContentBlindTime`)を v1370 で作ったのに**判定に配線していなかった**。
→ [[unwired-judgement-is-systemic-2026-08-12]] を私がまた踏んだ。
