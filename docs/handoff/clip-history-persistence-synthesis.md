# クリップボード履歴永続化 — 会議ハーネス素材の統合(司令塔による裏取り済み)

## 会議で出た、司令塔が却下した危険な提案(採用しないこと)

**複数の会議メンバー(groq/gpt-oss-120b, groq/llama-3.3-70b, groq/qwen3-32b)が「検疫(quarantine)方式を廃止すべき」と主張し、互いに同意し合っていた。これは明確に却下する。**

理由: 検疫方式は`_docs/CLIPBOARD-HISTORY-FOLDER-ARCHIVE-DESIGN.md`で設計された、**パスワードマネージャーの自動クリアと連動する安全機構**である。コピーされたテキストが`ClipAutoClearSec+2秒`以内に自動クリアされれば、ディスクに一度も書かれずに破棄される。これにより「KeePass等でコピーしたパスワードが、うっかりディスクに残る」事故を構造的に防いでいる。会議メンバーは「競合状態のリスク」「トランザクション整合性」という実装上の懸念を理由に、この安全機構ごと廃止するよう提案しているが、**パフォーマンスや実装の簡潔さのために安全機構を削るのは本末転倒**。競合状態が心配なら、検疫の実装を堅牢にすべきであって、検疫自体を捨てるべきではない。

**この提案(検疫廃止)はFableへの設計依頼から明確に除外し、「検疫は必ず維持すること」を制約として渡す。**

## 会議で出た、裏取り不要で構造的に妥当な論点

1. **起動時に全件を同期的に一括ロードするのはUIフリーズのリスクがある**という指摘(groq/gpt-oss-120b)は、AutoHotkey v2がシングルスレッドであるという事実に基づいており妥当。ただし対抗意見(groq/qwen3.6-27b)の「直近N件のみメモリロード+オンデマンド読み込み」という設計思想も検討に値する
2. **単一のJSON/SQLiteストアへの統一**という提案は、複数メンバーが独立に到達しているが、これは「検疫を廃止する」という前提とセットで語られていることが多いため、**検疫を維持したまま採用できる部分だけを取り出す**必要がある
3. **既存の`clip-archive`日次テキストログとの関係**をどう整理するか(そのまま残す/新ストアに統合する/廃止する)は、会議では明確な結論が出ていない

## Fableへの申し送り事項

- **検疫(quarantine)方式は絶対に廃止しないこと**。これは会議の複数メンバーが提案したが、パスワード漏洩防止の安全機構を実装都合で削る提案であり、司令塔が明確に却下した。設計はこの制約の中で組み立てること
- 起動時の同期一括ロードによるUIフリーズへの配慮は妥当な懸念として引き継ぐ
- 非永続原則の2度の改定履歴(`CLIBOR-PARITY-JUDGMENT.md`のG節、`CLIPBOARD-HISTORY-FOLDER-ARCHIVE-DESIGN.md`のH節)を踏まえ、今回の変更が「第5のテスト」的な位置づけになるなら、その論理を明示すること
