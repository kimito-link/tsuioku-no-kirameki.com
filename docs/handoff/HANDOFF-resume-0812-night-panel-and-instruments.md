## 1. ★黒画面の真因(確定・新版なしで証明済み)

**ユーザーが送った速報だけで証明できた。**

```
観測格子(sidepanel-entry.js:519)の 0〜12000ms の点数 = 16
速報の「窓0x0」の点数                                = 16   ← 一致
予定12000ms のサンプルの実発火時刻                    = 14574ms
────────────────────────────────────────
イベントループ遅延 = 2,574ms
```

`t` は **実発火時刻**(`Date.now()-_bootAt`・sidepanel-entry.js:304)。
**Chrome のパネル滑り出しではタイマーは遅れない。**
＝**拡張ページのメインスレッドが約2.6秒停止していた**。
`iframe load+50ms` のサンプル(529行)も14778ms＝**iframe load が14.6秒まで未完了**。

背景: 同じ速報の `更新所要7,883ms / 保存3,489件 / lives(stale) 3,301ms`。
拡張の全ページ(sidepanel / popup iframe / status / live-view)は**同一プロセス・同一メインスレッド**。

### ★7版外し続けた理由 = 適用範囲の取り違え

正本メモリ [[sidepanel-black-is-zero-area-window-2026-08-12]] の
「窓0x0＝Chromeの滑り出し＝**版を重ねない**」は**数百msについては今も正しい**。
今回はその上に**別現象が12秒以上乗っていた**。同メモリ自身の但し書き
「窓が面積を持ってからの遅れは詰める価値がある」＝**今回はその『詰める側』**。

### ★会議が訂正した私の誤り(次も踏みやすい)

| 私の主張 | 実際 |
|---|---|
| 「保険がフラグを立てないから refresh が付け直す→15秒」 | **保険は2つある**。バンドル内保険(popup-entry.js:22122)は `revealPopupPrimaryOnce()` を呼ぶ＝フラグを立てる。再付与バグは実在するが**主犯ではない** |
| 「14.5秒は観測分解能かも」 | `t` は実発火時刻。分解能の問題ではない |
| 「CSS(v1376)が原因では」 | 無関係。CSSは窓の面積に影響しない |
