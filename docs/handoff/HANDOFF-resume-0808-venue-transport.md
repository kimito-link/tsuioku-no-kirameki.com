## 2. ★三大トピックの結論

### (A) サイドパネルの一瞬黒 → 根治済み
真因は `popup.html:11` の **`color-scheme: light dark`**。
このアプリは light 固定（v0.1.51）なのに dark も対応と宣言していたため、
OS がダークだと **Chrome のキャンバス既定色が暗色**になり、自前の背景が効くまでの
数十msだけ黒が見えていた。`sidepanel.html:29` は同じ理由で既に `light` だった＝
**入れ物だけ直っていて中身が取り残されていた**（v1283/1285 と同じ構図）。

直し方は `<html>` の**インライン style 属性**。`<style>` ブロックでは**間に合わない**
（実測で `colorScheme==='normal'` の窓があった）。CSP が禁じるのは script であって
style 属性ではない。

**計器**: `tests/e2e/sidepanel-flash-capture.spec.js`（rAFごとに塗り状態を記録）
実測 143フレーム🔴 → 0 ✅。会場も同じ計器に載せた（会場の黒 #0a0b0c は
**OBS 用の意図的な仕様**なので「塗り忘れの透明」だけを異常と判定する）。

### (B) 会場に全部載らない → ★誤報だった（真因ではなかった）
状態速報の🔴「供給26件 → 画面0件」を信じて `popup-entry.js:6822` の
数値IDガードを真因と疑ったが、**外れ**。同じ報告に **鏡149件・会場152席** があり、
broadcasterUid が空ならそれらも空になるはず＝ガードは発火していない。
実態は **popup 起動283ms・幕が出たまま・heavyEverSettled=false** で
まだ読み切っていないだけだった。

→ 診断側を直した（v1290）: `verdict='settling'`（⏳）を新設し、
  **暫定paintのみ・確定paint0回**なら🔴にせず対処カードも出さない。
  確定paintが一度でもあって0件なら**従来どおり🔴**（検出力は維持）。

### (C) 会場へ運ぶ演出 → 実装済み（未マージ）
**サイドパネル側（画面右端）から新規入場者のアイコンが弧を描いて席へ飛び、
着弾で席がふくらむ。** 既存の `nlsb-gift-fly`（ギフト投擲）と同じ作法。

- 正本ロジック: `src/lib/venueEntryQueue.js`（DOM無し・純ロジック）
- SPEC: `docs/handoff/venue-transport-effect-SPEC-2026-08-08.md`
- **設計の肝**: `fly + seat + queue` を足すと必ず新規全員＝
  **上限は演出にだけ掛け、人は消さない**（v0.1.1232「上限こそが消失の実行者」）
- **この演出は計器でもある**: 入場をイベント化すると「飛んでこない＝載っていない」が
  目視で分かる。だから reduced-motion でも**消さない**（`nlsb-entry-fade`）

実配信規模（152人）で確認済み:
| 場面 | fly | seat | queue |
|---|---|---|---|
| 会場を開く(152人) | 0 | 152 | 0 |
| 1人来た | 1 | 0 | 0 |
| 40人が一気に | 5 | 16 | 19（計40＝誰も消えない） |
| 配信切替 | 0 | 2 | 0 |
