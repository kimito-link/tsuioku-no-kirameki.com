1 — 結論（Verdict）

数値カードは速報経路で改善済み。体感「読み込みが長い／スクロールしても中身が出ない」は別レイヤーが残っている

計画どおり A（幕）/ B（ランキング・レーン）/ C（スクロール取り込み） に分解すると、現行コードでは P0〜P2 の多くが既に入っている。一方で「記録 1万件級なのにリストが薄い」「スクロール中はランキングが更新されない」は、設計上の上限と見送り窓として残っており、バグというよりトレードオフの見え方問題になりやすい。

速報（A寄り）

良好

幕は記録数値で解除。トリオカードは panel metrics / summary 経路。

中身（B）

部分残存

暫定ランキングは直近30件上限。heavy 完了前は件数とリストが一致しない。

スクロール（C）

意図的遅延

visible 400ms / deep 1500ms。静止後再試行あり。フリーズ回避とのトレードオフ。

4 — 残存リスク（コードで裏取り済み）

P0 体感 — 「件数 11,092 なのにランキングがスカスカ」

因果: 暫定フィードの材料は SUMMARY_RECENT_ROWS_MAX = 30。heavy 未完了時は最大でも直近30コメント分のユーザーしか集計できない。記録カードの正本は summary total（万件）なので、数字とリストのギャップは構造的。

src/lib/commentSummary.js:26 / provisionalLaneCommentRows.js

さらに: merged.length <= primary.length のとき provisional:false になる穴があり、popup 側は !watchPopupHeavyCommentsSettled を OR して story 側を守っている（コメント 16184–16188）。UI 注記「暫定ランキングです」は laneFeedPick.provisional だけを見るため、heavy 未完了でも注記が出ないケースがあり得る。

P1 — スクロール中に「中身が増えない／ランキングが動かない」

content（取り込み）

  • visible scan 見送り窓 400ms
  • deep harvest 見送り 1500ms
  • 静止後に再試行（再スケジュールあり）
  • 一次取得は NDGR。手動スクロール過去読みは DOM 経路依存

popup（表示）

  • パネル内スクロール 400ms は renderUserRooms 自体を見送り
  • 既に描画済みなら次 refresh（最大数秒）までリスト更新なし
  • 「スクロールしても出ない」＝取り込み遅延＋描画見送りの二重

フリーズ（応答しません）回避のための意図的設計。退行させずに体感だけ改善するなら「見送り中 UI 明示」が安全。

P1 — heavy race（重い配信でレーンが途中件数のまま）

changelog（0.1.1033 前後）で実機確認済みの系統: 全件 read が終わる前に次 refresh が追い越し、heavySettled が立たずレーンが暫定のまま固まる。現行は「直前全件が総数の8割以上なら再利用」等で緩和済みだが、多タブ＋万件＋backfill 同時では再発余地あり。

popup-entry.js heavyDataPromise / watchPopupHeavyCommentsSettled / story provisional OR

P2 — ランキング集計の cap（2500）

renderUserRooms は capCommentsForAnalytics で均等サンプル 2500 件に落とす。1万件級では完全なユーザー別件数ランキングではない（負荷対策）。件数カードの正本とは別物。

  • eventDom 汚染 / staleDomBundleSuspected
  • 北極星 koken iframe マウント不全 Epic
  • Git / PR 整理
