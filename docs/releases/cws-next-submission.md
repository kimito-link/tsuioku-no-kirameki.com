## 1. 結論

- **manifest の権限・ホスト権限・content_scripts は 0.1.1728 と同じ**（変わったのは version だけ）。
  更新時に「新しい権限の確認」でユーザーの拡張が止まることはない。

  サーバー送信を ON にできる**。さらに **スマホの読み上げ（音声がサーバー経由）** と
  **スマホからコメント（サーバー経由で受けた本文を PC が投稿）** が加わった。
  → 審査で見られるのはここ。ダッシュボードの「単一用途」「権限の理由（app.tsuioku-no-kirameki.com・VOICEVOX）」を
  **今回の版に合わせて貼り直す必要がある**（前回と同じ文面のままだと実態と食い違う）。
- クラウドで master から提出用 ZIP を試し生成済み: **0.1.1747・137 ファイル・16,467,534 bytes**。
  `verify_no_secrets` 合格・同梱 JS に `eval` / `new Function` なし・外部スクリプトの読み込みなし。

## 3. 審査で気をつける点

1. **サーバーへの送信が「誰でも ON にできる」機能になった**
   - 文面上の約束: 既定 OFF・利用者が自分で ON・最新1件を24時間・OFF で削除・氏名やアカウント情報は使わない。
   - `privacy.html`（2026-10-22 更新済み・§4-3）、`cws-submission-texts.md` §1・§2-8d、ストア掲載文は、この約束でそろえてある。
   - ★**ライブの privacy.html が最新になっているか**を提出前に必ず確認する（審査員が見るのはライブ URL）。
2. **「スマホからコメントする」= サーバーから届いた本文を PC の拡張がニコ生に投稿する**
   - 一番説明が要る機能。遠隔操作と読まれないよう、「利用者本人が ON・本人専用 URL・本人のブラウザのログインで投稿・ログイン情報は預からない・本文は最長1分で消える」を §1 と §2-8d に明記した。
   - 届くのはコメント本文と lv 番号だけ（コードではない）なので「リモートコード」には当たらない。リモートコード宣言は従来どおり「使用していない」。
3. **VOICEVOX の理由文の旧記述が嘘になっていた**
   - 旧: 「コメント本文や個人情報が外部サーバーへ送信されることは一切ありません」→ スマホ読み上げで音声が外へ出るので不正確。
     §2-8c とストア掲載文を「スマホで聞く機能を自分で ON にしたときだけ届ける」に直した。
4. **データ使用の申告**は従来のチェック（個人を特定できる情報・ユーザーのアクティビティ・ウェブサイトのコンテンツ）で足りる見込み。
   スマホからのコメントは公開放送への投稿なので「個人的コミュニケーション」には当たらない、という整理を維持。
