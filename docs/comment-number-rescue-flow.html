フェーズ0：前提（この症状を直したい）

会場・応援レーンに人が出ない

コメントは大量に取れるのに、会場の席／応援アイコン列に人が並ばない。userId が乗らない行は席に出せない（venueParticipantKey が null）。

フェーズ1：当初の仮説（★着手前の前提）

⚙️ 仮説：番号セルが消えた

「現行ニコ生がコメント行から .comment-number を外した → parseNicoLiveTableRow が番号必須で DOM 観測を全捨て → visible:0」。緩めれば直る、という読み。

↓この前提が真でないと、以降の実装は無駄になる
フェーズ2：第1コミット（安全な土台・挙動不変）

✅ 受理門を純関数に正本化 v0.1.820

番号必須が3箇所に散在 → isHarvestableNicoCommentRow 1つに集約（ドリフト防止）。requireNumber:true 既定で従来と完全同値。既存テスト65本が緑のまま＝等価性を担保。挙動不変なので安全。

↓緩和（第2）の前に、前提を実機で必ず確かめる
フェーズ3：実機DOM答え合わせ（★最重要ゲート）

🟥 前提が覆った（2026-06-18・Claude-in-Chrome）

配信中 watch（ニコニコ実況・匿名主体）の実 DOM を検証：
① 番号セルは消えていない（12行すべてに存在・droppedNoNumber:0＝現行ゲートは1行も落とさない）。
② 匿名はDOMにuserIdが無い（React fiber 70連鎖walk でも hashedUserId 等ゼロ）。番号を緩めても席に出せない。

↓前提否定 → 緩和は利得ゼロ・働くガードを弱めるだけ
フェーズ4：判断（第2は凍結 / 真の経路へ）

❄️ 第2コミット：凍結

番号緩和は観測された問題を解決しない。再開条件＝ユーザー自身の配信で実際に番号無し行（noNumberRowCount>0）が観測された場合のみ。第1（正本化・挙動不変）は維持。

⚙️ 真の経路（次の伸びしろ）

匿名 userId（hashedUserId）は NDGR(protobuf)にしか無い（v0.1.803 で取得済）。「会場/レーンに人が出ない」の本筋は NDGR の匿名 userId をレーン/席に確実に通すこと（lane-empty-uid-missing 系）。
