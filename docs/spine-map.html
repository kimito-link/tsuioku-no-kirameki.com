🦴 コードの背骨マップ（データの一生）

取得→記録→集計→表示の背骨1本。網羅でなく根幹だけ。線（🩸=storageキー＝血管）が つながっているかを見れば、値が作られても届かない「断線」（過去の broadcaster バグ型）に気づける。
scripts/feature-map.mjs が実コードから自動生成（手編集しない・no CDN・依存ゼロ）。 テキスト正本: spine-map.md ／ 全地図の入口: MAP.md ／ 全storageキー: storage-bus.md。

✅ 背骨の血管はすべて producer/consumer 両側がつながっています。

読み方: 上から下へデータが流れる。各カード＝1つの段（節）。カード内の🩸＝その段から次の段へ データを渡す storage キー（血管）。
緑の血管＝書く人(producer)も読む人(consumer)も居る＝つながっている。 赤の血管＝片側しか居ない＝断線の疑い（値は作られたが届かない／その逆）。
節ファイルが消失すると赤枠＋(消失)。npm run feature-map -- --check が verify:cc で これを検知して落とす（地図が腐らない）。
