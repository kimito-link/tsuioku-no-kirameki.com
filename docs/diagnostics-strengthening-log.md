### この改造で診断がどう強くなったか

1. **保存しなくても中身が見える**（v0.1.858）
   レポートが使う純関数（`aggregateMarketingReport` / `analyzeAudienceEngagementGap`）を再利用し、
   主要KPI（本文数/コメントした人/分速/ヘビー・一度きり%/来場/沈黙視聴者）を `popup→storage→status`
   ブリッジで速報に表示。DL前に解像度が上がる＝過小集計などをその場で発見できる。

2. **診断が自分の矛盾に気づく**（v0.1.859 = self-verifying の核）
   `detectNumberInconsistencies` が status 自身の出した数字どうしを照合し、論理的に不可能/桁違いだけ⚠に出す:
   - コメントした人 > 来場（不可能）
   - のべ別キー > 本文コメント数（不可能）
   - レポート本文 < 記録総数の半分（過小集計＝v0.1.853 型断線の早期検知）
   - 記録 > 公式の130%超（別配信混入/二重計上の疑い）
   → 人が目で照合しなくても食い違いを自動で掴む。実際このセッションの実機速報で見つかった
   「ユニーク127 vs コメントした人26」を機に作った。

3. **二枚舌の解消**（v0.1.859）
   速報プレビューが過大な `uniqueUsers`（匿名を1件ずつ別人カウント）を出していたのを、HTMLレポート本体と
   同じ正本 `gap.uniqueCommenters`（実人数）に統一。本体と速報の数字が一致する。

4. **嘘の赤・既知0の正直化**（v0.1.860 = 実機速報が新機能を試した最初の成果）
   v0.1.859 を入れた直後の実機速報で2つの自己矛盾が見つかり、裏取りして修正:
   - 健全度パネル「userId付き保存」が匿名主体（withUid 6%）で🔴。だが対処カードは同じ事象を⚪（仕様）。
     → NDGR connected で低率は匿名主体＝構造的に正常 → `na`（該当外）。NDGR 切断の本物の異常だけ赤。
   - 公式値レーン「番組pt」が `state:ok / ndgrValue:0 / value:null` で「空」表示。0pt は取れていて0であって
     未取得ではない。→ 既知0は `✅0`、真に null の時だけ「空」（State Conflation の解消・v0.1.851 と同型）。

### 設計メモ（再発防止）

- **storage ブリッジが別ページ間連携の確立パターン**: status は本文配列を持たない→コメントを持つ popup が
  throttle publish→status が読む（voiceDiag/perfDiag/reportPreview すべて同型）。
- **feature-map の storage 断線ゲート**は `chrome.storage.local.set` を静的 grep で producer 検出。
  optional-chaining（`?.set`）だと取りこぼす→素の `chrome.storage.local.set` を guard 付きで使う。
- **max-lines ラチェット**（popup-entry 21025）に当たったら producer 本体を新規モジュールへ抽出し、
  entry 側は最小フック（import＋呼び出し）に。
- **診断値が0/空/食い違うとき**は「数える側」でなく「返す側（producer）」と「意味の定義」を実コードで確認。
  marketing と gap の「ユニーク」は意味が違った（過大 vs 実人数）＝バグでなく定義差。
