# 前提の賞味期限 — AIが「知識不足」ではなく「確かめない」で迷路に入る型

> ★症状: AIが自信を持って「これは無い」「これは危険」「これは緑（安全）」と言う。
> ★だが根拠が **古い** か、**自分で作った物** か、**探した場所が違う**。エラーは1つも出ない。
> ★だから気づくのは、実装した後か、人間に指摘されたときだけ。

★このKBは `ai-hub/kb/external-decision-surface-governance.md` の掟
「1件の発見を一般ルールにせず、**独立事例・反例・適用範囲・鮮度**を記録する」に従う。

---

## 1. 真因（1文）

> **AIが迷路に入るのは知識が足りないからではなく、手持ちの前提の「賞味期限」と「出処」を
> 確かめる工程が無いから。だから知見を足すほど、古い前提の在庫が増えて迷路は深くなる。**

★「作る前に探せ」では**説明できない事例が3つある**（下表 #3 #5 #6）。
　共通項は「探さなかった」ではなく「**確かめなかった**」。確かめる対象は既存コードとは限らない。

## 4. ★反例（適用範囲＝これは効かない場面）

> ★**記録がスクリプトのコメントの中にしか無かったため、2回目も一から調査した。**
> ★**それがこの項目を作った理由。3回目をやらないこと。**

`web-ios-android/_docs/shared-parts-duplication-knowledge-base.md`:

## 6. ★次に同じ型を踏まないための実務

★制度を増やさない（反例2・3のとおり効かない）。**確かめる対象を変える**だけ。

1. **「無い」と言う前に**: 探した場所を1つ言う。★#7 は探索範囲を言わずに「無い」と断じた
2. **基準を持ち出す前に**: その基準が**いつのものか**を言う。言えないなら基準として使わない
3. **「緑だから安全」の前に**: その緑を**誰が塗ったか**を言う。★#5b は自分の生成コードが塗っていた
4. **ルールを書き足す前に**: 同じ内容が既に何箇所にあるか数える。★3箇所あるなら4箇所目は効かない
5. **正本を直したら**: それを**指している側**（ai-hub の summary・handoff・README）も直す（§3）
