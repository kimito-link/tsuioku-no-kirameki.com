## 4. ★キットに効きそうな形（提案・押し付けません）

キットは「提出までを自動化」する立場なので、**門番（ゲート）を持つ文化**があります。
その流儀に合わせるなら、知見は**文章ではなく検査**にした方が効きます。

★参考: `soushin-suggest.link` の SS-12 は既に**そうしています** —
「症状の修正を実測ログ無しで配ろうとすると **build.ps1 が止める**」
「★ただし普通のビルド（機能追加・文言修正）は止めない
　— **全部を止めると通すためだけの空のログが置かれる**ため」

★この「全部は止めない」という但し書きが重要だと思います。
　追憶でも、止めすぎた検査は**やがて消される**という記録があります
　（`laneDensityLod.wiring.test.js:103-109`「CRLFで空振りして**死んだ検査**だった」）。

**候補（キット側で判断してください）**:
- 「新しい機能を足す」系のPRで、**同義の既存実装を grep した形跡**を要求する
- ★ただし**全PRを止めない**。新規追加のときだけ。

## 5. ★なぜキットではなく ai-hub に置くべきか

キット自身が `CLAUDE.md:9` で宣言しています:

> **横断知見の正本は常に `../ai-hub`。このリポは ai-hub を動かさず窓口を被せるだけ**

★横断知見をキットに直接書くと「正本が2つ」になります。
　これは**追憶がこのセッションで何度も踏んだ型**そのものです:
- `LANE_CSS_SYNC` … 同じレーンCSSが**3ファイル**にコピーされ、★**機械が値を照合していなかった**
- 匿名NNN … 採番の実装が**2本**あり、同じ人が画面によって**別番号**になっていた
  （実測: 会場「匿名890」/ コメビュ「匿名644」→ v0.1.1495 で正本1本に統合）

⟹ ★**同じ轍をリポ間で再生産しないため**、正本は `ai-hub` に置くのが筋です。
　　キットの `site/hub/` が `ai-hub/index.json` を読むので、**そこに入れれば窓口には出ます**。
