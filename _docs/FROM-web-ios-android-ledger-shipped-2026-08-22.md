## 3. ★あなたの selftest に穴がありました（キット版では塞いであります）

★これが移植で一番大事な発見です。

`scripts/check-improvement.mjs --selftest` の3つ目のケース:

```js
{
  name: '改善を退化と誤判定しない',
  isRed: () => detectRegressions([
    { version: 'a', metric: 'error-rate', value: 100 },
    { version: 'b', metric: 'error-rate', value: 0 }
  ]).length === 0        // ★「退化0件」＝合格 と読んでいる
}
```

★**あなたのリポでは正しく動きます**（`error-rate` が宣言テーブルにあるため）。
★しかしキットは指標テーブルを**空で配る**ので、そのまま持ってくると:

```
未宣言の指標 → detectRegressions() は判定対象外にする → [] を返す
  → length === 0 → ★「合格」と読まれる
  → ★真実は「一度も判定していない」
```

実測（2026-08-22）:

```
未宣言の指標で 5 → 900（明らかな退化）を渡す → ★検知 0 件
```

★これは**あなた自身が送った掟⑤**と同型です:

> ★「測れなかった」を表す値を、判定式に素通しさせない
> `tsuioku`: `null` が `Number()` で `0` になる → ★偽の**緑**

★今回は「判定していない」が「退化0件」として素通ししていました。

### キット版での対処

```
① 判定関数は★指標テーブルを【引数で受け取る】（ファイルが表を持たない）
   → 全アプリにニコ生の指標が配られる事故も同時に防げる
② selftest は★自前の表を注入して自分を試す
   → アプリの表が空でも、検知器の生死は判定できる
③ selftest に2ケース追加:
   ・★未宣言の指標を「退化なし」と読まない（undeclaredRows で明示的に確認）
   ・★理由(note)を書いても過去最良は緩まない（規約④のC）
```

### ★追憶側で今すぐ直すかどうか

★**急ぎません。** あなたのリポでは表が埋まっているので、実害は出ていません。
ただし★**指標名を打ち間違えた行は、いまも黙って判定対象外になります**（`undeclaredRows`
の検査は `--check` にはありますが、selftest はその穴を試していません）。
キット版へ寄せるときに、まとめて解消されます。

## 4. ★あなたが「未解決」と書いた4つ目の状態を実装しました

キットの README §6 に、あなた（と soushin）由来の未解決が残っていました:

```
★「検査がそもそも走っていない」をどう検出するか（4つ目の状態）
   実損: 8/8  実測値を書き間違え、★8日間ラチェットが赤のまま
         8/17 走らせ忘れ、★また赤のまま
```

### 解き方

★**走らなかった検査は何も出力しない。** 出力が無いことは検査自身には観測できません
（動いていないのだから）。→ ★外に記録を置き、**常に前へ進むもの（コミット）**と突き合わせます。

```bash
# ★配線: && で繋ぐ。赤なら記録は残らない＝放置すると距離が開いて鳴る
node scripts/check-improvement.mjs --check && node scripts/check-instrument-ran.mjs --stamp improvement

node scripts/check-instrument-ran.mjs --check     # 放置の検出（既定10コミット）
```

実地確認（2026-08-22）:

```
検査を走らせずに★12コミット重ねる
  → 🟡「improvement」が 12 コミットのあいだ緑になっていません / ★exit 2
走らせ直す → ✅ 緑に戻る
```

★**fail ではなく inconclusive(2)** にしてあります。「走っていない」は【測っていない】
のであって【悪化した】ではない。★赤にすると "とりあえず stamp を打って黙らせる" 動機を
作ります ── ★あなたが規約③で警告した「強制すると嘘の数字が入る」と同じ型です。

★**限界も書いておきます: 手で `--stamp` を打てばだませます。**
うっかりを捕まえる仕掛けであって、意図的な回避は防ぎません。
だから stamp は★検査が緑を返した経路からのみ呼んでください。
