# reference: ライブ会場モード 設計正本(全員集合会議 2026-06-13)

> Fable風司令塔 + 全員集合会議(gpt-oss:20b / deepseek-r1:14b / Codex gpt-5.5)で確定。
> Gemini CLI は認証切れ(exit55)で離脱。ユーザー裁定済み。

## ユーザー要望(原文の意図)
SHOWROOM のような「ライブ会場」感。ただしSHOWROOMはアバターが配信画面に重なって
ごちゃごちゃ→それを避けて整理。ボタンで会場モードに切替、視聴者がアバターで並ぶ、
発言したら吹き出し、サイズ/レイアウトをちゃんと、配置は「配信画面のすぐ下」。

## 会議結論(全員一致 + 司令塔裁定)

### 論点1: C案(ハイブリッド)— 全員一致
ニコ生ページには控えめな「会場モード」ボタンだけ注入。本家DOMにはぶら下げない。
**司令塔裁定(Codex「別窓」案 vs オーバーレイ案の割れを解消)+ユーザー確定:**
押すと **`position:fixed` で画面下端に固定した独自レイヤー「会場バー」をスライドイン**。
- ニコ生のReact再描画と無関係(fixedで被せるだけ・本家不変)= CWS審査リスクも回避
- 「映像のすぐ下」でなく「画面下端=映像を見ながら視界の下に会場」= SHOWROOM体験に近い
- OBS用途には comeview 別窓モードを別PRで残す(将来)

### 論点2: ハイブリッド50席・入れ替え制 — ユーザー確定
- 最大50席(既存 comeviewRows の50件capに整合)
- 前列~20人はB案canvasアバター(v0.1.704・**ユーザー単位でキャッシュ必須**=発言集中で重くなる)
- 残りは軽量カラーアイコン(色生成)
- 超過時はスクロールでなく**入れ替え制**(DOMを増やし続けない=軽さの肝)
- 優先順位: 直近発言者 > ギフト参加者
- ⚠️**呼称は「会場参加者」**(Codex指摘): 無言の視聴者一覧はNDGRで取得不可。
  取れるのは発言者・ギフト参加者だけ。「視聴者」と書くと誤認させる。

### 論点3: 頭上吹き出し + ログ併記 — 会議一致
- 吹き出しは頭上に約4秒・同時表示最大6個・1人につき最新1件へ更新(連投で増やさない)
- 長文は省略表示・全文は既存コメビュログ(comeview)で読める
- 重なり回避は **danmakuLaneScheduler.js を流用**(既存土台の初配線)
- 下部にログ併記(見逃し防止 + 会場感の両立)

## Codex が出した「見落としリスク」(全採用)
1. 無言視聴者は取れない→「会場参加者」表記
2. 匿名IDの放送内安定性・再接続時の同一人物判定を確認(name空が普通=NDGR仕様)
3. canvasアバターはユーザー単位キャッシュ必須(発言集中で重くなる)
4. 連投/同文/削除/NG/追っかけ再生コメントを吹き出し対象から整理
5. 別窓自動配置は画面サイズ/拡大率/マルチモニタで映像直下を厳密保証できない
   → だから画面下端fixedバーにした(裁定根拠)
6. 情報セット原則: 座席詳細にサムネ/ID/ハンドル/リンクをまとめる

## gpt-oss の追加リスク(採用)
- CSS競合: 名前空間クラス `nlsb-` で隔離(ニコ生CSSの上書き対策)
- リロード時の状態保存
- OBSスケーリング: ResizeObserver で自動再調整(別窓モード時)

## 設計原則の遵守
- 本家を変えない(fixedレイヤーのみ・DOMぶら下げ禁止)
- 入口は普段見る画面(ニコ生watchページにボタン)
- 読みやすさ優先(PR1は席表示だけ・演出は段階的)
- 名前空間 `nlsb-` でCSS隔離
