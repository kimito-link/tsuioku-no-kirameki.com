## 司令塔による裏取り（2026-09-16）

### ★真因: 会議が**間違ったCloudflareトークン**を読んでいた（CF勢6体が毎回401）

日報の失敗率（nemotron 34% / cloudflare 29%）を追って会議記録の失敗文言を読んだところ、
`cloudflare/gpt-oss-20b` が **9件すべて HTTP 401 Authentication error** だった。

**誤診しかけた点**: トークンは `/user/tokens/verify` で **active**、ゾーン一覧も200。
「生きている」ように見える。だが機能別に叩くと差が出た:

| 機能 | 結果 |
|---|---|
| ゾーン一覧 | **200** |
| アカウント情報 | 403 |
| Workers AI モデル一覧 | 403 |
| **Workers AI 実行** | **401** |

＝記録済みの「**Cloudflareの権限は機能ごとに独立・見えている≠使える**」型。

**そして真因は権限不足ではなかった。** 環境変数を調べると **`CF_WORKERS_AI_TOKEN` が既に存在**し、
これで叩くと **200（931ms）**。`web-ios-android/docs/ai-workflows/MULTI-BRAIN-HOWTO.md` が
「権限はWorkers AIだけ」として既に規約化していた。
**会議側が古い変数名 `CLOUDFLARE_API_TOKEN`（ゾーンDNS用）を読み続けていただけ**で、
ダッシュボード作業もトークン再発行も不要だった。

修正（3箇所・旧名はフォールバックに残して他環境を壊さない）:
`council-lineup.mjs` の `ENV_NAMES.CF` / `meeting.mjs` の `CF` / `scout-models.mjs` の `CF`。

**効果（実測）**: `council-env.mjs` が `CF_WORKERS_AI_TOKEN 6体が使用` を認識 →
実会議で `cloudflare/gpt-oss-20b` が **401 → ok** に復活・**6/6成功**・events空。
日報のCF勢6体の警告も全消滅。

### ★あわせて修理: 認証エラーが初日に警告されなかった

CF勢6体はscoutが検知していた（health記録6件）が、**streak=1のため日報に1体も出なかった**
（警告は2日連続が条件）。401は**待っても直らない**種類なので、
08-31に課金要求(402/403)を即警告にしたのと同じ理屈で**401も初回で即警告**に変更した。

検証: CF勢のhealthを0に戻して再実行 → **6体すべてに初回から警告**が出た
（「認証エラー(キー/権限の問題・人が直すまで回復しない)」と原因も明記）。
429の容量枯渇は従来どおり2日連続を待つ（待てば戻るため）。
