## 司令塔による裏取り（2026-08-31）

### ★最重要: mistral-large が無料枠から外れて死んでいた（日報は無警告だった）

```
HTTP 403 "This model is not available in your subscription tier"
type: tier_not_allowed / code 1910
```

- カタログ(/v1/models)には**在籍したまま**
- 同キーで `magistral-small` / `codestral` は **200** ＝キーの問題ではない
- `mistral-large-2512` も同じ403 ＝ large系が丸ごと無料枠から外れた

＝「カタログに残ったまま**課金要求で死ぬ**」型（cloudflare/glm-5.2の有料化と同一）。
**SambaNovaの429(容量枯渇)とは別物なので撤去する。**

### 放置すると危なかった理由: leadの頭脳が1種類に落ちていた

lead役は `nvidia/nemotron-3-ultra-550b` と `openrouter` 版が**同一モデルの2経路**。
mistral-largeが死ぬと**実質の頭脳が1種類**になる。統括役が単一モデル依存だと、
同じ誤り方をしても誰も気づけない。

**後継に `magistral-medium-latest` を採用**（roleOfに `magistral-medium`→lead を追加）:

| 検証 | 結果 |
|---|---|
| 2並列(本番経路) | 200 / 2338ms・2638ms |
| 統括プロンプト | 200 / 1924ms・統合と異論を指示どおり出力 |
| lead頭脳の種類 | **1種類 → 2種類に回復** |

不採用: `mistral-medium-latest` は200だが roleOf 上 generalist で lead の穴を埋めない。

**実装時の地雷**: `magistral-medium`→lead を `magistral`→critic **より後ろ**に書いたら
永久に効かなかった（ifは先勝ち）。実行検証で気づいて前に移動。`magistral-small` を
critic に残すため `"magistral"` ではなく `"magistral-medium"` で判定する。

### ★scoutの「有料化検知」は導入以来ずっと死んでいた（同時に修理）

なぜ403の日に日報が無警告だったのかを追った結果、**2つの欠陥**が見つかった。

1. **snippetが常に空だった** — `probeModel` は `choices[0].message.content` だけを見るが、
   非200では `choices` が無い。よって**エラー本文が一切入らず**、「有料化疑い」の
   文字列判定(`paid plan`等)は**導入以来一度も発火し得なかった**＝死んだ判定。
2. **`streak>=2` 一律だった** — 課金要求は**待っても戻らない**のに、2日連続を待っていた。

修正: 失敗時はプロバイダ別にエラー本文を拾う(`error.message` / `message` / `errors[].message`)。
課金要求(402 / `tier_not_allowed` / `subscription tier` / `paid plan` / `workers free plan`)は
**初回で即警告**。429の容量枯渇は従来どおり2日連続を待つ（待てば戻るため）。

検証: 死んだmistral-largeを一時的に戻して streak=0 から再実行 →
**「実疎通1日連続失敗（有料化(無料枠から外れた)）応答: This model is not available in your subscription tier」**
が初回で出た。副次的にSambaNovaの応答欄にも "Rate limit exceeded" が出るようになった（従来は空欄）。
