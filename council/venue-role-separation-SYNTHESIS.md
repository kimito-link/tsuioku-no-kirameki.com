# SYNTHESIS: 会場を「作る人/見せる人」分離設計に沿わせるか + popup要素をそのまま運ぶか

会議 2026-07-01 / design カテゴリ / routed 4体(qwen3-32b 批判, gemma4:latest 総合統括×2, llama-3.3-70b 爆速, gpt-oss-120b 批判)。司令塔が実コード裏取りの上で集約。**5体ほぼ完全一致**の珍しい収束。

## 収束した結論(全体一致)

### 問い2「popup のアイコン列・グリッド・診断をそのまま運ぶか」→ **運ばない(C案)**
- **理由(全体一致)**: popup は「数値ID+サムネ揃いだけ上段・匿名(a:)は下段へ流す」UI 契約。会場は「匿名も全員主役」(venueParticipantKey が userId あれば匿名も着席)。**匿名の扱いが正反対**で、そのまま運ぶと会場の「全員主役」が壊れる。実機868人は匿名90%超=上段に数値IDが密集し匿名が埋もれる現象を再現する。
- gemma(統括): 「Popup 固有ロジック(匿名除外)を会場に持ってくるのは設計思想の衝突。今回は完全に切り捨てる(C)」。
- ⭐ **司令塔の答え(ユーザー質問1へ)**: **「そのまま運ぶ」はダメ。会場は別目的(全参加者の全体像)なので、popup グリッドの丸呑みはしない。**

### 問い1「記事の分離設計に作り替えるべきか」→ **完全分離は過剰。だが計算のオフロードは必須**
- **完全分離(会場は貼るだけ)は不可能で過剰**(全体一致): 会場はリアルタイム描画ループ(renderSeats が毎フレーム席割り・アニメ・吹き出し追従)。静的「貼るだけ」を無理に当てると、時間変化する要素(席占有・バッジ)が退化する。
- **だが「重い集計を hot path から外す」役割分担は必須**: renderSeats 内の全件走査(順位/アバター解決率)を毎フレームやると記事の①「開いた瞬間に重い」を会場で再現する。
- ⭐ **司令塔の答え(ユーザー質問2へ)**: **記事の分離思想は"部分的にしか"入っていない。会場は「集計は1回→鏡→貼る」の役割分担を強めるべきだが、SW への大移設は今はやらない(過剰・退化リスク)。**

### 問い3/4「見せる側の集計をどこまで許すか・最小の落とし所」→ 変化検出スキップを最優先
- 全体一致の最小対策=**「1回計算 → 前回ハッシュ(sig)比較 → 無変化ならスキップ → 3秒 min-gap」**。これは私が Phase 3 で既に入れた方式(venueDiagSig)。会場全体の renderSeats にも sig スキップを広げるのが最現実的。
- 鏡を storage に増やすのは**最小限**(座席+順位程度)。gemma/gpt-oss は「SW/content が定期集計→鏡1枚→会場は storage.onChanged で貼る」を理想に挙げるが、qwen 批判=「席割り済み配列の storage 書込みは"記録本体不可侵"に触れうる・onChanged 頻発が逆に重い」。→ **今は storage 鏡を増やさず、sig スキップで hot path を守る**に留める。

### 問い(可視性)は分離とは別問題 → UI 改善で解く(全体一致)
- 「868人で上位が見えない・金オーラを消した」は**設計(分離)とは別レイヤ**。バッジ拡大/静的オーラ復活/上部トップNバーで解く。gemma フェーズ2・gpt-oss・qwen が口を揃える。

## やってはいけない(批判役の穴・全体一致)
1. popup の匿名除外を会場へ持ち込み「全員主役」を壊す(最重要)。
2. 記録の心臓部(記録 SW)に会場専用集計を足して太らせる(記録本体不可侵)。
3. 席割り済み配列を storage に書いて書込みを増やす/onChanged 頻発で逆に重い。
4. 分離のために大改修して既存の安定(満席維持・eviction・吹き出し追従・アニメ)を退化させる。
5. 毎フレーム全件走査で「開いた瞬間に重い」を会場で再現する。

## 段階プラン(会議の合意=gemma フェーズ0-2)
- **フェーズ0(計測・最優先)**: 実機868人で renderSeats の初回/再描画時間を計測、buildVenueSeating 内の重い計算を特定。
- **フェーズ1(hot path 防御・分離は最小)**: renderSeats に「変化検出→無変化スキップ」を広げる(順位/アバター計算を毎フレームやめる)。storage 鏡は増やさない。=記事の思想を"計算負荷オフロード"の形で最小導入。
- **フェーズ2(可視性回復=見せ方)**: バッジ拡大・静的オーラ復活・上部トップN バーのどれかで「上位が一目で分かる」を回復。これは分離と独立。

## 会議の限界(裏取り済み・司令塔補足)
- 会議は「SW で集計→鏡」を理想に置くが、実コード上「会場の参加者集約は userLaneCandidatesFromStorage(popup と共有の純関数)を鏡映する1経路」に既に統一済み(venueBar のコメント v0.1.789/754)。=会場は既に"レーン正本を映す"=部分的に分離済み。だから「席割り+順位の鏡を新規に SW へ」は二重実装になりうる=qwen 批判が正しい。→ **フェーズ1は新規鏡でなく既存経路に sig スキップを足すのが筋**。
- ⭐ ユーザーの2つの質問への最終回答:
  - Q1「そのまま運ぶ全体は大丈夫か」→ **大丈夫でない。C案=運ばない。会場は匿名も主役なので popup グリッドの丸呑みは思想衝突。**
  - Q2「分離思想は入っているか」→ **半分だけ。診断の鏡(venueSeatsDiag)と"レーン正本を映す"経路は分離済みだが、順位・アバター解決率は見せる側(renderSeats)で計算=未分離。ただし完全分離は過剰、目指すのは"計算1回→sig→貼る"の役割分担。**
