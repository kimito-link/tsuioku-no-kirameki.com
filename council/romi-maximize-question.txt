# お題: 星野ロミ理論の「最大化」

## 背景
星野ロミ氏のソース(すれちがいライト)から、再利用できる設計思想を抽出済み(横断資産:
AI汎用ルール/docs/design-principles-from-surechigai.md・html・図3枚)。核心は
「データを作る人(常駐側=記録)と見せる人(画面)を分け、重い処理は前段で1回、画面は貼るだけ」。

我々の対象 = ニコ生応援ライブビュー Chrome拡張(tsuioku-no-kirameki)。
- content(記録の心臓部)=watch タブで常時動く=星野ロミの「cron がクライアント不在でも生成」役。
- popup / 純Web live-view = 画面(貼るだけ)。
- 鏡(storage の snapshot)= 集計済みの置き場。
- 既に着手: v0.1.961 で content が コメント鏡を publish(popup を開かなくても出る)。
- 既知の地雷: popup の refresh/paint 改変=2回 revert / 丸ごとDOM鏡=実機で重く却下 /
  content(記録の心臓部)は壊すと記録が落ちる最重要領域。

## 問い(2つ。どちらも具体策まで)

### 問い1: この拡張で「星野ロミ理論」を最大化するには、次に何を・どの順で実装すべきか
- 「鏡の生成を popup→content へ寄せる」「表示は重い read をやめ鏡から貼るだけ」を、
  地雷(content 破壊・popup paint 改変・重い同期処理)を踏まずにどう進めるか。
- 11個の実装テク(二段フィルタ/受け手単位集約/動的キャップ/log NOT IN 冪等/集合UPDATE/
  CASE原子更新/API 1関数集約/常駐タスク/タイムスタンプ二択/冪等述語/自己文書化)のうち、
  この拡張(storageベース・DBなし)に効くものはどれで、どう翻訳するか。
- 最小で最大の効果(開いた瞬間が軽い・popup不要で出る・コメントが進む)を出す順番。

### 問い2: この設計ナレッジを技術記事として公開する具体策
- 公開先: tsuioku-no-kirameki.com/articles/ に技術記事として入れる。
- サイドバー(メニュー)からその記事に飛べる導線を付ける。
- 「実際にどうすればいいか」=記事の構成(誰向け・何を見せる・図3枚をどう使う)、
  サイドバー追加の実装方針(既存 articles の作りに合わせる=独自に作らない)。
- 他人が読んで価値があり、かつ自分/AIの今後の指針にもなる記事にするには何を書くか。
