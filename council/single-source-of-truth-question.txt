【会議の主題】
ユーザーの核心指摘:「星野ロミ理論つかってないんじゃ?」。
星野ロミ型=「データを作る人(記録/content)と見せる人(popup/プレビュー/純Web)を分け、見せる側はみな"同じ1つの真実(鏡)"を読むだけ」。
だが実機 v0.1.964 の状態速報で、まだ「拡張7 ≠ 鏡6」(1件差)が残り、応援プレビュー(passive)では描画関数が一度も呼ばれていない。
=「見せる側が同じ鏡を読むだけ」になっておらず、数字の出どころが二系統に割れている疑い。この構造の根を会議で固める。

【v0.1.963 で改善したこと(事実)】
- 北極星 貢献度コピー漏れ: 前回「拡張6 ≠ 鏡0(完全欠落)」→ 今回「拡張7 ≠ 鏡6」。deferWrite+allSettled後1回flush で 0→6 に劇的改善。
  だが【1件差が残る】。

【司令塔が実コードで確証した、1件差と"二系統"の正体】
1. 整合チェックが比べている2つの数は【別々の計算経路】:
   - 「拡張 apiRows=7」= content-entry.js:6204 kokenApiRowCount。content script が koken API を直読みして数えた【生の行数】。
   - 「鏡 6」= popup-entry.js:9993 が resolveOfficialContributionRankingRows→top10→buildNorthStarMirrorSnapshot で
     焼いた鏡の件数。popup が koken storage を読み直し、capRows/整形して書く。
   → 同じ koken 由来でも「content が数えた数」と「popup が鏡にした数」は別プロセス・別タイミングの2系統。
2. koken API は約30秒間隔で自動更新される(formatCardFreshnessNote autoRefreshing:true)。
   content の apiRows(今この瞬間=7)と、popup が鏡を焼いた時の koken storage(2分前=6)で、鮮度差で1件ズレうる。
3. 応援プレビュー(passive)の popup 固有診断: northStarRenderProbe.contribResolveCalls=0 / refreshAllStarted=0 /
   storyUserLaneRenderProbe.activePath="" / started=0。状態速報も「応援レーン描画: 描画関数が一度も呼ばれていません」。
   = 今回の鏡(6)は watch タブの本物 popup が2分前に書いたもの。プレビューはそれを読むだけ(passive 設計どおり)だが、
     比較対象の apiRows=7 は content の【今】の値=だから鮮度差で必ずズレる。

【ここが"星野ロミ理論を使っていない"の核心(仮説)】
- 「作る人」が二人いる: ①content が apiRows を数える / ②watch popup が鏡を焼く。同じ koken なのに二重計算・別タイミング。
- 本来の星野ロミ型なら「鏡を作る人は一人(=記録/常駐側 or 単一の resolver)」で、見せる側(popup/プレビュー/純Web)も
  診断の整合チェックも【同じ鏡】を読む。そうすれば「拡張 vs 鏡」の比較自体が同語反復(必ず一致)になり、1件差は構造的に消える。
- いま整合チェックは「content の生 apiRows(片方の作る人)」vs「popup の鏡(もう片方の作る人)」を比べている=
  二人の作る人を突き合わせている=ズレて当然=これが誤検知に近い構造警告を生み続ける。

【会議で詰めたい論点】
1. 上記仮説「貢献度の真実が content(apiRows)と popup(鏡)の二系統に割れている」は正しいか。
   1件差は本当に『鮮度差(koken 30秒更新)』で説明でき、コピー漏れではないと言い切れるか。他にズレる経路は?
2. 星野ロミ型に揃える最小の一手は?(構造の選択)
   (a) 「作る人を一人に」: 鏡を焼く責務を一箇所(例: content/常駐側 or 単一 resolver)に集約し、apiRows も同じ鏡から数える
       =整合チェックが同語反復になり1件差が消える。
   (b) 整合チェックを「鮮度を揃えてから比べる」: content apiRows と鏡の capturedAt が近い時だけ突合し、
       koken の自動更新で説明できる差は警告しない(v0.1.954 の SETTLED/鮮度ガードの貢献度版)。
   (c) 両方(根治は a、当面の誤検知抑制は b)。
