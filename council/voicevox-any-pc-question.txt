【お題】VOICEVOX読み上げが「どのPCでも動く」ようにしたい

## 実際に起きていること（ユーザー報告・2026-08-04）

メインPC（開発機）ではVOICEVOX読み上げが動く。
別のノートPCに入れたら、うまく動かなかった。

※ノートPC側で「何がどう失敗したか」の詳細は未取得。
　症状の言語化は「うまくいかなかった」のみ。ここは推測せず、
　「原因を切り分ける手段があるか」も論点に含めること。

## 前提となる実装の事実（司令塔がコードを読んで確認済み・推測ではない）

1. 接続先は完全にハードコード。
   src/lib/voicevoxClient.js:2
   `export const VOICEVOX_BASE_URL = 'http://127.0.0.1:50021';`
   ポート・ホストを変える設定UIは存在しない。

2. manifest.json の host_permissions に
   `http://127.0.0.1:50021/*` の1本しか無い。
   → 仮に設定UIでポートを変えられるようにしても、
     拡張はその宛先へ fetch する権限を持たない。
     つまり「設定項目を足すだけ」では原理的に解決しない。
     optional_host_permissions / 実行時許可要求の設計が要る。

3. 失敗理由を分類する計器は既にある。
   src/lib/voiceSynthFailureReason.js
   分類: unreachable / query_http / synth_http / timeout / query_body / synth_body / unknown
   unreachable のときの助言文（現状）:
   「VOICEVOX に接続できていません。起動しているか・ポート(既定50021)が
     合っているか確認してください(拡張側では直せません)」
   → 現状の設計思想は「接続不能はユーザーが自力で直すもの」。
     この前提自体を問い直すべきかが最大の争点。

4. 拡張ページ(comeview/venue/popup)は直接 fetch、
   Content Script(nicovideo.jp上)は background 経由プロキシ、という
   2経路構成。経路によって失敗の出方が違いうる。

## 検討してほしいこと

Q1. 「別のPCで動かない」の原因として現実的に何がありうるか。
    優先度順に、かつ「どれが実際に多いか」の見立て付きで。
    考慮すべき軸の例（これで尽きているとは限らない・追加歓迎）:
    - VOICEVOXが入っていない / 起動していない
    - 起動しているがポートが50021でない（別アプリと衝突・多重起動時の自動ずらし）
    - VOICEVOX本体ではなく類似エンジン（COEIROINK / AivisSpeech / SHAREVOX等）を入れている
    - CPU性能が低くタイムアウト（ノートPC=非力な可能性・GPU版とCPU版の差）
    - セキュリティソフト/ファイアウォールがlocalhost通信を遮断
    - Windowsの「ループバック制限」やプロキシ設定
    - 拡張のリロード漏れ・版ずれ

Q2. どこまでを拡張側で吸収すべきか。境界はどこか。
    「自動で見つけにいく」ことの副作用（起動の遅延・無駄なリクエスト・
     ユーザーが意図しない宛先への接続・審査上の懸念）も込みで判定すること。
    ポートスキャン的な挙動はCWS審査で問題になりうるか？も検討対象。

Q3. ユーザーが自力で直せるようにするには何が要るか。
    現状の「拡張側では直せません」という助言は、
    受け取ったユーザーが次に何をすればいいか分かる文になっているか。
    セットアップ確認画面（接続テストボタン等）は要るか。

Q4. 実装順序。1つだけ先に出すなら何を出すか。
    このプロダクトは「まず計器を入れて実測してから直す」流儀（AGENTS.md）。
    今回もその順序が正しいか、それとも自明なので直接直すべきか。

## 制約・前提（守ること）

- Chrome Manifest V3。host_permissions の追加は審査対象。
  2026-08-03に公開されたばかり（v0.1.1244）なので、
  次の版で審査を通す必要がある＝審査リスクの高い変更は慎重に。
- ユーザーは非エンジニアの配信者も含む。
  「ポート番号を調べて入力してください」は多くの人にとって高すぎる壁。
- 「推測で直す前に測る」がこのプロダクトの規律。
- 記録・送信ポリシー: ローカル保存のみ。外部送信を増やす案は不可。
