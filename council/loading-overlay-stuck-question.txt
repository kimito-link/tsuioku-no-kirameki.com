【司令塔の真因仮説(最有力)】
CSS フェイルセーフ(15秒)が幕を視覚的に消すが --done クラスを付けないため、shadeActive(クラス判定)が永遠に true。
=「ユーザーには幕が見えていないのに、診断だけが『ローディング継続』と言い続ける」=診断の誤検知。
10時間超の配信で shadeActive=true=本物の幕が10時間残るはずがない(JS安全網12秒/CSS15秒で必ず消える)=
クラスが付かなかっただけ、という状況証拠とも一致。

ただし副次の本物バグも疑う: JS の畳む安全網(12秒)が --done を付けていれば shadeActive は false のはず。
true ということは、この popup インスタンスで JS の畳む経路が --done を付けられていない(走っていない/別経路)可能性。

【会議で詰めたい論点】
1. 司令塔仮説(CSS フェイルセーフが --done を付けない→shadeActive 永続 true→誤検知)は本当に唯一/主因か。
   他に「幕が DOM に --done なしで残り続ける」経路はないか(dismiss が早期 return する条件・別 popup インスタンス・
   inlineWatchPanelHasRealDataForShade が永遠に false で poll し続ける等)。
2. JS の畳む安全網(18743 の 12秒 setTimeout)が --done を付けるはずなのに shadeActive=true なのはなぜか。
   この net が走らない/効かない条件はあるか(initPopup が throw・embedded で別経路・INLINE_PASSIVE 等)。
3. 修正方針(最小・低リスク・地雷ゼロ):
   (a) 診断 shadeActive を「クラス判定」でなく「実際に見えているか」で判定する
       (computed opacity/visibility or --done どちらかで畳まれていれば false)=誤検知を消す。
   (b) CSS フェイルセーフが消すのと同時に JS でも --done を付ける/animationend で --done を付ける
       =クラスと視覚を一致させる(診断とも整合)。
   (c) 両方(診断を視覚ベースに+animationend で --done 付与)。
   ★地雷回避: popup の refresh()/paint の read path 改変は禁止(2回 revert)。content/会場 不触。
     幕を「早く消しすぎて空白チラ見え」させない(幕の本来の役割=hidden 要素のガタつき隠しは保つ)。
4. ②応援ライブビュー/③純Web 側にこの幕/診断はあるか(3画面パリティとして揃える必要があるか)。
