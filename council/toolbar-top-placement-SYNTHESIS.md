# 操作ボタン群+会場モードボタンを「上の方」へ — 会議の収束(星野ロミ式)

会議: `council/toolbar-top-placement-answers.json`(2026-06-22・design・routed・成功2/3)
お題: 操作ボタン群と会場モードボタンを「上の方」に。星野ロミだったらどうするか。

## 会議の結論(fast + critic)
- **fast(爆速の視点)**: 案(a)が最良=パネルのヘッダーのすぐ下に操作ボタン群を移動し、会場モードボタンも同列へ。最小ブラスト半径(既存のボタン生成関数・CSSクラスを活かし DOM 移動だけ)。
- **critic(批判役)の穴**: 「横付き(beside)」モードでパネルが画面**右半分**に出ると、操作群が右寄りになり左手から届きにくい。会場モードを右下固定から外すと押しやすさ(Fitts則)が下がる懸念。「横付きモードでの操作性が考慮不足」。
- diverge(発散役)は空回答。

## 司令塔のコード裏取り(会議の素材を実機コードで検証)
- **操作ボタン群の正体** = popup.html `.nl-compose-quick-toolbar`(L11253-11340)。HTML/マーケ/メディアキット/スクショ/再読み込み/コメビュ/読み上げの7ボタン。**コメント送信ボタンの直後=compose(コメント入力)エリアの中**にあり、popup 構造上かなり下(header→統計カード→北極星レーン→設定→divider→**compose**→stats→watchメタ)。
- **会場モードボタン** = content-entry.js / venueBar.js の `.nlsb-toggle`(画面右下 fixed・別レイヤー・z-index 最上位)。compose とは別系統。
- **クリックハンドラは全て `getElementById`($('exportJson') 等・popup-entry.js)で個別束ね**。イベント委譲でも親依存でもない=**`.nl-compose-quick-toolbar` を DOM のどこへ移動しても id が同じなら全ハンドラ無傷**。→ 会議の「最小ブラスト半径」はコードで裏取りできた(回帰リスク極小)。
- inlinePanel は viewportInnerWidth<1100 で「下(below・player_row)」・以上で「横付き(beside)」。実機 1065px=下。

## 収束した1案(段階実装・星野ロミ式=大胆だが摩擦ゼロ・既存資産活用)

### 段階1: 操作ボタン群を compose の中から「上」へ昇格(最小・回帰ほぼゼロ)
- `.nl-compose-quick-toolbar` を、popup の**上部(配信統計カード liveStatCards の直後あたり)へ DOM 移動**。
  - id ハンドラは無傷なので JS は触らない。HTML の位置を移すだけ。
  - compose(コメント入力)はその場に残す(送信ボタンは入力の近くが自然)。クイックツールバーだけ上へ。
- **critic の穴への対処**: 横付き/下のどちらでもツールバーは「パネル内の上部」に固定されるので、パネルがどこに出ても【パネルの上端付近】に一貫して見える(画面の左右でなくパネル基準=モードでブレない)。右寄り問題はパネル内配置なので発生しない(パネル幅いっぱいに flex-wrap で並ぶ)。

### 段階2: 会場モードボタンを右下固定から「パネル上部の操作列」へ寄せる(要ユーザー確認)
- 現状 `.nlsb-toggle` は右下 fixed。これをやめてヘッダー隣接の操作列に入れるか、右下固定を残すかは設計判断が割れる:
  - 外す利点=操作群と一緒に上で見つかる(ユーザー要望「会場モードも上に」に直答)。
  - 外す欠点=会場モードは「全画面で開く」入口なので、視聴中どこからでも押せる右下固定にも価値がある(critic の Fitts 則)。
- **折衷(星野ロミ式・失敗体験の除去)**: 会場モードボタンを【両方】に出す=パネル上部の操作列にも1つ追加し、右下固定も残す。どちらからでも開ける=「見つからない」を構造的に潰す。会場モードのトグルは id/クリックで開くだけなので二重設置は安全。

## 評価軸での確認
- ①すぐ手が届く/見つかる=操作群が上端に・会場モードも上に出る(段階2)→ ◎
- ②映像を邪魔しない=操作群はパネル内(映像中央セーフエリアは不変)・会場トグルは従来通り小さい→ ◎
- ③回帰リスク=id ハンドラ無傷・DOM 移動のみ→ 極小(裏取り済)
- ④星野ロミらしさ=大胆(配置を上へ)×摩擦ゼロ(既存ボタン流用)×失敗体験除去(両方に置いて見つからないを潰す)→ ◎
- ⑤横付き/下の一貫性=パネル基準配置でモード非依存→ ◎(critic の穴を解消)

## 残る確認(ユーザーに1点)
段階2の会場モードボタンを「右下固定をやめて上だけ」にするか「両方に出す(上+右下)」か。
推奨=両方(見つからないを構造的に潰す・右下の常時アクセスも残す)。
