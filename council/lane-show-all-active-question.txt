お題: Chrome拡張「君斗りんくの追憶のきらめき」(ニコ生コメント記録・応援可視化)の【応援アイコン列(レーン)】と【会場モード】で、「アクティブにコメントした人・ギフト/広告した人(=素性=userId が取れた人)を全員出す」のが本来の設計のはずなのに、表示上限(limit)で大半が切られていた。星野ロミ(リスクを取って大胆・摩擦ゼロ・失敗体験の除去・既存資産を最大活用・見やすさ最優先・SHOWROOM感)ならどう設計するかで会議してほしい。

== 実データで確定した事実(状態速報・実機 lv350806949 ミュントゥ配信) ==
- interceptMapSize=522 = 素性(userId)を観測できた人=【522人】。
- コメントした人=204人(レポート)。来場1,287・沈黙視聴者1,083(推定)。
- ★avatarUidDiag.uidNoAv=522 / interceptAvatarSize=1 =【522人中、顔写真(個人サムネ)が紐付いたのは1人だけ(しかも配信者本人)】。この配信は顔写真がほぼ取れていない=ほぼ全員が「ゆっくり顔」表示になる。
- 別の482人/295人/301人規模の配信も同様に観測ユーザーが数百人規模になる。

== 実コードで裏取りした現状の絞り ==
[popup 応援レーン(りんく/こん太/たぬ姉)]
- popup-entry.js:5203 `const limit = INLINE_MODE ? 48 : 24;` =【インライン48人/別窓24人で打ち切り】。
- storyUserLaneBuckets.js `bucketStoryUserLanePicks(sortedCandidates, maxTotal)`: 候補を profileTier(3=りんく:数値ID+個人サムネ揃い / 2=こん太:数値IDで表示名か個人サムネのどちらか / 1=たぬ姉:匿名a:や素性不足)で分類し、tier 高い順に先頭 maxTotal(=limit) 件だけ採用。残りは捨てる。
- つまり 522人素性が取れていても popup レーンは最大48人しか出ない=【474人がレーンから漏れている】。顔写真がほぼ0なので、出る48人もほとんど tier1(たぬ姉・ゆっくり顔)。
- 別に「全コメント者グリッド」(応援N,NNNコメント・×回数つき)があり、これはコメント【回数】で並ぶ別表示(人ではなく発言数の特徴)。

[会場モード]
- venueBar は userLaneCandidatesFromStorage(全候補)を venueRowsFromUserLaneCandidates でほぼ全員(userId があれば全員)席にしている=limit 48 を通さない。
- 設計コメント(venueBar.js:48-52)の正本=【会場=popup レーンの鏡映(顔ぶれ一致が正)・ズレたら表示間引き層のバグ】。
- だが実際は popup(48で絞る)と会場(絞らず数百人)で顔ぶれ・人数が食い違う。直前に司令塔が会場 cap を 150→500 に上げたが、これはユーザーの本意(レーンの厳選された人を出す)と逆方向の見当違いだった。

== ユーザーの確定した意図 ==
- 「アクティブにコメントした人・ギフト/広告した人(素性が取れた人)は全員 popup に並ぶのが本来の姿。本当はもっといるはず」。
- 沈黙視聴者(無言・userId 取れない)は原理的に出せない(NDGR制約)=対象外でよい。
- 匿名(a:・ゆっくり顔)も出したい(「そもそも大した数じゃない」と思っていたが実は522人と多かった)。
- 「コメント回数で数える全コメント者グリッド」とは別物として、レーンは「素性が取れた人(人単位)を出す」ものという理解。

== 設計の核心(会議で解くべき緊張) ==
1. 「素性が取れた人を全員出す」を額面どおりやると、popup レーンに522人(将来もっと)が縦に延々と並ぶ=狭いインラインパネルが極端に長く重くなる。limit 48 はそれを防ぐ実務上の蓋でもあった。全員出す と 見やすさ/軽さ をどう両立するか。
2. 顔写真がほぼ取れない配信(522人中1人)では、りんく段(個人サムネ必須)はほぼ空で、ほとんどが「ゆっくり顔の匿名(たぬ姉)」になる。522人ぶんのゆっくり顔が並ぶことに意味/魅力はあるか。SHOWROOM感(顔が見える賑わい)と、ゆっくり顔だらけの違いをどう扱うか。
3. popup(確認・分析用の狭いパネル)と 会場(没入・全画面の主役)で、出す人数を変えてよいか。例: popup レーンは上位N人+「ほかM人」要約、会場は全員、など役割で出し分けるのが妥当か。それとも両方とも全員が正か。
4. 並び順は profileTier(りんく→こん太→たぬ姉)で正しいか。同tier内は何順(最近発言/発言数/ギフト)が良いか。

== 重要な過去の失敗(前提として必ず踏まえる) ==
- 司令塔が「とにかく全員500人」と早合点して会場 cap を 150→500 に上げたが、ユーザーの本意は「レーンに出る厳選された人(素性が取れた人)を出す」で、無差別な水増しではなかった=前提の取り違えで遠回りした。会議も前提が誤ると全員同じ方向に間違える(過去の「壁で覆う」失敗と同じ)。各メンバーは前提自体を疑うこと。
- loading="lazy" を会場(CSS 3D変形)に入れたら可視判定が崩れサムネが出ない実機症状=安易な最適化が裏目。実装手段は実機挙動で検証前提。

== 問い ==
1. 「素性が取れた人(コメント/ギフト/広告した人)を全員出す」を、見やすさ・軽さを保って実現する最良の設計は何か。候補(これに限らない):
   (a) popup レーンの limit 48 を撤廃し全員出す(縦スクロール+content-visibility 等で軽さ確保)。会場も同集合を鏡映。
   (b) popup レーンは「上位N人+ほかM人」の要約表示にとどめ、会場(全画面)でだけ全員を出す。役割で出し分け。
   (c) limit を「固定48」でなく人数連動(例: 観測数まで・上限は性能天井)にする。
   (d) その他の星野ロミ的アイデア(大胆・摩擦ゼロ・既存資産=bucketStoryUserLanePicks/buildPersonTileEl/会場tier を活かす)。
2. 顔写真がほぼ取れない配信(ゆっくり顔だらけ)でも「全員出す」は魅力的か。匿名の扱い(出す/要約する/別段に集める)。SHOWROOM感との両立。
3. popup と会場で人数・見せ方を変えてよいか。変えるなら境界はどこか(popup=確認/分析・会場=没入の主役、という役割分担は妥当か)。
4. 並び順・同tier内ソート。「コメント回数で並ぶ全コメント者グリッド」と「人単位のレーン」の役割の違いをユーザーに誤解させない見せ方。
5. 最小ブラスト半径で段階リリースするなら、どの順でPRを切るか(各段で実機確認・状態速報で人数を裏取りする前提)。

評価軸: ①素性が取れた人を抜け漏れなく出せるか ②見やすさ・軽さ(数百人でも破綻しない) ③popup(狭い)と会場(全画面)それぞれの役割に合うか ④顔写真が無い配信でも成立するか ⑤実装/保守コストと回帰リスク(最小ブラスト半径・既存の bucket/会場 tier/本物タイルを活かす) ⑥星野ロミらしさ(大胆・摩擦ゼロ・既存資産活用・失敗体験の除去) ⑦ユーザーに「全員出ている」と誠実に伝わるか(48で黙って切る=不誠実を避ける)。

各メンバーは『結論 → 根拠 → 反論・リスク → 具体案(どの関数/定数/DOMをどう変えるか・PR段階)』の4ブロックで。批判役は必ず穴を1つ指摘し、前提(全員を本当に全部出すべきか・popup と会場を分けるべきか)自体も疑うこと。司令塔(Claude)が最後に統合・裏取りして1案に収束させる。最優先は「素性が取れた人(アクティブ参加者)を、見やすさと軽さを保って誠実に全員見せる」設計。
