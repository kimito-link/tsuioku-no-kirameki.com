## 2️⃣ sanitize：全 popup を通すためのサニタイズ拡張  

### 根拠
- 1 つの HTML 文字列をそのまま `innerHTML` で貼り付けると、**スクリプト・インラインスタイル・危険 URL** が潜む可能性がある。  
- 既存 `sanitizeMirrorHtml` は「小フラグメント」用にタグ/属性が厳しく絞られているが、**丸ごと HTML** では `<div>、<section>、<a>、<img>、<svg>` などが大量に出現する。  

### 反論・リスク
- **過度に緩めると XSS が通過** → 重大なセキュリティインシデント。  
- **過度に厳しくすると UI が崩れる** → 画像が消える、リンクが無効になる。  

### 具体案 – 「HTML‑Mirror Sanitizer」(新規モジュール)

| カテゴリ | 許可タグ | 許可属性 (属性ごとに whitelist) | 特記事項 |
|----------|----------|--------------------------------|----------|
| **構造** | `div,section,article,header,footer,nav,main,aside,ul,ol,li,span,p,h1‑h6` | `class,id,style? (only safe CSS properties) ,data-*,title,hidden` | `style` は **CSS‑property whitelist** (例: `color,background-color,font-size,display,flex,grid,margin,padding,overflow`) |
| **リンク** | `a` | `href,target,rel,download` | `href` は `http:`、`https:`、`mailto:` のみ許可。`javascript:` は除外。 |
| **画像** | `img` | `src,alt,width,height,loading,decoding,referrerpolicy` | `src` が相対パスか `https:` の外部 URL のみ許可。`data:` URL は **許可しない**（別途 Base64 で埋め込む場合は事前エンコード）。 |
| **SVG** | `svg, path, circle, rect, line, polyline, polygon, g, text, defs, use` | `viewBox,width,height,fill,stroke,stroke-width,transform,style` | `on*` 系属性はすべて除去。 |
| **メディア** | `video, audio, source` | `src,type,controls,autoplay,loop,muted,preload` | `src` の同上。 |
| **フォーム系** | **除外** (popup では使用しない) | – | 予防的にブロック。 |

#### 実装手順
1. **DOMParser** で文字列 → `DocumentFragment` に変換。  
2. 再帰的にノードを走査し、**許可リスト**に合致しないタグは **`document.createElement('span')`** に置き換えて `textContent` に変換 (安全に除去)。  
3. 許可属性は **属性名と値の正規表現**で検証。  
4. `style` 属性は **CSS‑property whitelist**でフィルタし、残りは削除。  
5. 最終的に `fragment.innerHTML` を返す。  

> **ポイント**：このサニタイズは「丸ごと」用にだけ作る。既存の小フラグメントサニタイズはそのまま残し、コードベースの分離を保つ (`sanitizeMirrorHtml` → `sanitizeSectionHtml`, `sanitizeFullHtml`).
