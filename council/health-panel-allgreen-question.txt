お題: 「配信を見た瞬間、健全度パネルが全部100%(緑)に見えてほしい」を星野ロミ式でどう実現するか

# 文脈(実コードで確認済み・ハルシネ禁止)
Chrome拡張「君斗りんくの追憶のきらめき」= ニコ生のコメントを記録し可視化する拡張。
status.html の先頭に「健全度パネル」(約18セル・healthCells.js)がある。各セルは
{ level: 'ok'(緑) | 'warn'(黄) | 'bad'(赤) | 'na'(グレー「—」) } を持つ。

ユーザーの本音: 「配信を開いた瞬間に、パネルが全部 緑(正常)になっていてほしい」。
今は配信を開いた直後の数秒〜数分、以下のセルが黄色/赤になり「調子が悪い」ように見える:

- 取得率 70%(warn): recordedSum/officialSum。過去ログ取り込み(backfill)が進行中で
  記録 < 公式 だから低い。時間が経てば埋まる。閾値 80%以上で緑・40-79で黄。
- 過去ログ取得「取得中」(warn): backfill.running=true の間ずっと warn。
- 貢献度ランキング/ギフト履歴「取得中」(warn): API/iframe 待ちの間 warn(iframe_unrendered)。
- 記録↔公式一致 39%(bad): per-live レートの最小。backfill 途中の配信が引き下げる。
- NDGRコメント「0(匿名/取得前)」(warn): decoded>0 だが chats=0。匿名(184)主体の配信は
  仕様上 userId 付きコメントが取れない=これは直せない構造的制約。

# 設計上の緊張(ここを詰めてほしい)
「全部緑にする」には2つの道があり、星野ロミ式(=失敗体験の除去 / だが嘘はつかない /
既存データを活かす / 過剰実装しない)の解釈が割れる:

道A(正直派): 「進行中(取得中・backfill中)」を【異常な黄色】ではなく【正常な途中状態】
  として色を分ける。例: 完了予定の作業が進行中=青や進捗バーで「順調」を表す。
  完了したら緑。数字は変えない。初動が「異常に見えない」だけ。

道B(楽観派): 「取得中」「backfillで率が低い」を最初から ok(緑)扱いにする。
  一目で全緑になるが、本当に詰まっている時も緑になり「正確さ」を損なうリスク。
  この拡張には self-verifying-loop の鉄則(検証可能な事実だけ自動で緑にする・
  嘘の安心を出さない)があり、道Bは原則違反になりうる。

# 問い(3点)
1. 「配信を見た瞬間に全部100%(緑)に見せたい」というユーザー体験を、嘘をつかずに
   実現する設計は何か。色の意味体系(正常/進行中/異常/対象外)をどう再設計すべきか。
2. 「進行中(backfill中・取得中)」と「本当に詰まっている(失速・エラー)」を、
   ユーザーが既に見て不安にならない形で、かつ正確に区別する具体案は。
   (既存の値: backfill.running / backfill.stopReason==='stalled' / lastIngestAgoMs /
    state==='iframe_unrendered' 等が使える)
3. 匿名主体配信の「NDGRコメント 0」のような【構造的に直せない=正常】な項目を、
   赤/黄でなく「これは正常」と伝える最小の見せ方は。

# 出力フォーマット(各メンバー固定)
結論 → 根拠 → 反論・リスク → 具体案(実装の粒度で・既存フィールド名を使って)

# 制約(星野ロミ式・絶対)
- 嘘をつかない(本当に詰まっている時に緑にしない)。記録本体・コメント取得は不可侵。
- 新規の重い集計を hot path に足さない(healthCells は再表示のみ)。
- 過剰実装しない(新テーブル/動的シミュレータ/巨大SVGは却下対象)。
- 既存フィールド(healthCells.js が既に読む livesData/fastDiag)だけで完結させる。
