# お題: status.html を「これ1枚見れば、あらゆる不具合の原因にたどり着いて直せる」集約画面にする

## ユーザーの要望（原文の意図）
「いろんな情報を1つの status.html に集約したい。これさえ見れば、あらゆる不具合が直せる――そういう画面にしたい。」

## 前提（実在するものだけ・推測しない）
Chrome 拡張『君斗りんくの追憶のきらめき』(ニコ生コメント記録・可視化)。status.html は拡張内ページ
(`chrome-extension://…/status.html`)で、**完全リードオンリー**(storage write しない・2秒ごと自動更新・document.hidden で停止)。

### status.html が【今すでに】集約しているもの
- 概要(記録件数・取得率・公式値レーン状況)・配信ごとカード(健康チェック5段階)
- content 由来の fastDiag(`nls_ai_share_fast_diag_v1`)= コメント取得経路別件数・userId率・NDGR重複除去・
  北極星レーン5種・backfill stopReason・longTasks・networkErrorProbe・多タブ汚染 等(巨大JSON)
- popup 固有診断(`nls_ai_share_popup_diag_v1`)= avatarLoadDiag・northStarRenderProbe・watchSnapshotMeta・storageReadback
- **🧠 全体マインドマップ**(折りたたみツリー・🟢健全/🟡注目/🔴要対応/⚪情報 の badge・7枝)
- AI共有まとめテキスト(content+popup 全集約・コピーして AI に貼る用)
- ボタン: コメビュ/評判チェック/次配信/自動巡回/スマホ送信/コピー/JSON DL/一時停止

### status.html に【まだ無い・課題】
- マインドマップの badge は出るが、🔴/🟡 を見ても「**で、どう直すのか**」の次の一手が画面に出ない
  (原因→対処の橋渡しが無い。AIに貼って聞くしかない)。
- 既知の不具合パターン(例: 匿名配信で会場が空=userId が DOM に無い・NDGR のみ / 取得率が伸びない=backfill stalled /
  アバターが付かない=avatarMapSize 少 / レーンが空=northStar 描画詰まり)が、**症状から原因へ自動で結びつかない**。
- storage は read only。content/popup/SW/offscreen の状態は storage 経由でしか取れない(直接呼べない)。
- 巨大 JSON は人には読めない(AIには貼れる)。「人が見て分かる」と「AIが直せる」の両立が未整理。

## 問い（これに答えて）
status.html を「**これ1枚見れば、あらゆる不具合の原因にたどり着いて直せる**」画面にするには、どう設計するのが最善か。
ただし「全部の生データを盛る」のは却下(既にやっていて人には読めない)。**症状→原因→次の一手**を結びつける設計を求める。

## 特に答えてほしい論点
1. 「あらゆる不具合が直せる」は**幻想か実現可能か**。実現可能なら、その境界(status だけで直せる範囲 vs 直せない範囲)はどこか。
2. **症状→原因→対処**を結びつける最小の仕組みは何か(ルールベースの診断? 既知パターン辞書? 重大度ソート?)。
3. 既存の fastDiag/popupDiag/マインドマップ/AI共有まとめを**捨てずに**どう繋ぐか。
4. 「人が見て分かる(要約・次の一手)」と「AIが直せる(全データ)」を1画面でどう両立するか。
5. リードオンリー制約(storage 経由のみ・SW/offscreen を直接呼べない)で**取れない情報**は何か。それを正直に「不明」と出す設計。
6. やってはいけない過剰実装(アンチパターン)。

## 制約（必ず守る・破る案は減点）
- リードオンリー維持(storage write しない)・外部送信ゼロ(プライバシー)・追加の重い依存ゼロ(CWS審査/オフライン)。
- 既存資産(fastDiag/popupDiag/マインドマップ/AI共有まとめ)を捨てない・作り直さない。
- 過剰実装しない(全部入りの巨大フレームワーク・万能AI診断エンジンは却下)。最小で最大の不具合を自己解決に導く一点。
- 純ロジックは src/lib に切り出しテスト可能に(status-entry は描画配線)。
