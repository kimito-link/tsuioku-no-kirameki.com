## 結論
「会場モード」を「popup の DOM をコピーして貼り付ける」という物理的な作業ではなく、**「popup の描画エンジン（paintStoryUserLaneDomFilled）を、会場モードという『巨大なキャンバス』上で直接駆動する」**というアーキテクチャ転換で実装します。
具体的には、既存の独自席生成ロジック（buildVenueTiers 等）を即座に無効化し、会場の DOM 生成関数を「popup の bucket データを直接受け取って、popup と同一の CSS クラスと構造で描画する関数」に差し替えます。これにより、CSS の重複定義を避け、popup と会場が「同じ描画コード」を共有する唯一の正解を実現します。

## 根拠
1.  **本物の再利用の真髄**: ユーザーが求める「コピペ」は、DOM ノードを物理的に移動させること（`appendChild`）ではなく、**「同じデータから同じ見た目（クラス・構造・振る舞い）を生成すること」**です。DOM を移動させると、popup 固有のイベントリスナーや状態管理が壊れるリスクがあり、CSS クラスの競合も起きます。
2.  **CSS 問題の解決**: `popup.html` 限定の CSS を会场（content script）に持ってくるのは保守上最悪です。描画ロジック（JS）が「popup 用の CSS クラス名を出力する」のではなく、「会場モード用（＝popup と同一のクラス名）の CSS を用意した環境で描画する」ようにすれば、JS は共通化でき、CSS は会場モード専用の `<style>` タグとして注入するだけで済みます。
3.  **摩擦ゼロのUX**: 独自席を「削除」するのではなく、「描画ロジックの分岐」で**「会場モード時は独自席生成関数を呼び出さない」**とすることで、コードの削除（破壊的変更）を避けつつ、実質的に独自席を消去できます。これにより、回帰テストのリスクを最小化します。
4.  **VOICEVOX と演出の同期**: 演出時間は「待機時間」ではなく「初期化時間」と定義し、演出開始直後に非同期でVOICEVOX 初期化（エンジン起動・モデル読み込み）を開始させます。演出終了時の `Promise.race` で「VOICEVOX 準備完了」か「演出終了（タイムアウト）」のどちらが先か判定し、遅れた場合は「準備完了まで読み上げを保留（キューに溜める）」する仕組みにします。

## 反論・リスク
*   **リスク1（CSS の重複と競合）**: 会場の DOM に `popup` 固有のクラス（例：`.popup-icon-grid`）を大量に生成すると、ページ全体のスタイルが崩れる可能性があります。
    *   *対策*: 会場モードのコンテナ（ダイアログ）に対して、`position: relative; isolation: isolate;` を適用し、外部スタイルの影響を遮断しつつ、内部で popup と全く同じ CSS を注入（scoped style のような振る舞い）します。
*   **リスク2（VOICEVOX の起動遅延）**: 演出時間（例：3 秒）よりも VOICEVOX の起動が大幅に遅れる場合、ユーザーは「何も起きない」体験をします。
    *   *対策*: 演出中に「読み上げ準備中」のステータスをアイコン自体（例：アイコンの周りをぐるぐる回るアニメーション）で可視化し、VOICEVOX 準備完了と同時に吹き出しが出現するように設計します。「待たされる」のではなく「準備中」という状態が視覚的に伝わるようにします。
*   **リスク3（スクロールと座標計算）**: popup は固定サイズですが、会場モードはスクロール可能になるため、吹き出しの座標計算（`getBoundingClientRect`）がズレる可能性があります。
    *   *対策*: 吹き出しの位置計算を、イベント発生時ではなく「描画完了時＋スクロールイベント」で動的に再計算する仕組み（Observer 監視）を吹き出しコンポーネントに追加します。

## 具体案
### 1. 実装アプローチ：「描画関数の共有化とコンテキスト切り替え」

### 2. CSS 解決策：「会場モード専用スタイル注入」
*   `venue.css`（または JS 内で生成する `<style>`）に、popup と**完全に同一**のクラス定義（`.icon-grid`, `.person-tile`, `.ad-row` など）を記述する。
*   これにより、JS は「popup 用クラス」を出力するだけでよく、CSS は「会場用」だが中身は同一という状態を実現。これにより `popup.html` の依存を完全に排除。

### 3. VOICEVOX 同期設計：「演出＝ウォームアップ」

*   **演出中**: キャラクターが「会場モードになるよー」と喋っている間、バックグラウンドでエンジン起動。

    *   どちらが先に来ても「読み上げ可能」とみなす（遅れてもキューに溜める）。
    *   演出終了と同時に、キュー内のコメントを順次読み上げ開始。

*   吹き出しコンポーネントに `IntersectionObserver` を設定し、スクロールやリサイズ時に `getBoundingClientRect()` を再取得して位置を修正する。
*   CSS で吹き出しを `position: absolute`（親コンテナ相対）ではなく、`transform: translate(...)` で絶対位置制御するか、または `fixed` 座標計算（画面座標）に変更し、スクロールに追従させる。

### 5. 段階リリース（最小ブラスト半径）
