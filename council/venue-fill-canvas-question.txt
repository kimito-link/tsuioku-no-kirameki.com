お題: Chrome拡張「君斗りんくの追憶のきらめき」(ニコ生コメント記録・応援可視化)の【会場モード】を出したとき、配信画面(プレイヤー映像)以外の余白を全部覆い尽くすレイアウトにしたい。ユーザー要望「会場モードを出したとき、配信画面じゃない部分を全部おおいつくすようにしてほしい。見やすさ使いやすさ重視」。星野ロミ(リスクを取って大胆・摩擦ゼロ・失敗体験の除去・既存資産を最大活用・見やすさ最優先)ならどう最大化するかで会議してほしい。

== 現状(実コードで確認済み) ==

[会場モードの構造・src/extension/venueBar.js]
- `.nlsb-root`: position:fixed; inset:0(画面全体を覆う土台)。z-index 最上位。
- `.nlsb-stage`: position:fixed; inset:0(全画面)。display:grid。padding clamp(52px,7vh,76px) clamp(14px,3vw,44px) 64px。**背景は意図的に透明**(後述の過去方針)。中央に「映像セーフエリア」を空け、下端に客席(ひな壇)を置く2行グリッド(grid-template-rows: minmax(0,1fr) auto / areas "safe" "seating")。
- `.nlsb-stage-layout`: **width: min(1500px, 100%); margin: 0 auto** ← ここが余白の主因。中身(席・ヘッダー)を最大1500px幅に制限して中央寄せ。広い画面では左右に余白ができ、その余白から後ろの配信ページ(白背景・本家UI)が透けて見える=ユーザーが「覆われていない」と感じている部分。
- `.nlsb-seating`: 画面下端のひな壇(客席)。max-height: var(--nlsb-venue-max-h, 55vh)。客席は下端だけで、中央〜上部は空けて映像を透かす設計。
- `.nlsb-residents`: 3キャラ(りんく・こん太・たぬ姉)を画面の左右の縁に絶対配置。
- 吹き出し(.nlsb-bubble-layer)・ギフト投げ演出(.nlsb-gift-proj)・額縁(.nlsb-charframe)は最前面レイヤー。

[重要な過去の設計方針(今回のお題と緊張関係にある)]
- 2026-06-13(強い方針): 「配信の画面と実際の画面にスモークをかけないで・ちゃんと見たい」→ 全面を覆う暗幕を撤去し、`.nlsb-stage` の背景を透明にして、後ろのニコ生映像と本家UIをそのまま透かして見せる設計にした。会場の雰囲気は上端・下端の淡い照明(radial-gradient)だけで出し、中央の映像にはかけない。
- 中央セーフエリア(.nlsb-safe-area)は pointer-events:none で、配信映像・本家UIを直接クリックできるよう透過させている。

[今回のスクショで分かる現状]
- 会場モードを開くと、画面の一部(左〜中央)にしか会場が広がって見えず、右側に大きな白い余白(配信ページの白背景)が残っている。
- ユーザーはこの「配信画面以外の余白」を会場(席・装飾・盛り上がり)で埋めて、配信に没入できる一体感のある画面にしたい。

== 設計の緊張関係(会議で解くべき核心) ==
- 過去方針「映像も周りも透けさせてそのまま見せる(スモーク禁止)」 vs 今回要望「配信画面以外を全部覆い尽くす」。これは一見逆方向。
- 両立の鍵: 「配信映像(プレイヤーの矩形)」だけは見せ続け、それ以外の余白(本家のコメント欄・サイドバー・空白)は会場の世界で覆う、という切り分け。映像は素通し・周りは会場、にできるか。

== 問い ==
1. 「配信画面以外を全部覆い尽くす」を実現する最良のレイアウトは何か。候補(これに限らない):
   (a) .nlsb-stage-layout の width 制限(min(1500px,100%))を撤廃し、画面全幅(100vw)に席・装飾を広げる。余白に席や群衆を敷き詰める。
   (b) 背景透明をやめ、映像の矩形だけをくり抜いた(mask/clip-path)不透明の会場背景で全画面を覆う=映像は見えるが周りは完全に会場。
   (c) 会場を「映像の周囲を囲むレイアウト」に再設計(映像を中央に据え、上下左右の余白すべてに席・ランキング・盛り上がりメーター・3キャラを配置)。
   (d) その他の星野ロミ的アイデア(大胆だが見やすい・没入感を最大化)。
2. 過去方針「スモーク禁止・映像と本家UIを透かす」と今回要望「全部覆う」をどう両立させるか。映像の矩形をどう特定して、そこだけ素通しにするか(プレイヤー要素の座標は content script が取得可能=player.frameTarget の rect が診断に出ている)。本家のコメント欄やサイドバーは覆ってよいのか(ユーザーは「配信画面じゃない部分」と言っている=映像以外は覆ってよい解釈が自然)。
3. 「見やすさ・使いやすさ」をどう担保するか。全画面を会場で埋めると、席が増えすぎて散らかる/重くなる懸念。情報の優先順位(映像>盛り上がり>応援者>装飾)をどうレイアウトに落とすか。横長/縦長や画面幅で破綻しないか。
4. 最小の実装変更で実現する道。既存の席割り(buildVenueSeating)・吹き出し・3キャラ・ヒートを活かしつつ、主に CSS(width撤廃・grid再構成)で済むか。回帰リスク(中央セーフエリアのクリック透過・席の visibleSeats 制限・吹き出し座標)。

評価軸: ①「配信画面以外を全部覆う」没入感・一体感が出るか ②配信映像は見続けられるか(映像を隠さない) ③見やすさ・使いやすさ(散らからない・情報の優先順位) ④実装/保守コストと回帰リスク(最小ブラスト半径) ⑤星野ロミらしさ(大胆・摩擦ゼロ・既存資産活用・失敗体験除去) ⑥画面幅(横長/縦長・狭い/広い)で破綻しないか。

各メンバーは『結論 → 根拠 → 反論・リスク → 具体案(どの要素をどのCSS/DOMでどう変えるか・段階)』の4ブロックで。批判役は必ず穴を1つ指摘。司令塔(Claude)が最後に統合・裏取りして1案に収束させる。最優先は「見やすさ・使いやすさを保ったまま、配信画面以外を会場で覆い尽くす」設計。
