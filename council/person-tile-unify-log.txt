**3. データモデル**  

```ts
// 既存
type UserLaneCandidateFromStorage = {
  userId: string;
  nickname: string;
  avatarUrl: string;
  avatarObserved: boolean;
  liveId: string;
  commentCount?: number;
  giftCount?: number;
  _laneSortAt?: number;
};

// 正本化＋読み取り専用拡張
type UserProfile = UserLaneCandidateFromStorage & {
  /** コメント行（userId が付与されたもの）を全件取得しただけの参照 */
  comments: ReadonlyArray<CommentRow>;
  /** ギフト行 */
  gifts: ReadonlyArray<GiftRow>;
  /** 広告/貢献度行 */
  ads: ReadonlyArray<AdRow>;
};

/**
 * pure function – storage から取得した rows, liveId を渡すだけで
 * userId がキーの Map<UserProfile> を生成。書き込みは行わない。
 */
function buildUserProfiles(
  rows: CommentRow[],               // IndexedDB から取得した全コメント行
  liveId: string
): Map<string, UserProfile> {
  const map = new Map<string, UserProfile>();
  rows.forEach(row => {
    const uid = row.userId;
    if (!uid) return;               // userId が無い行は除外（NDGR では取得不可）
    let profile = map.get(uid);
    if (!profile) {
      profile = {
        userId: uid,
        nickname: row.nickname ?? `a:${row.anonymousId ?? '???'}`,
        avatarUrl: row.avatarUrl ?? '',
        avatarObserved: !!row.avatarObserved,
        liveId,
        commentCount: 0,
        giftCount: 0,
        _laneSortAt: row.timestamp,
        comments: [],
        gifts: [],
        ads: []
      };
      map.set(uid, profile);
    }
    // 集約は読み取り専用なので直接 push せず新配列を作らない
    if (row.type === 'comment') profile.comments = [...profile.comments, row];
    if (row.type === 'gift')    profile.gifts    = [...profile.gifts, row];
    if (row.type === 'ad')      profile.ads      = [...profile.ads, row];
    // カウントは即時インクリメントだけ
    if (row.type === 'comment') profile.commentCount = (profile.commentCount ?? 0) + 1;
    if (row.type === 'gift')    profile.giftCount    = (profile.giftCount ?? 0) + 1;
  });
  return map;
}
```

- **書き込みゼロ**：`buildUserProfiles` は **pure function** で、引数の `rows` は既に IndexedDB から読み取ったキャッシュ。内部で新しい配列を生成しても外部ストレージに書き込まない。
- **オンデマンド**：`UserTile` が必要になるたびに `profile.comments.slice(-1)[0]` などで最新コメントだけを取得すれば、全体再走査を防げる。

**4. コンポーネント分割**  

```
+-------------------+          +-------------------+
|   UserTile (正本) |<-------->|   TileContext     |
|  - avatar         |  props   |  (popup|venue)    |
|  - nickname/id    |----------|  - mode           |
|  - badge (count)  |          |  - actionsHook    |
+-------------------+          +-------------------+
        ^   ^                         ^   ^
        |   |                         |   |
        |   +--- PopupUserLane --------+   |
        |                                 |
        +--- VenueSeat -------------------+
            (adds: SpeechBubble, Voice, GiftAnim)
```

- **`UserTile`**：丸サムネイル・アバター・ニックネーム・ID・カウント表示だけを描画。`props: { profile: UserProfile; mode: 'popup' | 'venue' }`。`mode` に応じて CSS（横並び vs 座席位置）を切り替えるだけでロジックは共有。
- **`PopupUserLane`**：`UserTile` を横並びに配置し、匿名段落用の追加ラッパー（`<section class="anonymous">`）を保持。`mode='popup'` で `UserTile` に渡す。
- **`VenueSeat`**：`UserTile` に `mode='venue'` を渡し、**座席レイアウト**（`transform: translate3d(x,y,0)`）を付与。さらに以下を **副作用フック** で付加  
  - `useSpeechBubble(profile)` → コメントがあれば吹き出しを生成。  
  - `useVoicePlayer(profile)` → 読み上げキューに enqueue。  
  - `useGiftThrow(profile)` → ギフトが来たら `giftThrowProjectile` を発火。  
  これらは **venue‑only** の副作用で、`UserTile` 本体は一切触らない。

- **共通 CSS**：`.user-tile { width: 48px; height: 48px; border-radius: 50%; }`。`popup` 用は `flex`、`venue` 用は `position:absolute` で座標計算だけ別。

**5. 反論・リスク・段階導入**  

| リスク | 内容 | 対策・段階 |
|-------|------|------------|
| **hot‑path での全コメント集約が重い** | `buildUserProfiles` が全コメント行を走査すると数千件になる可能性。 | ① 初回ロード時に **一度だけ** 実行し、結果を `useRef` に保持。② 以降は **増分更新**（`onNewRow`）だけを差分マージし、全走査を回避。 |
| **座席入れ替えロジックが複雑化** | 匿名ユーザーが大量に同時にアクティブになると、FIFO 入れ替えが頻発し UI がちらつく。 | `VenueSeatManager` に **優先度スコア**（`_laneSortAt` + `commentCount`）を付与し、上位 150 をソート済みリストで保持。入れ替えは **スロットリング（30 fps）** で実行し、1 フレームでの DOM 変更数を上限 20 に抑える。 |
| **タイル正本化で既存バグが再現** | 既存の「匿名は別段落」ロジックが `UserTile` に混在すると、popup が崩れる可能性。 | `PopupUserLane` だけが **匿名判定**（`profile.nickname.startsWith('a:')`）を行い、`UserTile` には「表示だけ」委譲。既存 CSS をそのまま流用し、見た目のドリフトは防げる。 |
| **読み上げ・ギフト演出が失敗したときのフォールト** | 音声合成エラーや projectile 描画失敗で画面が止まるリスク。 | 各副作用フックは **try/catch** で失敗を捕捉し、`console.warn` 後は **no‑op** にフェイルオープン。UI の描画は絶対に止めない。 |

### 段階的導入プラン  

1. **第1スプリント** – `UserTile` 正本コンポーネント実装、`PopupUserLane` からの置換。データモデルは `UserLaneCandidateFromStorage` → `UserProfile`（コメント・ギフトは空配列）に拡張し、書き込みは行わないことだけ検証。  
2. **第2スプリント** – `VenueSeat` に `UserTile` を組み込み、座席上限ロジック（150 席 FIFO）を実装。既存 `collectVenueParticipants` の匿名除外分岐を削除し、テストで匿名も座席に入ることを確認。  
3. **第3スプリント** – 吹き出し・読み上げ・ギフト演出フックを追加。`useSpeechBubble` などは **lazy** にインポートし、実際に該当ユーザーがアクションしたときだけロード。  
4. **第4スプリント** – 背景群衆 Canvas の密度表現を `activeSeatOverflow`（表示しきれないアクティブ人数）と `totalPV`（来場者数）に分離し、テキスト表示を「超過アクティブ N 人」へリネーム。  

この手順で **既存 UI の壊れリスクを最小化** しつつ、**正本コンポーネント化とデータ再利用** を段階的に導入できます。
