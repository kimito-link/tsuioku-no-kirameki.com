## 結論(1案)

**規模(300体)は真似ない。本質は「ソース照合で自分の嘘を捕まえる機械ゲート」を1枚ずつ増やすこと。**
明日からの具体は**3段階・小さく**:

1. **【最優先・低コスト・今すぐ】changelog-vs-version の機械照合 `:check` を1枚追加**。
   verify:cc に既にある drift 検知(tree-map/site-health/feature-map/bump)の仲間。changelog 先頭 version が
   package/manifest と一致 + date 形式 + summary≤35字 を機械照合(今 changelog.test.js が一部担うが、
   verify:bump と分離した独立ゲートにして「版を上げたら changelog 先頭も上がっている」を強制)。
   → これは**完全に機械決定可能**=loop の核心と同種。

2. **【中・半自動】「診断文言の主張する因果を、実コードで裏取りする」を運用ルール化(機械化はしない)**。
   今日の stale-DOM(cause「公式値レーンが混乱」が嘘)を捕まえたのは人間+LLM がコードを読んだから=
   **意味照合は文字列等価で機械決定できない**(後述・会議の安易な「嘘検出自動化」推しは半分罠)。
   代わりに**機械化できる薄い部分だけゲート化**: advice card の cause/action に「混乱/混入/汚染」等の
   "実害を示唆する語" が入っていたら CI で警告し、人間に「実コードでその因果が本当にあるか裏取りせよ」と促す
   lint 的チェック(嘘の自動判定でなく"裏取り喚起"=誤検知の害が小さい)。

3. **【低】/code-review を「指摘ゼロまで自動反復」化は今はしない(クレジット罠)**。
   既に /code-review はあるので、ループ化でなく「substantial なコミット前に1回回す」を運用で徹底すれば足りる。
   自動反復はクレジット枯渇+UI判断に暴走の二重罠(会議・批判役一致)。

## 根拠

- **実コード棚卸しで確定**: 元ネタの「①ソース照合」は本リポに**既に厚い**(tree-map:check / site-health:check /
  feature-map:check / verify:bump = 生成物がソースとズレたら verify:cc が落ちる=自分のミスをソース照合で捕捉)。
  「②間違いゼロまでループ」も verify:cc 緑まで通さない運用で実装済み。**足りないのは"カバー範囲"**であって機構ではない。
- **会議2/2一致**: 規模は本質でなく罠・自動ループは検証可能なものだけ・UI判断適用は暴走・嘘検出が穴。
- **今日の実例2件が証拠**: ナビ(会議のハルシネを grep で訂正)・stale-DOM(診断の嘘をソース照合で捕捉)。
  どちらも「LLMの出力を実コードに突き合わせて間違いを捨てた」=loop の縮小実例。仕組み化の価値は実証済み。

## 反論・リスク(司令塔が会議に裏取り上乗せ)

- 🔴 **会議の「診断文言の事実性を機械照合(嘘検出)」推しは半分罠**。「cause の散文が実コードの因果経路と
  一致するか」は**意味的判断で、tree-map:check のような文字列等価では機械決定不能**。今日の嘘は
  Explore+grep で人間/LLM がコードを読んで初めて分かった。**全自動の嘘検出を作るのは over-engineering**
  (検証のための検証=メンテ不能・批判役の穴指摘と一致)。
  → 機械化は**「実害を示唆する語の検出→人間に裏取りを促す」薄いゲート**まで(嘘の自動判定でなく喚起)。
- 🔴 **批判役の最大の穴=「会議→裏取りループの自動化」**。これは**やらない**。会議の議事録自動生成+裏取り
  自動反映はメンテ負担増+クレジット枯渇。司令塔(人間が見る Claude)が手動で裏取りする現運用が、
  まさに「ソースに突き合わせる別モデル」の役=既に機能している。自動化で人間の判断を抜くのが暴走の入口。
- やってはいけない過剰実装(会議+司令塔一致): ①300体を真似て常時大量エージェント(クレジット枯渇)
  ②正解が一つでない UI/設計判断を自動ループに乗せる(今日のナビ=死にリンク可否はロミ思想+ユーザー確認で
  決めた=自動化不能) ③嘘検出の全自動化(意味照合は機械決定不能) ④検証のための検証を増やしメンテ不能。

## 検証可能/不能の線引き(この問いの核心)

| 種類 | 例 | self-verifying loop 適用 |
|---|---|---|
| 機械決定可能(文字列/構造の等価) | 地図がコードとズレてない・リンク先が実在・版が同期・テストが緑 | ✅ 自動ゲート化(既存+案1) |
| 意味照合(散文の因果が正しいか) | 診断 cause が実コードの挙動と一致するか | △ 全自動不能。"喚起"まで機械化+人間が裏取り(案2) |
| 正解が一つでない(設計判断) | ナビの死にリンク可否・UI 文言・ロミ思想の適用 | ❌ 自動ループ禁止。会議+裏取り+ユーザー確認 |

## 具体案(次の1コミットで何を足すか)

### 案1(採用・次コミット候補 v0.1.835): changelog 整合ゲート
- 置き場所: `scripts/` に `changelog-check.mjs`(または既存 verify-bump.mjs に統合)。
  純ロジックは `src/lib/changelogConsistency.js`(changelog先頭version === package === manifest・
  date が YYYY-MM-DD・summary≤35字・items非空 を検査し violations を返す純関数)+test。
- package.json に `changelog:check` を追加し run-verify-cc.mjs のステップに挿入。
- 既存 changelog.test.js と重複する部分は test に残しつつ、**verify:cc で落ちる独立ゲート**にするのが新規価値
  (テストは開発者が test を回さないと気づかない・:check は verify:cc 必須経路)。

### 案2(採用・運用+薄い機械ゲート): 診断文言の"実害語"喚起
- 純ロジック `src/lib/diagWordingGuard.js`: advice card 配列を受け、cause/action に
  ['混乱','混入','汚染','破壊','失われ'] 等の実害示唆語が含まれ かつ severity が 'info' のカードを
  「文言と重大度の不一致(info なのに実害語)」として列挙する純関数+test。
- これは「嘘の自動判定」ではなく「info なのに不安語=要・実コード裏取り」の喚起。誤検知しても害は
  "人間が確認するだけ"。statusActionAdvisor.test.js から呼んで「info カードに実害語を入れない」を回帰防止。
- AGENTS.md §12 系に1行: 「ユーザー向け診断 cause を書く/変えるときは、その因果が実コードの経路に
  本当にあるか grep で裏取りしてから書く(stale-DOM v0.1.834 の教訓)」。

### 案3(運用のみ・実装なし): /code-review を substantial コミット前に1回(ループ化しない)
