### nvidia/qwen3.5-122b  [発散アイデア（推論強）]  (16634ms)

## 結論
**案1（鏡スナップショット送信＋純Web再描画）をベースに、CSS を「Popup 用（固定幅）」から「レスポンシブ用（Flex/Grid 自動伸縮）」へ即時書き換える「ハイブリッド再描画方式」が最善です。**
既存の描画ロジック（JS 関数）はそのまま使い回しつつ、純Web 版専用の CSS ファイルを新規作成し、アバターの `referrerPolicy` を `no-referrer` に統一することで、ニコ生の CDN 制限を回避しつつ「見た目の完全一致」を実現します。

## 根拠
1.  **「そっくり」の保証（評価軸①）**: 案2（HTML 文字列転送）は、Popup の CSS がスマホ画面（300px 幅）を前提に書かれているため、PC 画面で表示すると文字が潰れたりレイアウトが崩れたりして「そっくり」ではなくなります。一方、案1は描画ロジック（JS）は共通化しつつ、CSS だけを環境に合わせて最適化できるため、PC でもスマホでも「意図したデザイン」を維持できます。
2.  **既存資産の最大化（評価軸③）**: 既に `laneMirror.js` で顔/名前入りのデータを生成するロジックが完成しており、`paintStoryUserLaneDomFilled` などの描画関数も Chrome 非依存です。これらを流用すれば、描画ロジックの二重開発（案3）や HTML パースのオーバーヘッド（案2）を避けられます。
3.  **セキュリティとデータ量（評価軸④・⑤）**: 画像 URL はニコ生 CDN 直リンクですが、`referrerPolicy: "no-referrer"` を HTML の `<meta>` または画像タグに設定することで、外部サイトからのリファラーを隠蔽し、CDN の制限を回避できます。データ量は JSON 形式の再描画が HTML 文字列転送より軽量で、60秒ポーリングでも十分です。

## 反論・リスク
**最大のリスク：ニコ生アバター画像の「Hotlink 保護」と CORS 問題の再発。**
ニコ生の画像サーバー（`secure-dcdn.cdn.nimg.jp`）は、リファラー（アクセス元サイト）を厳しくチェックする傾向があります。純Web（`app.tsuioku-no-kirameki.com`）から直接画像を引用すると、ブラウザがリファラーを送信し、画像が表示されない（403 Forbidden）か、代わりにプロキシ画像が表示されるリスクがあります。
また、案1の「再描画」アプローチは、もし `paintStoryUserLaneDomFilled` 関数内部に `document.createElement` などの DOM 操作が密結合しており、ブラウザの DOM ツリー構造に依存している場合、サーバーサイド（SSR）や単純な innerHTML 代入では崩れる可能性がありますが、今回の要件は「純Web（ブラウザ側）での再描画」なので、この点はクリアされます。ただし、**「PC 画面で Popup 風の狭いレイアウトを維持しつつ、レスポンシブにする」**という CSS の設計難易度が極めて高い点も懸念です。

## 具体案
以下の手順で実装します。

1.  **データ送信側の強化（拡張機能側）**:
    *   `src/lib/laneMirror.js` の出力データに、各ユーザーのアバター画像 URL を含むことを確認（既存なら OK）。
    *   `status.html` の送信処理で、`laneMirrorSnapshot` と `statCardsMirror` のデータを `POST /api/status` に含める。
    *   送信ヘッダーに `x-share-key` を忘れずに設定。

2.  **サーバー側の対応（Vercel）**:
    *   `api/status.js` は変更なし（既存の Redis ストアで JSON を返すだけで OK）。

3.  **純Web 側の描画ロジック（新規作成・既存流用）**:
    *   **CSS の分離**: `app/popup.css`（既存の固定幅用）をコピーし、`app/live-view-responsive.css` を新規作成。
        *   コンテナを `max-width: 360px` (Popup 風) に設定しつつ、PC 画面では中央揃えにする。
        *   応援レーンのカード要素（`person-tile`）に `flex: 1` や `min-width` を追加し、幅が狭くなった場合の崩れを防ぐ。
        *   **重要**: `<meta name="referrer" content="no-referrer">` を `app/index.html` の `<head>` に追加。これによりニコ生画像の表示エラーを防ぐ。
    *   **JS の統合**: `app/app.js` を複製し、`app/live-view.js` を作成。
        *   `src/lib/personTileDom.js` と `src/lib/story/renderStoryUserLaneDom.js` の関数をそのまま `import`。
        *   描画時に、`document.createElement` で生成された要素に、新規作成した `live-view-responsive.css` のクラス名（または親要素）を適用させるよう調整。
        *   `buildLiveBlockText` などのテキスト生成ロジックはそのまま流用。

4.  **レスポンシブの調整**:
    *   `live-view-responsive.css` で、`@media (min-width: 768px)` などの条件を使い、PC 画面でも「Popup を拡大したような見た目」ではなく「Popup のデザインを維持したまま、画面中央に収まる」レイアウトを定義する。
    *   アバターのサイズを `width: 40px` など固定ではなく、親要素の幅に比例するように `aspect-ratio` を設定し、スマホ/PC共通で崩れないようにする。

5.  **検証**:
    *   拡張機能からデータ送信後、PC ブラウザとスマホブラウザで `https://app.tsuioku-no-kirameki.com/live-view?v=xxx` にアクセスし、画像表示とレイアウト崩れを確認。
    *   特に PC 画面で「画面いっぱいに広がる」のではなく「Popup 風の縦長のウィンドウとして中央に表示される」ことを確認する。
