# 結論：ヘッダーを「UI部品」ではなく「生データ（JSON）」として解釈し、ブラウザ側の「動的レンダリング」で統一する

既存の「HTML部品をコピー＆ペースト」や「JSでDOMを操作して穴埋め」という発想を捨て、**「ヘッダーは自動生成スクリプトが出力する『データ構造』であり、各ページはそのデータを『描画するキャンバス』である」**という逆転の発想で実装します。

1.  **構成**: 5つのノード（3地図＋status＋任意）を横一列に配置。現在地は「太字＋色付き下線＋ARIA属性」で明示。
2.  **実装**: 共通ヘッダーのロジックを `scripts/repo-tree-map.mjs` 内の**「ヘッダー生成関数」**に集約。手書きの `status.html` は、このスクリプトが生成した**「ヘッダー用のJSONデータ」**を埋め込むだけで済む（HTMLタグ自体をスクリプトで生成させるのではなく、データだけ渡す）。
3.  **パス解決**: アブソリュートパス（`/docs/...`）と相対パス（`../`）の両方に対応する**「ルート相対パス（`/docs/` 基準）」**を強制し、`<base>` タグは使用せず、JS内で現在のURLを解析して動的にリンクを補正する「自己修復リンク」を採用。
4.  **モバイル**: 横スクロール禁止。幅が狭くなったら「全リンクを隠し、現在地のみ表示する『ミニマムモード』」へ自動遷移（CSSの`@media`だけで完結）。
5.  **過剰実装の禁止**: 「React/Vue等のフレームワーク導入」や「ヘッダーHTMLを外部ファイルからfetchして注入する非同期処理」。これらは「依存ゼロ・再生成が即座に完了する」という要件と矛盾し、初期読み込みを遅らせるだけで価値を生みません。

# 根拠：なぜ「データ駆動型」で「自己修復」なのか

### 1. 自動生成ページと手書きページの「ドリフト」を防ぐ唯一の解
現状、自動生成ページはスクリプトがHTMLを吐き出し、手書きページは人間がHTMLを記述しています。ここに「共通ヘッダー」という概念を無理やり押し付けると、スクリプトの修正と手書きページの修正がバラバラになり、すぐにリンクが切れます。
**発散案**: ヘッダーの「見た目（HTML/CSS）」はあくまで「結果」であり、「正解」は**リンク先とラベルのリスト（データ）**にあります。
*   **スクリプト側**: 5ページ分のリンク情報をJSONオブジェクトとして生成し、HTMLの`<script id="nav-data" type="application/json">`内に埋め込む（または直接HTML文字列を挿入）。
*   **手書き側**: `status.html` にも同じJSONデータ（または同じ構造のHTML断片）を配置。
*   **メリット**: 5ページの構成が変われば、スクリプトを再実行するだけで全ページが更新されます。`status.html` だけ忘れるというヒューマンエラーを排除できます。

### 2. 絶対URLと相対パスの「二面性」を解決する「自己修復」
`htmlpreview.github.io`（絶対URL）と `docs/` 直下（相対パス）でリンクが切れる最大の理由は、`<a href="./index.html">` という書き方が、絶対URL環境ではブラウザのドメインを無視して正しく機能しない（または逆に、絶対URL環境で `../` を使うと外れてしまう）ためです。
**発散案**: リンク先を「静的な文字列」ではなく、**「現在のURLから計算する動的なパス」**として定義します。
*   スクリプト内で生成するリンクは、常に**「ドキュメントルート（`/docs/`）からの相対パス」**（例：`/docs/feature-sitemap.html`）として統一します。
*   しかし、ブラウザ表示時に、もし現在地が `htmlpreview.github.io` 配下であれば、そのパスはそのまま機能します。もし `localhost/docs/` 配下であれば、`/docs/` がルートとして機能します。
*   **さらに過激な案**: `window.location.pathname` を解析し、`/docs/` が含まれていればそのまま使い、含まれていなければ（htmlpreviewの場合）自動的にパスを補正する**「JSによるリンク補正機能」**をヘッダー内に内包させます。これにより、HTMLファイルそのものを書き換えることなく、環境適応が可能になります。

### 3. 「最小で最大効果」のUI設計
初心者が迷うのは「今どこにいるか」がわからないことと、「どこへ行けばいいか」の選択肢が多すぎることです。
*   **必須リンク**: 5つすべて（5枚のページ）。
*   **不要な要素**: 「ホーム」「戻る」「検索」。これらは「地図」の文脈ではノイズです。
*   **現在地**: 「太字」＋「背景色（ダークテーマ変数 `--accent`）＋「ARIA属性 `aria-current="page"`」。これだけで視認性は確保。
*   **モバイル**: 横スクロールは「地図を狭める」行為なのでNG。代わりに「現在地のみ表示し、他は『≡』で展開」か、あるいは「現在地を中央に押し出し、他は左右にスライドさせる（CSS Scroll Snap）」が望ましいですが、今回は「最小構成」を優先し、**「幅制限で自動非表示（現在地以外を隠す）」**という荒技を採用します。初心者は「全部見たい」のではなく「次に行きたい」だけだからです。

# 反論・リスク：なぜこのアプローチが「星野ロミ式」なのか

### 反論1：「JSでリンクを補正するのは重く、バグの温床では？」
*   **反論**: 現代のブラウザはJSの処理速度が圧倒的に速い。ヘッダーのサイズは数KB以下であり、読み込みへの影響は計測不可能レベル。
*   **リスク回避**: 補正ロジックはスクリプト生成時に**「確定値」**として埋め込むため、ページロード時のJS実行コストはゼロです。生成されたHTMLにはすでに正しいパスが書かれているため、ブラウザ側のJS実行は不要です（**生成時に解決する**）。
*   **星野ロミ的視点**: 「実行時の計算」ではなく「生成時の最適化」。これこそが「落とさない・過剰実装回避」の極致です。

### 反論2：「手書きの status.html にスクリプトのロジックをどう持たせるのか？」
*   **反論**: `status.html` 自体をスクリプトで生成させるのは無理がある（手書きのキャラ吹き出しを維持したい）。

## 結論
共通ナビゲーションヘッダーを実現するために、scripts/repo-tree-map.mjs にヘッダーの正本を置き、自動生成ページと手書きの status.html で共有する。ヘッダーには、現在地を示す active 表示と、対象ページへのリンクを含める。

## 根拠
- 自動生成ページは手編集禁止のため、ヘッダーは scripts/repo-tree-map.mjs 側に正本を置く必要がある。
- 共通ヘッダーを実現するために、重複定義のドリフトを防ぐ単一正本を置く必要がある。
- 相対パス文脈と絶対URL文脈で同じヘッダーが壊れないリンク解決のために、絶对URLを使用する。

## 反論・リスク
- 自動生成ページと手書きの status.html で共有するヘッダーを管理するのは、維持コストが高い可能性がある。
- 外部CDN禁止のため、ローカルリソースの管理が必要になる。

## 具体案
- scripts/repo-tree-map.mjs にヘッダーの正本を置く。
  - ヘッダーには、現在地を示す active 表示と、対象ページへのリンクを含める。
  - 例:
    ```javascript
const headerHtml = `
<nav>
  <ul>
    <li><a href="feature-sitemap.html" ${currentPage === 'feature-sitemap' ? 'aria-current="page"' : ''}>機能マインドマップ</a></li>
    <li><a href="code-tree.html" ${currentPage === 'code-tree' ? 'aria-current="page"' : ''}>全ファイルツリー</a></li>
    <li><a href="repo-tree-map.html" ${currentPage === 'repo-tree-map' ? 'aria-current="page"' : ''}>ディレクトリ逆引き</a></li>
    <li><a href="status.html" ${currentPage === 'status' ? 'aria-current="page"' : ''}>status状態ページ</a></li>
  </ul>
</nav>
`;
```
- 自動生成ページにヘッダーを挿入する。
  - 例:
    ```javascript
// scripts/repo-tree-map.mjs
function generatePage(content) {
  // ヘッダーを挿入
  return headerHtml + content;
}
```
- 手書きの status.html にヘッダーを挿入する。
  - 例:
    ```html
<!-- status.html -->
${headerHtml}
<!-- 中身 -->
```
- 相対パス文脈と絶対URL文脈で同じヘッダーが壊れないリンク解決のために、絶対URLを使用する。
  - 例:
    ```javascript
const absoluteUrl = 'https://example.com';
const headerHtml = `
<nav>
  <ul>
    <li><a href="${absoluteUrl}/feature-sitemap.html" ${currentPage === 'feature-sitemap' ? 'aria-current="page"' : ''}>機能マインドマップ</a></li>
    <!-- ... -->
  </ul>
</nav>
`;
```
- アクセシビリティ/モバイルのために、nav 要素、現在地の aria-current、狭幅での折返し/横スクロールを実装する。
  - 例:
    ```css
nav {
  /* 狭幅での折返し/横スクロール */
  overflow-x: auto;
  white-space: nowrap;
}

nav ul {
  list-style: none;
  margin: 0;
  padding: 0;
  display: flex;
  flex-wrap: wrap;
}

nav li {
  margin-right: 20px;
}

nav a {
  text-decoration: none;
  color: #fff;
}

nav a[aria-current="page"] {
  color: #ccc;
}
```
