# お題: バグを未然に防ぎ「設計をミスゼロ」に保つ "完全なMAP" の設計

## 背景（前提・実在するものだけ）
このリポジトリ(Chrome拡張『君斗りんくの追憶のきらめき』＋公開LP)では、今日までに
「迷子・断線・誤前提によるバグ」を構造的に防ぐための仕組みを段階的に作ってきた:

1. `docs/repo-tree-map.md`/`.html` — ディレクトリ役割マップ＋「機能→担当ファイル」逆引き索引
   ＋Mermaidマインドマップ。`scripts/repo-tree-map.mjs` が ROLES/FEATURES 辞書＋git追跡から
   **自動生成**。`npm run verify:cc` の `tree-map:check` が腐り(辞書とコードのズレ)を検知。
2. `docs/feature-map/*.md` — esbuild entry 単位の機能依存図＋storage の producer/consumer 断線検出(自動生成)。
3. `docs/person-tile-architecture.md`/`.html` — 設計正本マインドマップ(手書き・なぜこうなってるか)。
4. `docs/comment-number-rescue-flow.html` — フェーズ・状態色・依存ゲートのフロー図(手戻り防止)。
5. status.html — 状態速報＋「全体マインドマップ(折りたたみツリー・🟢🟡🔴⚪badge)」＋AI共有まとめ。
6. AGENTS.md — 配置ルール/設計判断/実装前ゲートの正本。「迷ったら repo-tree-map を引く」導線。

## 問い（これに答えて）
上記の既存資産を土台に、**「バグを未然に防ぎ、サイト/拡張の設計をミスゼロに近づける "完全なMAP"」**を
作るなら、どう設計するのが最善か。次の3つの利用者すべてに効く1つの仕組みを提案せよ:
- (a) **AI開発者**(Claude等のエージェント。毎回ゼロから文脈を組む。誤前提で誤実装しがち)
- (b) **人間の開発者**(久しぶりに触ると「どこを直すと何が壊れるか」を忘れる)
- (c) **通常のWeb事業**(公開LP・記事ページ。リンク切れ・文言不整合・デプロイ事故を防ぎたい)

## 制約（必ず守る・破る案は減点）
- **自動生成・自動更新**であること(手書きだけの図は腐る。今日の tree-map と同じ流儀)。
- **腐り検知**があること(コードと地図がズレたら verify/CI で失敗する)。
- **外部送信ゼロ・追加の重い依存ゼロ**(プライバシー方針・CWS審査・オフライン動作)。
- **既存資産を捨てない**(repo-tree-map / feature-map / status マインドマップ を活かして繋ぐ。作り直さない)。
- **過剰実装しない**(全部入りの巨大フレームワークは却下。最小で最大の事故を防ぐ一点を選ぶ)。

## 特に答えてほしい論点
1. 「バグを未然に防ぐ」ために、今 **欠けている1枚**は何か(依存の可視化? 影響範囲? 不変条件? リンク健全性?)。
2. それを **どうやって自動生成・腐り検知**するか(具体的な仕組み。既存 verify:cc/tree-map:check への接続)。
3. (c)通常Web向けに、**リンク切れ・文言不整合・デプロイ事故**を防ぐ最小の自動チェックは何か。
4. AI が「迷ったとき/実装前」に **このMAPをどう参照すれば誤前提を潰せる**か(参照導線の設計)。
5. やってはいけない過剰実装(アンチパターン)は何か。

各メンバーは必ず: **結論 → 根拠 → 反論・リスク → 具体案(最初の1コミットで何を作るか)** の4ブロックで。
