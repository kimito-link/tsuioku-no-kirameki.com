## 1. マイ効果音差し替え機能の設計

### 1.1 原則

- **音源はリポジトリ/ストアに絶対同梱しない**(定額ライセンスの個人利用範囲)。音声データはユーザーのブラウザ内 IndexedDB にのみ存在する。
- リポジトリに入るのは **No.→音種キーの割り当てプリセット表(JSONメタデータのみ・§2の表そのもの)** と取込UI・注入コード。タイトル/No.は事実メタデータでありライセンス対象外。
- **effectSoundPlayer.js は無改変**。差し替えは deps 注入のみ(§1.4)。カスタム未割り当てキーは従来の同梱合成音へ自動フォールバック。新設キー(voice_*等)は未割り当てなら `no-path` で静かに無音=安全側。

### 1.2 ストア構成(IndexedDB)

- DB名 `tk-custom-sounds` / version 1。オブジェクトストア2つ:
  - `blobs`: `{ id: 'as_204361', blob: Blob, name: 'audiostock_204361.mp3', bytes, importedAt }`。id はファイル名の `audiostock_(\d+)` から機械導出。
  - `assignments`: `{ key: 'gift_medium', ids: ['as_812926','as_1587171',...], gain: 1.0 }`。ids の**配列順=変奏の順繰り順**(§1.5)。
- 割り当て変更は `chrome.storage.local` の世代カウンタ `customSoundRev` を+1して他コンテキスト(venueBar/popup)に通知(storage.onChanged)。音声Blob自体はstorageに載せない(サイズ地雷)。

### 1.3 取込UI(診断ページの試聴パネル拡張)

- 既存の試聴パネルに「マイ効果音」タブを追加:
  1. `<input type="file" multiple accept="audio/*">` で D:\download の85本を一括選択(フォルダ選択でも可)。
  2. ファイル名から No. をパース → **同梱プリセット表(§2のJSON化)で全85本を自動割り当て**。1クリックで完了、手作業ゼロ。
  3. キーごとの割り当てリスト表示: 変奏の追加/削除/並び替え/▶試聴(拡張と同じ音量で再生)/キー単位の gain スライダー(0.0〜1.0)。
  4. 「既定に戻す」=assignments の該当キー削除(合成音フォールバックへ)。
- トリム/加工機能は付けない(ブラウザ内加工は前回失敗系譜。素材をそのまま鳴らす)。

### 1.4 再生側の注入(venueBar / popup 共通)

起動時+`customSoundRev` 変化時に一度だけ:

```
assignments を読む → 割り当て済み Blob だけ URL.createObjectURL → 
customVariantPaths = { gift_medium: [blobURL1, blobURL2, ...], voice_atsui: [...], ... }
```

呼び出しは既存のまま、deps だけ変わる:

```js
playEffectSound(kind, {
  variantPaths: { ...EFFECT_SOUND_VARIANT_PATHS, ...customVariantPaths }, // カスタム優先で上書き
  paths:        { ...EFFECT_SOUND_PATHS, ...customSinglePaths },
  getUrl: (p) => p.startsWith('blob:') ? p : chrome.runtime.getURL(p),   // blob素通し・既存はgetURL
  rng: rotationRngFor(kind),                                             // §1.5 決定論順繰り
  volume: gainFor(kind)                                                  // assignments.gain 反映
});
```

- `resolveEffectSoundPath` は任意キーの variantPaths を既に解決できるため、**新設キー(voice_*/bgm_jingle_*/breakthrough/payout/hold_lamp)も注入だけで鳴る**。player・manifest とも改修ゼロ(blob URL は web_accessible_resources 不要)。
- 旧URLは割り当て変更時に `URL.revokeObjectURL`。blobURL化は割り当て済み分のみ(85本全量でも合計約50MB・Audio要素は再生時デコードなので常駐メモリは小さい)。
- 二重再生ガード(会場優先プレゼンス)・600ms同種ガード・Audioキャッシュは既存のまま効く(キー単位の仕組みでありパスが blob になっても不変)。

### 1.5 変奏選択の決定論化(順繰りローテーション)

既存playerの変奏選択は `deps.rng` 注入可。ここに **「キーごとの発生通し番号 counter を保持し、`rng() = (counter mod N) / N` を返す」** 注入rngを渡す。結果 `Math.floor(rng()*N)` = counter mod N となり、変奏は1→2→3→1…の完全決定論順繰り。

- 効果: (a)乱数の残滓が消える(絶対制約への完全準拠) (b)**全変奏=85音源すべてが必ず順番に実際に鳴る**(「全部活かす」の構造的保証) (c)同一状況の再現テストが可能。
- counter はコンテキスト内メモリで十分(リロードで1に戻っても「どの変奏か」が変わるだけで演出の当否に無関係)。

## 3. 物語弧の設計 — 決定論ステートマシン「追憶の台」

### 3.1 二層構造(イベント直結層+フェーズ層)

- **イベント直結層(現行維持・メーター非依存)**: ギフト/節目/順位/広告は従来どおり即座に鳴る。directHit のコンボ置換昇格もそのまま。**過疎配信でもこの層は死なない**(会議批判への回答その1)。
- **フェーズ層(新設)**: メーターの相対比 R でフェーズを進め、遷移の瞬間だけボイス・reach SE・BGMを発火する。低流速対応の核心は次項。

### 3.2 相対閾値 R(低流速でも成立する決定論・会議批判への本回答)

- メーター M: 既存 `meterStateFor`(半減期60秒)。重み=コメント+1・gift small/medium/large/mega +4/+8/+16/+32・広告+8・節目到達+10。
- ベースライン B: 12秒tick(状態速報extrasと同じ間引き)ごとに `B ← B + (M − B) × (1 − 0.5^(dt/600000))`(半減期10分のEMA・純関数 `baselineFor(prevB, M, dtMs)`)。下限 `B_floor = 2.0`(無音配信の過敏化防止)。
- **相対比 R = M / max(B, 2.0)**。「いまこの配信は、この配信自身の平常時の何倍盛り上がっているか」。深夜の過疎配信でも常連が畳み掛ければ R は 2.5 を超える=**絶対流速に依存しない**。
- ウォームアップ: 配信検知から3分間は R を 1.0 に固定(Bが立つ前の誤爆防止)。
- さらに保険: **節目接近リーチ**(コメント数が次節目まで残り≤10%)はメーター無関係に発火。低流速でも1配信に最低1周の物語弧が保証される(会議批判への回答その2)。

### 3.3 フェーズ遷移表(全て決定論・遷移時のみ発音)

| 遷移 | 条件(いずれか) | 鳴らすもの(直列・積み増しなし) |
|---|---|---|
| 通常→煽り | R≥1.5 | (音なし・メーターDOMの色替えのみ)+voice_chance(§4ゲート通過時) |
| 煽り→リーチ | R≥2.5 / 節目接近(残り≤10%) / コンボ2連中 | reach SE → voice_atsui |
| リーチ→突破 | R≥4.0 / 節目500到達 / gift_large以上 / コンボ3連目 | breakthrough SE → (300ms) → voice_breakthrough |
| 突破→大当たり | 節目1000+到達 / gift_mega / directHit昇格結果が jackpot・mega | (イベント側 jackpot/mega SE) → voice_jackpot |
| 大当たり→払い出し | 大当たり音の終了後 自動チェーン | payout SE 1本 → (BGM ONなら bgm_jingle_stage → bgm_fever_loop) |
| 払い出し→通常 | フィーバー終了(§5)または即時 | (BGM ONなら bgm_jingle_win) |
| 降格(各段) | R <(現フェーズin閾値−0.5)が60秒継続 | **音なしで静かに1段降格**(ガセリーチ=実機にもある。偽の解決音は鳴らさない) |
| リーチ滞在上限 | 120秒突破なし | 音なしで通常へ(引っ張りすぎ防止) |

- ヒステリシス: in/out差 0.5(=in閾値の20%)+時間ヒステリシス60秒の二重。境界チャタリングで音は絶対に連発しない。
- hold_lamp: R が 1.0→1.5→2.0→2.5 の帯を**上向きに**跨いだ瞬間のみピコン(下向きは無音)。連発ガード: 同帯20秒CD。
- コンボとの接続: `directHit` の promotedSteps≥1 は「上乗せ」= voice_kamitsumi(§4)。梯子昇格自体が 保留→きゅいん→リーチ→大当たり の弧なので、フェーズ層は**梯子の結果を追認するだけ**で二重に音を出さない(イベント音はイベント直結層の1本のみ)。

- **全ボイス共通の最短間隔45秒**(どれかが鳴ったら全 voice_* が45秒沈黙)。
- **1配信合計20回上限**。カウンタは liveId 切替でリセット(popup再読込のリセットは「多く鳴る側」に倒れるが上限20が天井なので許容。厳密化するなら storage.session に liveId キーで保持)。
- 全条件は事象履歴の純関数=決定論。`voiceGate(state, key, nowMs)` 1関数に集約しテストで固定する。

### 4.3 VOICEVOX読み上げ・配信音声との優先度(置換原則の拡張)

優先度レーン(上が勝つ。同時発音は行わず、下位は**破棄**・上位は**置換**):

1. **P1 大当たりチェーン**(jackpot/mega SE→voice_jackpot→payout): 実行中は P3 以下を破棄。
2. **P2 ボイス(voice_*)**: 再生中に上位フェーズのボイス条件が来たら現ボイスを止めて置換。下位条件は破棄。
3. **P3 突破/リーチSE**(breakthrough/reach)。
4. **P4 通常SE**(gift/milestone/rank/ad・600msガードは現行のまま)。
5. **P5 hold_lamp**。
6. **P6 BGM**(常に最下位・ダック対象。§5)。

- **VOICEVOX は別レーン(情報チャネル)として常時通す**。衝突回避は帯域でなく**時間分離**: VOICEVOX発話中(または読み上げキュー≥2)は voice_* を**スキップして諦める**(遅延再生禁止=文脈がズレた頃に鳴る事故の禁止)。ボイスが飛んでも対応するSEは鳴っているので演出は欠落しない。
- 唯一の例外: **voice_jackpot だけは重なり許容**(1配信最大3回の祭りの瞬間のみ。読み上げを止める実装は作らない)。
- 発話中判定は `deps.isNarrating()` として注入(reportCompleteVoice/読み上げ側の再生状態を参照する読み取り専用関数。読み上げ側の改変はしない)。
