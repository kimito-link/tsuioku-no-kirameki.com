お題: スマホアプリ「すれちがいライト」(任天堂DSのすれちがい通信のスマホ版・Expo製アプリ+Next.js製API/管理画面+MySQL空間DB)を【星野ロミ視点】で解決・成長させる。星野ロミの設計思想(摩擦除去・供給/参加インセンティブ・参入障壁をプロダクト内部に埋める・行動データを継続/収益に変換・技術はデザインより先に"機能する仕組み"・現実主義=完成に必要な最短の仕組みを選ぶ)で、このプロダクトの【次の一手】を会議してほしい。

== プロダクトの中核思想(提供ソース deep-research-report -sorcecode.md より) ==
「登録の摩擦を消し、位置の危険を丸め、会話の重さを軽くし、それでも"歩く理由"は強くする」。
- 認証=UUID ゲスト方式(初回摩擦ゼロ・機種変更/複数端末に弱い)
- 位置=約500mグリッドに丸め(プライバシー保護・地図精度は犠牲)
- コミュニケーション=SNSを作らない判断。フォロー/チャット/タイムライン無し。"いいね/わかる/ウケる/いい曲"の低圧リアクションのみ。年代/性別は明示トグル。
- マッチング=リアルタイムpushでなく5分ごとcron+ティア制(500m/3km/10km/50km)。24時間マッチ0件ユーザーを上位ティアで救済・同一ペア8時間クールダウン=「今日は誰とも会えなかった、を減らす」設計。
- おさんぽ(分身)=純粋な位置偽装でなく「人口の気配がある県の町へ分身を送る」=当たりのある疑似旅行ガチャ。
- 継続導線=都道府県コレクション・バッジ(13種+)・ストリーク・おさんぽ。
- スタック=Expo+RN+TS / Expo Router / Zustand / Next.js / MySQL8(GEOMETRY+SPATIAL INDEX+ST_Distance_Sphere) / Spotify / Nominatim(逆ジオコーディング)。

== 確認された課題(HANDOFF.md「既知の課題」+レポートの技術指摘) ==
1. プッシュ通知(FCM)未実装=「すれちがいに気づけない」=継続率の生命線が欠けている。スキーマ/ロジックは準備済み・Firebase Admin SDK 導入が必要。
2. 認証が UUID のみ=機種変更でアカウント消失=せっかくの継続(コレクション/バッジ/ストリーク)が消える=継続導線と矛盾。
3. ドキュメント/スキーマと実装の不整合=アバターが HANDOFF/SQL では DiceBear 前提だが実装は svgavatars.html を WebView+PHP風リライト。users 初期SQLに avatar_url カラムが無いが API/UI は前提に動く。
4. 管理画面クライアントに admin:admin の Basic認証ヘッダー直書き=本番前に是正必須(セキュリティ)。
5. 逆ジオコーディングが公開 Nominatim 依存(1req/s 上限)=伸びると破綻=キャッシュ/セルフホスト/別サービス移行計画が要る。
6. locations テーブルを削除しない方針(将来ビッグデータ活用想定)=肥大化対策が要る。
7. テスト/CI/CD 未整備・本番デプロイ未実装・App Store/Google Play 審査対応・集客/マーケ戦略 未着手。
8. 背景位置取得はOS制約でアプリ完全終了時は止まる=UX文言に注記が要る。

== 星野ロミ視点で解くべき核心 ==
星野ロミは「美しいブランド」でなく「成長・定着・収益化に直結する摩擦除去」を最優先する。漫画村=会員登録不要/即読める、Share Videos=供給者報酬+導線書換え+見られない時の代替送客、SocialXup=検索した瞬間グラフ+繰り返し使う理由。この思想で「すれちがいライト」を見たとき、限られた工数で【最初に何を直し、何を足すか】。技術課題の修正(衛生)と、成長の一手(攻め)をどう順序づけるか。

== 問い ==
1. 星野ロミなら「すれちがいライト」の【次の1手】に何を選ぶか。候補(これに限らない): (a)継続率の生命線=プッシュ通知(FCM)を最優先 (b)機種変更でコレクションが消える=ゆるいアカウント連携(UUID 引き継ぎ)で離脱コストを上げる (c)"歩く理由"の強化=おさんぽ/コレクション/バッジに供給インセンティブや参入障壁を埋める (d)集客=SocialXup流の検索入口/SEO/共有導線 (e)その他。優先順位と理由を。
2. 星野ロミ的な「参入障壁をプロダクト内部に埋める」を、このアプリでどう実装するか(Share Videos の導線書換え/供給者報酬に相当するものは何か)。ネットワーク効果・離脱コストをどこに作るか。
3. 行動データ(locations の蓄積・すれちがい履歴・コレクション)を、継続と収益にどう変換するか。広告/課金/プレミアム(漫画村プロ型)のどれが筋か。プライバシー(500m丸め・SNSにしない)思想と両立させつつ。
4. 技術課題(認証/スキーマ不整合/admin直書き/Nominatim依存/テスト無し)のうち、成長の前に必ず潰すべき「衛生」はどれで、後回しでよいのはどれか。星野ロミの現実主義(最短で機能する仕組み)で順序づけよ。
5. 最小工数で効く段階リリース順(各段で何を出すか・何を計測するか=星野ロミの計測志向)。

評価軸: ①星野ロミ思想との整合(摩擦除去/インセンティブ/参入障壁/データ活用/現実主義) ②継続率・定着への効き ③限られた工数での費用対効果(最小ブラスト半径) ④プライバシー/安全(SNSにしない・500m丸めの思想を壊さない) ⑤収益化の筋の良さ ⑥技術的衛生(本番運用に耐えるか) ⑦計測可能性(何を見て成否を判断するか)。

各メンバーは『結論 → 根拠 → 反論・リスク → 具体案(何を・どの順で・どう作るか)』の4ブロックで。批判役は必ず穴を1つ指摘(特に『プッシュ通知を最優先にすると本番デプロイ/認証が無いまま通知だけ来る矛盾』『参入障壁を埋める=ユーザーの自由を縛り摩擦が増えるジレンマ』『データ収益化とSNSにしない/プライバシー思想の衝突』)。司令塔(Claude)が最後に統合・裏取りして1案に収束させる。最優先は「限られた工数で、星野ロミ思想に忠実に、継続率と本番運用耐性を最大化する次の一手」。
